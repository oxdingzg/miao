# 远程控制

[English](remote-control.en.md)

Remote Control 让你从另一台设备操作正在运行的 miao 窗口。任务仍在本地执行；你部署的 Hub
在该窗口与客户端之间转发加密流量。iOS 使用账号级接入：两端登录同一个 Hub 账号后，
电脑只需开启要共享的会话，不需要二维码、配对码或首次设备批准。

## iOS：同账号直接控制

1. 电脑使用 `/login` 登录 Hub；iOS 登录同一个 Hub 的同一账号。
2. 电脑打开要共享的会话，输入 `/remote-control`。命令只切换当前会话的共享状态，
   不弹设置窗口，也不要求选择时长；再次输入即关闭这个会话，不影响其他已共享会话。
3. iOS 前台自动刷新账号目录，侧栏按电脑列出已开启远控的会话，点选即可同步查看和操作。

此模式以 Hub 认证的账号为接入依据。主机要求 Hub 控制连接提供的认证账号与本机绑定账号
一致，同时验证客户端密钥持有证明；不能仅凭客户端自报账号接入。授权仅在加密连接内生效，
每次请求仍检查本机的会话发布状态，关闭共享后立即拒绝后续访问。Hub 必须支持在主机的
`connected` 控制消息中传递认证账号；旧 Hub 缺少此信息时会拒绝接入，不会自动放宽认证。

下面的设备邀请流程保留给旧客户端及独立设备授权，不是新版 iOS 的前置步骤。

## 手机上的待处理收件箱

侧栏的**待处理**列出所有正在等你处理的会话：每条写着会话标题和具体的审批命令或提问，
点一下就跳到那个会话继续处理，不用逐个打开去找。列表来自电脑上的一次汇总查询，只包含
这次授权范围内的会话；没有待处理的会话不会出现，关闭共享的会话也会立即消失。

这条列表随前台每十秒刷新一次，打开侧栏时也会立即刷新一次。审批和提问本身仍然只在
会话内回答，收件箱只负责把「什么在等我」摆到眼前。

## 在手机上配置服务商与模型

手机可以填写服务商的 API Key、断开已保存的凭据，并选择电脑上新会话的默认模型。

1. 电脑上打开 `/remote-control`，在授权流程的**选择设备权限**一步选
   **允许配置服务商与模型**。默认是「不配置服务商」，此时手机端不显示该入口。
2. iOS 侧栏点**服务商与模型**：已连接的服务商可以断开；可连接的服务商点进去
   输入 API Key；默认模型在**新会话**一栏里选择。
3. 环境变量提供的服务商、需要浏览器登录的 OAuth 服务商，仍然只在电脑上处理，
   手机端会标注「在电脑上连接」。

密钥只经加密连接送到你的电脑，并保存在电脑的凭据存储里。手机不显示已保存的密钥，
也不会把它写进本地缓存或操作账本；配置结果由重新读取服务商列表确认。断开只删除
电脑上保存的凭据，不影响其他设置。

## 连接前

- 使用支持 `/remote-control` 的当前 miao 构建，并保持本地窗口运行。
- 部署具有账号鉴权和 HTTPS 地址的 Hub。仓库提供 [Hub 与容器说明](../packages/remote-control/README.md)
  和 [Compose 部署](../packages/remote-control/deploy/README.md)。
- 从同一个 Hub 域名提供 Web 客户端，或使用兼容的 iOS 客户端。
  Hub 独立于 mtty.dev，本站不提供托管的 Hub 服务。

运行 miao 的机器主动向 Hub 发起出站连接；不需要暴露本地 API 或映射入站端口。

## 连接窗口并批准设备

1. 在要工作的项目中启动 `miao`，打开 `/remote-control`。
2. 用对话框里的设置流程连接 Hub 并登录。保存过配置不会让新窗口自动连接；
   需要为该窗口显式开启访问。
3. 创建邀请，选择要共享的项目或会话、允许的操作及有效期，在远程客户端打开它。
4. 在本地窗口核对候选设备公钥与范围，再批准。建立传输连接不会自动信任设备。
5. 通过远程客户端的会话列表和操作入口，在授权范围内使用。访问仅限选中窗口持有的会话，
   包括通过该连接远程创建的会话。

对话框也列出待配对请求与已批准设备。可拒绝不需要的请求，或撤销设备；撤销会使授权失效，
并关闭其活动通道。关闭 Remote Control 会断开该窗口的连接，本地工作继续。

## 窗口关闭后

每次普通 miao 调用都拥有自己的执行与远程连接。关闭该窗口就会结束二者；后台任务和排队输入
不会让窗口继续存活。独立窗口共享持久化历史，但分别持有执行权和远程连接。远程重连保留
选中的窗口目标，不会自动切换到同机上的另一个窗口。

重新打开历史不代表自动恢复执行，请显式继续中断的工作。
所有权、更新与私有 `runtime access` 集成桥接见[运行时生命周期](runtime.md)。

## 显式服务端访问

`miao serve` 是独立的前台 HTTP API 服务；`miao attach <url>` 和
`miao run --attach <url>` 连接你明确选择的服务端，与 Hub/设备配对是不同入口。
它的监听接口和鉴权单独配置，见[安全说明](../SECURITY.zh.md)。

## 从旧 IM 桥接迁移

旧 WeChat/QQ 桥接、`miao remote` CLI 和 `remote.*` 配置均已移除。
`/remote` 保留为 `/remote-control` 的兼容别名，设置面板使用 `/remote-settings`。
请使用 `/remote-control`、自己的 Hub 与已配对客户端。这是设备级远程访问，不是 IM bot
的迁移；旧聊天命令和 bot 账号不会沿用。

## 排查

- **主机离线：**保持选中的 miao 窗口打开，显式开启该窗口的 Remote Control，并确认 Hub
  的 HTTPS 地址可达。
- **已连接但无权限：**确认 Hub 账号，再检查本地设备批准、范围和有效期。Hub 登录与设备
  授权是两个独立条件。
- **会话被另一窗口持有：**使用该所有者窗口的连接，或先关闭它，再在别处显式继续会话。
- **写操作中断线：**重试前先检查会话。重连不会自动重复业务请求或工具效果。

可用性以所安装的构建为准；源码中的界面改动可能尚未进入最新发布版，使用预览功能前请查看发布说明。
