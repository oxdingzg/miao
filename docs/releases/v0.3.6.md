# miao v0.3.6

v0.3.6 fixes the two ways a native Session could look stuck, and makes the shell say what it is actually waiting on.

## Improvements and fixes

- **A delegation no longer strands its parent.** Waiting for a subagent read the child Session's events through a fixed 500-event window anchored at the admission sequence, so a child that recorded more than 500 events never surfaced its `run.finished`. The parent waited for a stop that could not arrive, the drain never ended, and the Session stayed busy forever — a hang, not a slow turn. The wait now advances a cursor and pages until the child's outcome is visible.
- **Queued prompts stay visible in a native Session.** Their inbox lives in the engine, so the shell's per-second input poll saw an empty list and deleted the admitted receipts it had just rendered. A `pending_inputs` command now reads unpromoted admissions — with their attachments, delivery and admission time — and the client projects them as ordinary pending inputs.
- **A waiting turn no longer reads as a stopped one.** The status line preferred the previous step's settled activity (`ran 2 shell commands · 8m 46s`) over the fact that the model had not answered yet, which is exactly the shape an operator reads as a hung tool. Waiting now outranks stale activity and keeps a live timer.
- **A native turn reports its provider phase.** Status carries `preparing`, `requesting` and `retrying`, so a slow first token renders as waiting on the model rather than as local work. The phase is derived from durable events only, so a reconnect replays the same status stream it delivered live; live-only stream fragments publish in a separate ordinal band, so a delta that arrives before the commit it belongs to cannot collide with that commit's events.
- **The sidebar reads context as pressure and trend.** The Context section leads with a pressure bar against the window (`N% of <window>`, warning at 80% used, error at 90%) and a 40-turn sparkline, instead of ten flat text rows that required mental arithmetic. An unknown window keeps the absolute token count with no percentage, and a rejected turn is never presented as settled history.

## Validation and limits

Every change passed `guard` and the aggregated `ci-gate` suite, including the Rust engine tests on macOS, Linux and Windows, the TypeScript unit, typecheck and e2e suites, and the session blackbox replay.

- The delegation cursor is covered by a drain test whose child Session records 668 events; the same test fails against the previous engine within 120 seconds.
- Pending inputs are covered by engine store and stdio tests plus a projection test for attachments and cursor paging.
- The phase mapping is covered by bridge and translator tests. The blackbox replay suites additionally require every published event to carry a unique source and a reconnect to reproduce the same event ids; that requirement rejected an earlier revision which published a `streaming` phase from the live progress pipe, since a progress-only event does not exist in the journal.
- The waiting status line is covered by TUI render tests.

Live engine recycling under a production daemon, clustered placement and long-running watcher hosts remain outside the automated evidence.
