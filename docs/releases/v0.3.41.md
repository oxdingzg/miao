# miao v0.3.41

v0.3.41 makes the strip at the foot of the screen say what it was missing.

## The provider stands beside the model

- **The Session strip names the provider.** It read
  `deepseek-v4-1-flash-261017 · openai-chat` — the model and its wire
  transport, with the provider that serves it left out, although the provider
  is the fact an operator changes their mind about. The strip is now
  model · provider · protocol · variant, and the picker keeps its own label
  because its rows already sit under a provider header.

## The landing screen says what the next prompt runs on

- **The launch prompt carries the model.** Before any Session exists the strip
  was cleared outright, and the engine's settings hold the
  `unavailable/model` sentinel, so the one screen whose job is "what will this
  prompt run on" said nothing at all. miao now remembers the last selection in
  the TUI's own preferences and labels it from the catalog there, the way the
  product's home status line reads its local selection.

The landing prompt keeps `prompt.max_width` (75 columns by default): the product
caps the home prompt the same way and leaves a Session composer full width.
