# miao v0.3.14

v0.3.14 修复了 v0.3.13 之后的启动失败。v0.3.13 把 Rust TUI 变成了 `miao` 默认启动的前端，而每次启动都在能输入任何提示词之前停在 `engine_closed: miao-engine output stream closed`。这是两个彼此独立的缺陷造成的，现在都已修复。不需要改任何配置：升级后照常启动 `miao` 即可。

## TUI

- **`miao` 又能启动引擎了（#1566）。** 启动器把**产品数据库**当成引擎的 `--db` 传给了 `miao-tui`。`miao-engine serve` 会拒绝这个文件——它是另一种 schema，引擎回一句 `Invalid("not a miao-engine database; use a separate path")` 并在读取任何请求之前退出，TUI 只能把它报告成输出流关闭。现在启动器改用和 server、migration CLI 相同的方式推导引擎数据库：一个 Location 的存储是它在引擎存储根目录下目录名的纯函数（`engine.storage`、`MIAO_ENGINE_STORAGE`，或产品数据旁的默认位置），因此 TUI 和 server 打开同一个文件。显式关掉 native storage 的安装现在会得到一句明确的拒绝，而不是一个立刻死掉子进程。
- **会话目录能加载了（#1566）。** 引擎的命令信封是相邻标记（adjacently tagged）的，声明为不带参数的命令不允许出现 `params` 键。TUI 读目录时发的是 `{"method":"sessions","params":{}}`，引擎每次都回 `invalid_request: expected an id and a typed method/params request`。`sessions` 和 `model_catalog` 现在按 TypeScript 宿主的写法发成 `{"method":"sessions"}`，于是首页列表、模型对话框和账户对话框都能填上内容。

## 引擎

- **派生配置段按各自的键路径校验（#1555），** 写错的 `agent`、`command` 或 `skill` 条目会指出具体失败的键，而不是笼统指向整个文档。
- **配置文档解析失败的目录现在会显式失败（#1547），** 而不是带着一份被静默削减的配置启动。
