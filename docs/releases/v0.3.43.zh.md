# miao v0.3.43

v0.3.43 让 native 引擎可以用上 OpenCode Go。

## 网关的每一轮都要说明自己的会话

- **从产品配置派生的路由会发送 `x-opencode-session`（#2586）。**
  native 引擎的模型路由由产品配置的 `providers` 段派生。此前这些派生路由带着
  provider、endpoint、凭据和限额，却没有鉴权头；而 OpenCode 的网关按会话路由，
  不说明会话的请求会被直接拒绝。于是即便 key 已经存好，每个 `opencode-go` 回合仍然
  返回 `HTTP 400 MissingSessionID`；而配置里没有对应路由的模型会静默回落到配置声明的
  第一条路由——通常是一个 OpenCode Free 条目，于是得到 `429 FreeUsageLimitError`。
  现在 `opencode-go` 的路由会带上与会话绑定的头，复用产品自身路由所用的 `$session`
  占位符，兄弟 Session 依旧各自路由与缓存。该 provider 的环境变量回退也改用网关文档
  里的 `OPENCODE_API_KEY`，而不是机械拼出的 `OPENCODE_GO_API_KEY`。

## 手机可以独立使用

- **在遥控之外新增「本机」模式（#2584）。** iOS App 现在有两个 Tab。「本机」完全在手机上运行助手：服务商在手机上配置、进程内 Agent 循环与沙箱文件工具、流式输出按 Markdown 渲染、多会话、图片附件、语音输入，并可选接 HTTP MCP 工具。「电脑」保持原有遥控客户端。添加服务商只需选一个、填一把 Key：内置火山引擎、智谱、DeepSeek、OpenAI、Kimi、百炼、硅基流动与 OpenRouter。
- **排队改为单条消息的选择，而不是一个模式（#2589、#2591）。** 遥控输入栏原先是粘性「排队」开关，之后每条消息都会静默排队，一条回答看起来像是回答更早的问题。现在只在运行中出现、发送后复位，并提示「已排队：这一轮结束后发送」。
- **TUI 在回合进行中改为排队（#2590）。** 过去每条输入都以插话投递，会并进正在跑的回合；后续补充容易被当成当前任务的一部分。现在有活动回合时排队、空闲时直发，与 Claude Code 一致；Esc 仍先取回最新排队输入再中断。
