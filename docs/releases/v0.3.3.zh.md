# miao v0.3.3

[English](https://github.com/oxdingzg/miao/blob/v0.3.3/docs/releases/v0.3.3.md)

本版本修复原生引擎长任务中断、过程缺少说明、会话标题恢复与 Google 错误误判，并补上产品与原生引擎之间的回归验证。

## 改进与修复

- 产品会话取消隐式的 25 次模型请求上限。显式配置的 agent 轮数限制仍然生效，暂停原因可在历史记录中重放。独立引擎配置保留文档中的默认预算。
- 原生执行复用 TypeScript runner 的模型专属提示词。连续三批工具调用没有普通说明时，在下一次请求中提醒模型用用户的语言报告简短进展；不会伪造持久用户消息，也不改变工具结果顺序。
- 统一识别裸 `New session` 占位标题。空闲及重新访问的历史未命名会话可补生成标题；辅助请求有超时和模型回退。手动重命名同步原生与目录状态，并优先于后台生成。
- 区分 Google 请求限流、服务额度耗尽、临时容量不足和未分类的 429，保留真实状态与重置提示，支持周额度提示。关闭网关隐藏的 SDK 重试及控制台堆栈输出，避免把有效的服务端错误误报为流格式异常。
- 会话页合并重复的输入框模型栏，把模型、变体、上下文、目录、分支和 agent 集中在底部一行；仍可点击模型打开选择器。
- 产品原生会话、provider、系统上下文及投影代码变化时，CI 必须运行真实原生二进制的 HTTP 回归。测试使用已提交的模型目录样本并禁止联网发现，修复冷启动下载导致的不确定超时。

## 验证与边界

最终组合代码的 Rust 全套测试通过 645 项，零失败。其余 CLI 测试按文件隔离运行，通过 144 个文件、1,043 项测试，零失败；编译后的预览版通过真实 PTY 检查，模型与状态信息合并为一行。真实原生二进制的完整 HTTP 套件通过 343 项测试，覆盖 119 个文件。受控 HTTP 场景分别通过 TS 与原生执行相同的 27 次请求任务，并验证显式轮数暂停、重启历史、模型绑定及标题恢复。模型提示词校验使用实际 TS 选择器生成的 21 组哈希。真实 Google 会话完成十次连续工具调用，并输出三次可读进展；之后服务端报告了额度耗尽。

Gemini 网页的用量不等于另一个接入服务的可用额度。上游真实额度不足仍需等待服务恢复；miao 会保留证据及重置提示，不会静默切换账号或 provider。未连接账号的真实服务验收不属于自动化测试已证明的范围。
