# miao v0.3.39

v0.3.39 makes the two things an operator does most often — adding a provider
and leaving a session — end where the screen says they end.

## Adding a provider works from the command line

- **`miao auth` finds the product store by itself (#2553).** `auth login` and
  `auth` refused to run without `MIAO_ENGINE_CREDENTIAL_DB`, so on a default
  install the command the TUI told an operator to run failed on an internal
  variable name. The store resolves the way the engine already resolves it —
  an explicit value wins, otherwise `<data home>/miao.db`, created on the first
  login — and a store nobody wrote yet lists as empty instead of as an error.
- **`auth logout` can name an account (#2553).** It removed only the `default`
  label, so an account stored with `--account NAME` could not be removed by any
  command. It now takes `--account NAME` and reports how many remain.
- **A provider is added inside the picker (#2556).** Selecting a provider the
  engine does not serve yet used to answer with instructions: run `miao auth
  login <provider> <key>` in a shell, then restart miao. It now opens a key
  prompt; Enter stores the key in the product credential store — the same file
  a single-binary start reads, created on first use — and says the restart is
  what brings the provider's models in. Providers the shipped catalog serves
  over `@ai-sdk/openai-compatible` (opencode-go among them) need nothing else;
  one that is not in the catalog at all, or is served over a native protocol
  (openai, google), still needs a `providers` entry in the configuration.
- **`miao models` lists what the engine actually serves (#2555).** It read only
  the configured providers, so a machine that routes nine providers reported
  three: the catalog-derived routes that `model-routes.json` carries never
  appeared. It now reuses the engine's own route materialisation and prints the
  same set the running engine has.
- **The instruction it replaced was wrong twice (#2554).** It also said to add a
  model for the provider in `miao.json`. The engine builds its route table when
  it starts and this TUI has no reload path, so reopening the picker inside the
  running process could never show the new provider; and the providers the
  engine serves over `@ai-sdk/openai-compatible` route automatically once they
  hold a key credential, so the `miao.json` step was unnecessary for the ones
  an operator is most likely to add.

## Leaving a session names it

- **Quitting prints the Session and how to return (#2551).** The Rust TUI had
  no exit epilogue at all — the only one lived in the legacy TypeScript TUI,
  which runs only under `--tui=legacy` — so a finished conversation left no
  identifier an operator could type. It now prints the title, the id, and
  `miao -s <id>`, after the alternate screen is restored, which is also why
  earlier attempts printed nothing at all.

## Pickers paint what they list

- **ctrl+o in the model picker, and the paired-device list (#2552).** Both
  answered `title()` and took the keyboard without being reachable through the
  list accessors the paint path uses, so they drew a border and a title over an
  empty body. Both variants are reachable now, with a test that walks every list
  variant so the class cannot come back.
