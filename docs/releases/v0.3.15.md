# miao v0.3.15

v0.3.15 is a reliability release. Two defects that made miao look frozen or die mid-turn are fixed, and neither needs a configuration change: upgrade and start `miao` as before.

## TUI

- **An engine that fails to start now says why (#1580).** Every engine startup failure reached the screen as `engine_closed: miao-engine output stream closed`, whatever the cause: the child's stderr was captured only to detect `Busy` and then discarded, and the stdout reader published the closure before the reaper could read the exit status. On EOF the TUI now waits up to 500 ms for the exit status and quotes the last lines of the engine's stderr, so a refusal reads `engine_closed: miao-engine exited (exit status: 1): Error: "unknown or duplicate option"` instead of a bare stream closure. A version mix, or an engine handed a database it refuses, is now diagnosable instead of a dead screen.

## CLI

- **A closed terminal no longer ends the process (#1582).** Bun reports a failed write to a closed pipe or terminal after `write()` has returned, so no caller's `try/catch` ever sees it; it arrived as an `uncaughtException`, and the fatal handler recorded it and exited 1. That turned a window that went away — or a reader that stopped reading — into a mid-turn process death; one install's `crash.log` held 29 such records. `EPIPE`/`EIO` failures with `syscall: "write"` are now ignored by the fatal handler, while every other uncaught exception still exits non-zero.
