# miao v0.3.64

[English](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.64.md)

v0.3.64 的主线是「如实说明在跑什么」：后台任务在**运行中**就能报出它在说什么，jobs 面板显示任务的输出而不是整段结果外壳，压缩也会说清自己在做什么。同一版里**引擎沙箱默认关闭**，这是行为变更，升级前请先看这一节。

## 运行中的任务就能看到输出（#2925、#2923）

- **运行中的输出会被保留在内存里**，并在 jobs 回包里补进该行，所以任务还没结束时也能回答「它现在在说什么」。原先 `read_pipe` 是「读满整条流才返回」，progress 通道只在末尾收到一次；现在改为分块读并逐块上报，同时保持原来的 32769 字节上限与 `output_limit` 停止语义。
- **jobs 面板预览的是输出，而不是结果外壳**。过去它把整个 `result` 对象序列化进行里，显示成 `completed · {"enforcement_required":false,…}`；现在显示最新几行输出，失败且无输出时回落 `error`，并按行宽裁剪。

## 引擎沙箱默认关闭（#2927）

- **行为变更。** 未显式要求时，运行不再处于沙箱中：引擎默认不启用 workspace-write 沙箱启动命令，TUI 里用 `/sandbox` 为当前 Session 打开。若你此前依赖「沙箱总是开」的假设，请先确认这一点再升级。

## Windows 上被冻结的 permission source 重新生效（#2915、#2916、#2917）

- **冻结的工作区按 Location 的拼写存储。** handoff 行存的是 Windows `\\?\C:\...` 形式，而 `engine_location.root` 存普通形式，触发器那句字符串相等永不成立，于是冻结形同虚设。Windows 主机实测：`cargo test --lib permission` 由 5 passed / 1 failed 变为 **90 passed / 0 failed**。
- **发布门禁不再跳过这条用例**，`specs/ci-windows.md` 也记录它是产品缺陷而非 hosted runner 限制。
- **权限分类器不论分隔符都能识别受保护路径。** `protectedPath` 原先按 `path.sep` 切分，Windows 上拿到 POSIX 风格资源（`/project/.git/config`）时 `.git` 段不可见，判成 `safe`。

## 压缩按大小规划，并说明自己在做什么（#2920、#2921、#2912）

- **压缩按大小规划**，不再按消息条数。
- **被拒绝的一轮保留原因**，folding 改为显式开启。
- **状态条会报出「压缩停止」与「无法开始」**，不再让阶段状态无从判断。

## 验证

- 发布提交的 CI 全绿：`engine`（四分片）、`tui`、`cli`、`blackbox`、`unit`、`typecheck`。
- Windows 主机：`cargo test --lib permission` 90 passed / 0 failed；`miao-tui` 656 passed / 0 failed。
- 已知但**未在本次修复**（已记录）：`tests/web.rs` 在 Windows 上有一条审批相关用例以 `STATUS_STACK_OVERFLOW` 崩溃（#2926）；Windows 的 TS 单元腿仍红在没有产物消费的模块上（#2873）。

## 升级

`latest` 通道的 `miao` 会自动更新；否则重新执行安装命令。
