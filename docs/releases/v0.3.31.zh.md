# miao v0.3.31

v0.3.31 让 composer 在引擎帧流断掉之后不再永远等待，并完成了发布产物里最后一个
TypeScript 专用入口的退役。

## 帧静默时 composer 自行恢复

一个会话停在 `Waiting for model · no engine signal 6h 11m`,而引擎的 journal 讲的是另一
个故事：那次运行早在 01:10 就因 provider HTTP 520 失败并如实记录，之后用户发出的每一条
提示——包括那条「怎么不动了？」——都被正常受理并正常执行。引擎→TUI 的帧流断了，请求
通道却一直完好。状态栏甚至把静默时长测得很准，只是对这个测量结果什么都没做。

- **静默现在触发重投影 (#2495)。** 会话打开期间超过 30 秒收不到任何引擎帧，客户端就走
  请求通道重新投影。请求/应答不依赖事件流，composer 因此显示持久状态的真实结果——运行
  已结束、已失败、或仍在执行——而不是无限等待，同时给出一条「状态已从 journal 恢复」
  的提示。
- **间隔指数退避。** 每次由静默触发的投影把等待时间翻倍，300 秒封顶；任何一帧到达即重
  置，所以合法处于两帧之间的会话不会被反复投影打扰。

## install 不再下载早已不存在的伴随产物

- **`install` 只下载本平台产物 (#2497)。** 发布产物是每个平台一个 `miao-<os>-<arch>`，
  产品在进程内链接引擎与 TUI——v0.3.30 的 release 里根本没有 `miao-engine` 或 `miao-tui`
  归档。`install` 却仍然尝试下载这两个伴随产物：先从指定 release 下载，再从最新 release
  兜底。每次安装因此多了两个注定失败的请求，兜底失败还会落进 TypeScript 时代的报错文案。
  这两条路径连同其报错一并删除。

## TS 的 `__sandbox-run` 入口退役

- **隐藏的 `__sandbox-run` 命令删除 (#2494)。** 它存在的唯一意义，是让单文件编译的
  TypeScript 构建能把自己重新执行为 sandbox runner。那个构建已经不存在——CI 的 sandbox
  冒烟走 `miao-run` (#2493)，发布的是 Rust 二进制，Rust 引擎自带 `__sandbox-run` 处理。
  没有任何路径再派发 TS 入口，因此 `packages/miao/src/sandbox-runner.ts` 一并删除。
