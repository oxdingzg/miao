# miao v0.3.7

v0.3.7 is mostly the native engine learning to let go: an orphaned engine is released instead of being resurrected by the supervisor tick, an idle engine stops being kept alive by other processes' work, catalog and peer reads carry metadata instead of history, a lost engine is reported as a failed turn rather than a hang, and a long foreground command is no longer rejected at two minutes. The shell picks up what the engine durably recorded — one identity for engine-generated inputs, session listings back in their own scope, a compact live row — and the build can embed the engine it pairs with.

## Engine and native Session

- **An orphaned engine is released, not resurrected.** A 60-second supervisor tick re-owned every dead engine unconditionally, so an engine that reclaimed itself after 15 idle minutes was respawned a minute later, forever, spawning fresh LSP and MCP children each cycle — one window reached 68 live engines. Re-owning now happens only when the dead child's last probe showed armed timers. When the shell dies ungracefully, a Unix host-death watchdog in the engine polls the parent pid and unwinds cleanly, reaping kill-on-drop children instead of waiting for an stdin EOF that inherited LSP/MCP descriptors prevent from ever arriving; Windows keeps the idle-reclaim backstop.
- **An idle engine is released, not kept alive by other processes' work.** Idle detection asked the shared engine database for every running row, so work owned by another process — or a crash residue nobody claimed — kept an otherwise idle engine alive, and completed timer/cron handles counted as live work on top of that. Reclamation now looks only at rows this process owns plus its unfinished local background tasks, and leaves other owners' rows alone.
- **Catalog and peer reads carry metadata only.** A session-list snapshot projected and transmitted message history, and a snapshot that timed out could take the shared engine down while another Session was executing. Catalog and peer reads now ask for metadata without projecting or sending history — a 4 MiB transcript keeps its full snapshot while the metadata response stays under 4 KiB — and large JSONL frames are assembled without rescanning everything accumulated so far.
- **A lost engine is reported as a failed turn, not a hang.** Replay bursts used to terminate the engine when its output queue filled; they now wait for bounded capacity. Shutdown drains and closes the output receiver even when the bridge still holds sender clones, where the previous release acknowledged shutdown and stayed alive. An unexpected engine exit publishes an ordered live failure and idle status for busy Sessions, so the shell stops showing an execution that no longer exists; no durable cursor is invented and no provider work or tool is retried automatically.
- **An open Session stays visible when only its catalog entry fails**, instead of the listing dropping it.
- **Long foreground commands are no longer rejected.** The `bash` and `run_command` tools capped `timeout_ms` at two minutes while the product's TypeScript tool accepts ten, so a three-minute remote build came back as a bare "invalid tool input" and the model retried the same command. The ceiling is now ten minutes and the default two, matching the product.
- **The engine's route schema is decoded as it is sent.** Provider routes come back in snake_case, and reading them as camelCase silently produced empty or partial route sets. The client now decodes snake_case and rejects conflicting or non-numeric entries instead of guessing.
- **Engine-generated inputs share one identity.** A pending inbox containing a monitor, wakeup, cron or job notice failed the whole page: the projection decoded every engine input id as a paid prompt id. Inbox read, promotion projection and revert boundary now derive one identity from the engine's durable input id, so a notice stays the same object across all three.
- **An explicit context window survives route generation.** A configured native context window was silently replaced by the catalog window whenever the host generated provider routes, so `MIAO_CONTEXT_LIMITS=4000` ran with the model's full window. Generated routes now inherit the explicit configuration, matching the precedence operator-provided routes already had.
- **Two concurrent creates of one native Session adopt each other.** Both could observe an empty product projection; if one published the Rust placement before the other reached the TypeScript ownership fence, the second failed instead of joining. On that specific placement conflict the second create now re-reads and adopts the existing Session, while a binding with no projected Session still fails.

## Shell, app and CLI

- **The live row is one line.** A running turn repeated agent/model metadata, a waiting row, a scanner/timer/interrupt row and a status line around a padded input. One fixed row now carries the phase or tool activity, phase elapsed time, the turn duration when it differs and fits, and the next Escape action; failures stay in the transcript.
- **Session lists stay in scope.** Refresh and the session picker dropped directory/project scope when calling the V2 list API. Both now send the current absolute directory by default, or the current project when directory filtering is disabled, and fall back to directory scope when project identity is unavailable.
- **Usage history is readable after paging.** Settled provider steps survive transcript paging and compaction as durable facts, and a new paginated endpoint exposes model attribution, input/output/reasoning and cache read/write tokens, cost and observed TTFT. The app charts that history per bar, separating uncached input from cache reads and writes, with independent scales when the model or window changes.
- **The home screen names its version.** The installation version now renders under the home logo; it previously appeared only in the sidebar footer and the debug dialog.
- **A headless run keeps its title.** A short `miao run` could finish its answer and close the runtime before the background title was persisted. Explicit Session waiters now settle that Session's existing title work without taking ownership of model work or changing busy/idle status.
- **Native background logs stay off the protocol stream.** Native background fibers were built outside the server's observability layer, so their default logger wrote multiline diagnostics to stdout — the same stream an ACP editor reads as JSON-RPC. An exchange could therefore be corrupted by a background title log. Those fibers now log through the server layer, and a real `miao acp` subprocess exchange completes with every frame valid JSON-RPC.
- **MCP tools keep their real names.** Native MCP aliases truncate and sanitize server and tool names, and decoding the alias's first underscore reconstructed the wrong product identity for long names or names containing underscores. The trusted original identity is now stamped into durable history instead of being re-derived.
- **A compact tool that needs approval is bound to its planned target.** When an extension discovered through `tool_call` needed approval, the runtime prepared its real target and arguments while the store compared them against the wrapper's persisted name and input, so the run failed before approval was even shown. The approval is now bound to the planned target: no call before approval, one dispatch after acceptance, none after rejection.
- **Cancelling a Session cancels its running hooks.** A pre/post-tool lifecycle hook received a fresh cancellation token instead of the active Session's, so an operator could cancel and the hook process kept running until it finished on its own. Hooks now share the Session's token.
- **A title is generated and renamed once.** A native Session's idle listener and an explicit wait could generate its title at the same time, and the duplicate guard returned immediately for the second request, so a short-lived CLI could finish its wait before the rename was durable. Title work is now coalesced by storage and Session ID around the whole generation-and-rename operation, and waiters join it through the durable rename.

## Build, CI and release

- **The single-file build embeds an engine.** A build that passes `--engine` bakes the engine binary into the compiled executable and materializes it at startup where candidate discovery looks, so a fresh install works without a separate install-engine step. An already-installed compatible engine still wins; the embedded copy only fills the gap.
- **Windows validation moved to the release gate.** Windows engine and runtime suites no longer run on pull requests or pushes to `main`; the nightly schedule is the early warning and `release.yml` runs the full Windows engine suite against the exact release commit, with publishing waiting on it. An ordinary pull request starts no Windows job, so a Windows-only break surfaces at night or at release instead of on the PR.
- **Benchmarks left the pull-request path** for the same reason: they cost a runner on every push without gating anything.

## Validation and limits

Every change passed `guard` and the aggregated `ci-gate` suite, including the Rust engine tests on macOS and Linux, the TypeScript unit, typecheck and e2e suites, the session blackbox replay, and the conformance harness.

- The released engine's Windows suite is the one place Windows is guaranteed to run against a shipped commit; the first release with that gate is this one.
- Editor acceptance against the compiled 0.3.7 candidate (Neovim 0.12.6 with CodeCompanion v20.0.1) passed allow-once, reject and cancellation through the actual UI, and the earlier protocol failure it found — background title logs on ACP stdout — is the fix above.
- R13 and R14 conformance evidence is retained in full, including the failing R13 cell that exposed the title wait/rename race fixed above; every evidence file passed parsing and credential/private-host scans.
- The plan for Phase 2 — retiring the second placement and collapsing the runtime onto one kernel, with the capabilities that must exist first — is recorded in `specs/rust-phase-2.md`. It is a design document, not a description of what this release does.
- Long-running watcher hosts, clustered placement and live engine recycling under a production daemon remain outside the automated evidence.
