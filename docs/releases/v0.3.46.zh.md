# miao v0.3.46

v0.3.46 修掉了「刚存入 provider key 仍然要求整个重启」的原因，修好工作区界面上的两个
缺陷，并让落后于输出的终端读取直接跳到最新窗口，而不是逐块追赶积压。

## 存入的 key 能直接服务它的模型

- **无论多大都要写出路由清单（#2662）。** 启动器会派生模型路由，写进临时清单，并把
  `MIAO_ENGINE_MODEL_ROUTES_CONFIG` 指向它——但只在序列化后小于 64 KiB 时才写。
  超过这个上限文件就被跳过，这次启动仍用启动时派生的那份路由，于是之后存入的 key
  无处追加路由：provider 与它的模型要等整个 miao 重启、重新派生列表之后才出现。
  这个上限属于「经环境变量传值」，不属于引擎自己读的文件。`miao serve` 的派生路径
  有同一个门槛，会静默退回「只有配置里的路由」；现在两条路径共用一个写入函数。

## 工作区界面

- **`<leader>w` 又能列出工作区了（#2663）。** 这条命令给 unit 标签的请求发了一个
  空 `params` 对象，引擎以 `unsupported request workspaces` 拒绝。
- **删除 worktree 不再让它上面工作的 Session 失联（#2663）。** 之前只读检出目录的
  台账，所以一棵在成为 worktree 之前就有 Session 入驻的树，可能在自己的台账仍锚定
  着这些 Session 时被删除，把它们的工作目录弄丢。现在两份台账都读，强制删除时也都
  重新指向。

## 终端读取

- **落后的读取从最新窗口继续（#2661）。** 当读取游标被 1 MiB 环形缓冲越过时，它
  会从最旧的保留字节重放，于是慢读者每次调用只能前进一个 32 KiB 窗口，而程序仍在
  绘制，永远追不上当前画面。全屏重绘又只用转义定位、不输出换行，行预算折不开，面板
  会把一整屏当成一行来排版；两处都修了。
