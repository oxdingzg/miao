# miao v0.2.22

本版修复引擎工作目录消失后会话列表无法加载的问题，让原生会话的停止失败在对话里可见，并避免把总结请求发给容量不足的模型。

## 修复

- **工作目录消失后的会话列表**：原生会话的 placement 可能比它的目录活得更久，例如 worktree 被外部删除，或引擎存储来自一个临时工作区。读取这样的 Location 会在 `realPath` 上失败，导致整个会话列表返回 500，连健康的会话也一起看不到。现在会跳过无法读取的 Location 并记录警告，目录和其余可读的引擎位置照常提供各自的分页结果。该存储里的会话历史不会被改动；目录恢复后它们会重新出现（#1190）。
- **原生会话的停止失败**：App 的 reducer 之前忽略引擎的 `session.next.failed` 事件，导致正在流式输出的 assistant 草稿永远不结束，错误也看不见。现在它按 `step.failed` 的方式结算：消息以错误结束，挂起的工具标记为 interrupted；没有未结算内容时该事件是幂等的空操作。只有步骤、没有内容的事件也会先创建 assistant 消息，因此重放的 `tool.called` 和 `step.ended` 会更新真实消息而不是去改不存在的消息（#1186）。

## 引擎

- 路由清单 v2 会发布每个模型声明的上下文和输出容量。总结角色在发送前会用保留片段的估算 token 与绑定模型的声明容量比较，容量不足时跳过该模型，记录 `role.provider.skipped` 和 `reason: capacity`，改由主模型执行。这修复了大上下文会话的总结请求被发给小上下文模型、随后被服务商拒绝的情况（#1185）。

## 验证范围

所有改动合入前均通过完整 CI。会话列表修复为两种情形增加了回归测试：解析时目录已消失，以及快照时引擎子进程已死；两者都断言健康的原生会话仍然出现在列表里。对话修复新增 5 个基于真实 wire 结构的 reducer 测试，其中一个覆盖原生会话被 drain 失败后草稿必须结算且错误可见。引擎侧覆盖 Rust 的 `route_limits` 集成测试（声明与未声明容量）、TypeScript 清单测试（发布的 `limit` 字段），以及两侧的类型检查。

## 更新方式

重新运行安装脚本，或让正在运行的 `miao` 在下次检查时通过后台更新获取 v0.2.22。已有会话、凭据和配置都会保留。
