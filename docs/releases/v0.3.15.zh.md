# miao v0.3.15

v0.3.15 是一次可靠性修复。两个让 miao 看起来卡死、或跑到一半就退出的缺陷都已修复，两者都不需要改任何配置：升级后照常启动 `miao` 即可。

## TUI

- **引擎启动失败时现在会说明原因（#1580）。** 以前不管什么原因，引擎启动失败到屏幕上都是一句 `engine_closed: miao-engine output stream closed`：子进程的 stderr 只被用来识别 `Busy`，随后就被丢弃，而 stdout 读取端在回收器读到退出状态之前就先把关闭发布了出去。现在遇到 EOF 时 TUI 会最多等 500 ms 取到退出状态，并引用引擎 stderr 的最后几行，于是拒绝的原因会显示成 `engine_closed: miao-engine exited (exit status: 1): Error: "unknown or duplicate option"`，而不是一句光秃秃的输出流关闭。版本混搭、或引擎拿到它拒绝的数据库，现在都能直接看出原因，而不是一块死掉的屏幕。

## CLI

- **终端断开不再结束整个进程（#1582）。** Bun 会把写入已关闭的管道或终端报告在 `write()` 返回**之后**，因此任何调用方的 `try/catch` 都看不到它；它以 `uncaughtException` 的形式到达，致命处理器记录后 `exit(1)`。于是一个关掉的窗口、或一个不再读取的对端，就变成了跑到一半的进程死亡；某台安装的 `crash.log` 里有 29 条这样的记录。现在致命处理器会忽略 `syscall` 为 `write` 的 `EPIPE`/`EIO`，其它未捕获异常仍然以非零码退出。
