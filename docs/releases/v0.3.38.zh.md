# miao v0.3.38

v0.3.38 让任务清单真正生效:模型看得到它,右侧的清单才会填上内容。

## 任务清单随每一轮请求发出

- **每种模型都会被告知如何维护清单 (#2544)。** 引擎此前只在清单已经存在时才发送
  持久状态,而 persona 素材里只有 Anthropic 系列提到 `todowrite`。用其他模型
  ——DeepSeek、GPT、Gemini、Kimi——的会话从未听说过这个工具,于是没人写下第一份
  清单,右侧面板整场会话都显示 `Todo 0/0`。现在 system prompt 末尾带上任务清单
  规程(跟踪多步工作、开始时标 `in_progress`、验证后标 `completed`、用 id 与
  `depends_on` 表达依赖、说明阻塞含义),已记录的清单仍随每轮的状态注记送达。
- **`todowrite` 读起来是一个规划工具。** 描述改为先说"跟踪多步工作",而不是
  描述这次存储调用,与 TypeScript 版给模型的说法一致。

## 输入框改为换行,而不是横向滚动

- **长草稿在框内换行 (#2540)。** 之前 composer 按水平偏移裁掉光标所在行,而框的
  高度却按换行后的行数增长,输过边界后只剩尾部可见。现在逐显示行绘制,光标跟随
  换行移动;正好填满一行时仍为光标保留一格。
- **首页输入框随草稿增高。** 它此前用整个窗口宽度(而不是 `prompt.max_width`)
  计算换行,还在已含边框的高度上又加了 2 行。
- **排队内容显示在输入框上方 (#2540)。** 回合进行中发出的提示过去只在标题里显示
  `1 queued`;现在等待中的提示直接画在输入框上方(`❯ 内容 · queued`,最多三条,
  更早的折叠为计数),位置就是操作者输入的地方。

## 会给出下一步动作的诊断

- **缓存健康给出修复建议 (#2535)。** `cacheDiagnostics` 新增 `recommendations`
  ——分解不合法、未上报缓存读取、无缓存读取——并带上各自计数,不再只给一个
  `null` 比率。
- **未知配置键会被点名 (#2534)。** `config explain` 新增 `warnings`,给出所在
  来源和最接近的已知键;`miao debug config` 打印来源、解析结果以及这些告警。
  读取本身仍然成功。

0.3.37 的其余内容全部保留:平铺的转录、`ctrl+o` 的 provider 回退、到达即显示,
以及诚实的 `miao upgrade`。
