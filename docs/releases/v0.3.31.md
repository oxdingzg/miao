# miao v0.3.31

v0.3.31 stops the composer from waiting forever when the engine's frame stream
dies underneath it, and finishes retiring the last TypeScript-only entry point
from the shipped binary.

## The composer recovers when frames go quiet

A session sat at `Waiting for model · no engine signal 6h 11m` while the engine
journal told a different story: the run had failed with a provider HTTP 520 at
01:10, the failure was recorded, and every later prompt — including the user's
"why is this stuck" — was admitted and served normally. The engine→TUI frame
stream was dead; the request path was fine. The status line even measured the
silence correctly. It just did nothing with the measurement.

- **Silence now triggers a re-projection (#2495).** When no engine frame arrives
  for 30 seconds while a Session is open, the client re-projects through the
  request path. Request/response does not depend on the stream, so the composer
  shows the durable truth — run finished, failed, or still running — instead of
  an unbounded wait. A notice says the state was recovered from the journal.
- **The interval backs off.** Each quiet-triggered projection doubles the wait
  up to a 300 second ceiling, and any arriving frame resets it, so a session
  that is legitimately between frames is not hammered with projections.

## install stops downloading companions that no longer exist

- **`install` fetches exactly the platform artifact (#2497).** Releases publish
  one artifact per platform, `miao-<os>-<arch>`, and the product links the
  engine and the TUI in-process — v0.3.30 carries no `miao-engine` or
  `miao-tui` archive at all. `install` still tried to download both companions:
  first from the requested release, then from the newest release as a fallback.
  Every install therefore made two requests that could only fail, and each
  fallback ended in a TypeScript-era message. Those paths and their messages are
  gone.

## The TS sandbox-run entry point is gone

- **The hidden `__sandbox-run` command is deleted (#2494).** It existed only so
  a compiled single-file TypeScript build could re-execute itself as the
  sandbox runner. That build is gone — CI runs the sandbox smoke through
  `miao-run` (#2493), the shipped binary is Rust, and the Rust engine carries
  its own `__sandbox-run` handling. Nothing dispatched the TS path any more, so
  `packages/miao/src/sandbox-runner.ts` is deleted with it.

## Upgrading

    miao upgrade
