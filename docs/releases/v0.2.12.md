## [0.2.12] - 2026-10-16

miao 0.2.12 fixes long sessions: a turn could reach the input ceiling the
provider enforces without compacting, and recovering from that refusal took
long enough that a stopped drain never wrote the checkpoint, so the same
refusal returned on every continuation.

### Fixed

- **Context limits**: compaction now plans against the input ceiling a model
  catalog publishes next to the context (`limit.input`, the context minus the
  output the endpoint reserves) instead of the raw context. On a model that
  advertises 1,050,000 tokens but accepts 922,000 as input, the old budget sat
  64k above what the endpoint takes, so a request in between went out and came
  back `context_length_exceeded` while the session still reported a few percent
  of its window in use (#894).
- **Overflow recovery**: a refused turn is summarized in one cached call over
  its own prefix, because a summary reserves only its own output and so still
  fits where the turn did not. The bounded slices stay as the fallback for a
  prefix that cannot hold the instruction at all, which is what writes a
  checkpoint instead of a chain of slices a stopped drain abandons (#894).
- **Budget reporting**: compaction, the context notice, and the interface share
  one sending-time budget, marked as estimated or counted, and a provider
  report is reused only while the request prefix it describes still matches
  (#893).
- **Auto-continuation**: a runnable todo list no longer keeps a session going
  after a provider turn was rejected for size, so a refused request is not
  replayed indefinitely (#893).

### Validation and upgrade

- Upgrade through the usual miao auto-update channel, or use the repository
  installer. The published artifact is smoke-tested by launching the terminal
  interface, not only by asking it for its version.
