# miao v0.3.4

[English](https://github.com/oxdingzg/miao/blob/v0.3.4/docs/releases/v0.3.4.md)

本版本让长时会话端到端可靠：客户端消失后原生引擎自行回收，卡住的控制调用会给出明确的超时而非笼统的传输错误，已经追平的订阅者不再重放整个 journal。TUI 不再把往回翻历史的读者拽回末尾，不再让提示词投递状态撑大对话记录，还允许把仍在排队、尚未投递的提示词取回编辑，并在每条回合结束时用一行总结它的耗时、完成时间以及仍在后台运行的工作。新增的每条提示词软性 token 预算会把失控的 drain 收束成一份总结，而不是一张无上限的账单；进程命令也首次遵循运维方的沙箱开关。

## 改进与修复

- 进程命令遵循运维沙箱开关。原生引擎对自己运行的命令应用配置的沙箱策略，而不是固定行为，运维可以按部署开启或关闭隔离。
- 客户端未正常退出的 stdio 引擎现在仅以客户端输入判断回收。内部事件与进度通知不再顺延空闲期限，活跃后台工作仍会顺延；被终止或打断的引擎通过 shutdown 展开，kill-on-drop 的子进程（LSP、MCP、worker）被回收而非变成孤儿。shutdown 之后直接退出，避免卡在 stdin 兜底读取上。
- 关闭交互式原生客户端不再留下悬空的请求：未完成的 RPC 被拒绝、请求优雅关闭、不退出就回收子进程，持有管道的后代进程无法在宿主退出后继续吊着引擎。控制类 RPC 获得 60 秒期限，超时会点名卡住的操作并指向 durable-receipt 指引；模型执行仍是异步的，不受该期限约束。CLI 里第二个遗留信号处理器已移除，SIGTERM 与 SIGHUP 统一走窗口持有的关闭路径，在进程退出前完成原生客户端清理。
- 已经追平的原生事件订阅者立即返回空页，不再每次轮询都重新解码并翻译整份 journal。新事件与重连仍会重建所需前缀并保持既有身份；2,500 事件的回归测试禁止任何空闲 journal 读取。
- 重复相同的工具调用会被拒绝并返回纠正性错误结果，而不是让整个运行失败。原生 loop guard 现在只对模型原始输入签名、与 TypeScript 阈值一致、每个耗尽签名只上报一次，并给模型改变思路的机会；批量读取在守卫前结算，合法轮询不受影响。
- 助手身份归属到实际服务的 agent。引擎在 provider 身份之外记录 agent 清单名，宿主通过定价目录渲染产品模型，会话头部显示真实的 agent 与模型，而不是空 agent 或 Unknown 占位。
- 会话标题使用真正服务该会话的模型。过时或为空的产品行不再把标题请求打到已耗尽的 provider，而对话本身在另一个模型上正常工作；耗尽的标题候选也会记录日志。
- task 工具在每次准入时注册命名 subagent。直接点名 subagent 的 task 调用不再以未注册失败，未变化的目录不会每条提示词重复追加注册事件，引擎任务输入被投影为产品词汇（subagent_type 与首行描述），子任务行标题与原生产品任务一致。
- 新增每条提示词的软性 token 预算，约束打转的 drain。`agent.budget` 在一次准入提示词的所有 provider 轮次中统计计费的输入、输出、推理与缓存 token；到 80% 提示模型收尾，到 100% 只给一个不带工具的终轮，drain 以一条 durable 暂停通知结束并记录停止原因。提交新的用户输入会重置预算，每条提示词各有自己的额度。
- Google 账号配额错误现在说明它来自 Antigravity 模型服务，而不是 Gemini App 的用量限制；模型发现保留后端原因与重置延迟，限流与容量错误保留证据，不暴露 provider 描述、也不增加重试。
- 原生模型与变体选择在成功选择后会被记住（包括变体轮换），重启 TUI 会恢复你选择的模型而不是此前保存的旧值；被拒绝的选择不会改动已保存的偏好。
- TUI 等待提示词准入不再受客户端超时限制，负载下的慢准入不会在客户端表现为传输错误。
- 往回翻历史不再丢失新输出。离开末尾时记住最后读到的消息，之后到达的消息以 `↓ N new messages` 胶囊计数；点击它、按最后一条消息快捷键，或滚回接近底部，都会重新钉住末尾并清零。胶囊是浮层，出现与消失都不会重排对话。
- 提示词投递状态移到页脚。SENDING、RETRYING、QUEUED 不再渲染在用户行内，等待准入的提示词不会撑大对话记录、也不会改写已经发出的消息；历史只保留持久消息。
- 重复的工具行被折叠。连续完成的读取合并成一行 `Read N files`，点击展开路径；运行中与失败的读取保持独立，正文或其它工具会打断这一组。超过行内预算的编辑 diff 现在预览前 20 行并统计剩余行数（`edit` 与 `apply_patch` 都适用），不再把改动藏在一次点击之后。
- 仍在等待投递的提示词可以取回编辑。esc 现在移除最新的等待提示词，只有队列为空时才打断正在运行的回合；上箭头把那条提示词取回输入框，服务端确认取消后才恢复文本。已经越过提升边界的提示词属于历史，绝不会被恢复；被其它客户端取消的提示词也不再显示为待投递。队列非空时 esc 提示读作 `remove prompt`。
- 回合结束会留下一行总结：`● Worked for 1m 12s · done 11:42 AM`。它覆盖从开启该回合的提示词到最后一个完成步骤的整段耗时，而不只是单个步骤；被中断的回合读作 `Stopped after …`，结尾失败的回合仍交给原有的错误块，仍有委托出去的子会话在运行时追加 `· N subagents still running`。
- 终端标题只保留会话主题。硬编码的 `miao | ` 前缀已移除，空标题或仅控制字符的标题仍回退为 `miao`，40 字素上限不再被七个字符的装饰占去。

## 验证与边界

Rust 引擎套件在 macOS arm 构建机上零失败通过（单元、集成与终端覆盖），`cargo clippy --all-targets -- -D warnings` 与 `cargo fmt --check` 干净；cron 容量测试改为调度互不相同的输入，真正覆盖它声称测试的共享预算。TypeScript typecheck 通过，engine bridge、assistant-identity、translator、session-runner、journal 与原生客户端生命周期套件全部通过，最后一项包含针对真实预编译引擎的"无响应子进程"测试。空闲回收由真实 stdio 引擎测试覆盖：启动二进制、在无客户端关闭的情况下度过空闲窗口并断言干净退出；真实 TUI 运行后发送 SIGTERM 能回收其原生子进程。TUI 交互测试覆盖新消息胶囊、页脚回执线、读取折叠、diff 预览、终端标题、esc 与上箭头共享的等待提示词目标，以及回合总结的仅限最后一回合、中断、失败结尾与后台子会话等情形。

每条提示词的 token 预算由 TypeScript runner 执行。原生引擎的 agent 清单对未知字段严格校验，因此本版本尚未把 `budget` 转发给它，原生 drain 仍以会话级 USD 预算作为唯一上限，引擎侧执行留待后续。生产 daemon 下的引擎回收、集群化放置与长期 watcher 宿主仍在自动化验证之外。
