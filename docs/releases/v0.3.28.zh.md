# miao v0.3.28

v0.3.28 修复了让长回答只以残片形式出现的缺陷：进程内引擎把自己的进度通道饿死，
承载流式增量的环形缓冲溢出，而客户端又把本可用于修复的溢出信号丢掉了。
现在两条引擎路径上的回合都会一边流式输出一边绘制。

## 流式回答不再丢失开头

- **进程内传输层不再饿死进度接收端 (#2439)。** `start_embedded` 把
  `runtime.progress()` 和 `host.dispatch(...).await` 放在同一个 `select!` 里，
  而一次 dispatch 会占住该循环跑完整个 provider 回合。该通道是 256 槽的环形
  缓冲，引擎对每个流式增量发一条通知——单次回答实测 **597 条**——于是接收端
  落后于自己的环，拿到 `Lagged`，错过的增量永久消失。接收端现在运行在独立
  任务上，只做排空，命令阻塞多久环都不会溢出。
- **客户端会响应溢出通知 (#2439)。** `TransportEvent::Resync` 原本是空分支，
  连引擎自己的上报都不起作用。现在它把投影标记为脏，从而重读快照并重放持久
  日志，而不是画出一个有洞的转录。

真实 PTY、同一提示、各跑三次：

| | 首字 | 增长 |
|---|---|---|
| 修复前 | 2.4s / 5.3s / 8.3s | 增量经常丢失 |
| 修复后 | 2.6s / 2.7s / 2.8s | 每次都平滑 |

## 转录布局

- **折行的代码块保留边框 (#2437)。** 围栏代码块画成 `  ╭ … │ … ╰`，而所有
  markdown 行都用两格悬挂换行、续行把前缀抹掉。这对正文正确，对代码块是错的：
  长行输出会丢掉 `│` 并把文字左移三列，读起来就是「整段堆成一列」。
- **首页输入框与 TypeScript 版对齐 (#2435)。** 读取 `tui.json` 的
  `prompt.max_width`（正整数上限、`"auto"`、或默认 75），banner 与输入框
  整体垂直居中，而不是偏下五分之二。

## TUI 测试套件

- **pty 套件不再被单个失败掩盖 (#2431)。** `cargo test` 在第一个失败的二进制
  就停止，而套件按名字顺序运行，于是 `input_latency` 一红，`interaction_*`
  和 `smoke`——全部会话测试——从未执行。两条腿现在都传 `--no-fail-fast`。
- **套件跟随输入框式首页 (#2431)。** `d5ca52247a` 把首页历史列表换成了输入框，
  却没有改任何 pty 测试。现在它们通过 `--session` 直接进入指定会话，不再与
  catalog 竞速。
- **问题面板不会活得比问题更久 (#2431)。** 超过截止时间后引擎把问题解析为
  过期并拒绝回答和拒绝两条路径，于是阻塞面板的两种结果都失败于
  「question is already resolved」。过期问题现在从投影中剔除，Escape 可在
  本地清除陈旧面板。

## 发布标识

- **发布的是产品 CLI (#2416)。** 两条打包路径此前都构建 `crates/miao-tui`
  并改名为 `miao`，导致发布出的 `miao` 拒绝 `models`、`auth`、`serve` 等
  文档声明的命令。现在两条路径都构建 `crates/miao-cli`，CI 也新增 `cli`
  job 编译该 crate。
