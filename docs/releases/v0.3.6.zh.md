# miao v0.3.6

v0.3.6 修复了 native 会话「看起来卡住」的两种成因，并让状态行如实说明它到底在等什么。

## 改进与修复

- **委派不再让父会话悬空。** 等待子代理时，读取子会话事件用的是锚定在 admission 序号上的固定 500 条窗口，因此事件超过 500 条的子会话永远不会暴露它的 `run.finished`。父会话等一个不可能到达的停止信号，drain 永不结束，会话就一直 busy —— 这是真卡死，不是慢回合。现在等待会推进游标并分页，直到子会话的结局可见。
- **native 会话里排队的提示词不再消失。** 队列在引擎侧，外壳每秒轮询输入列表看到的是空表，于是把刚渲染出来的排队回执删掉。新增 `pending_inputs` 命令读取尚未提升的 admission（含附件、投递方式和入队时间），客户端把它们投影成普通的待处理输入。
- **等待中的回合不再被读成「已停止」。** 状态行过去优先展示上一步已结算的活动（`ran 2 shell commands · 8m 46s`），而不是「模型还没回答」这一事实 —— 而这正是操作者读作工具挂住的形状。现在等待优先于过期的活动，并保留实时计时。
- **native 回合会报告 provider 阶段。** 状态携带 `preparing`、`requesting`、`retrying`，因此慢首 token 显示为在等模型，而不是本地在算。阶段只从 durable 事件派生，所以重连时重放出的状态流与实时投递的一致；仅存在于 live 通道的流式片段使用独立的序数带，因此先于其所属提交到达的增量不会与该提交自身的事件撞车。
- **侧栏把上下文读成压力与趋势。** Context 区域现在先给对窗口的压力条（`N% of <window>`，已用 80% 提示、90% 告警）和最近 40 回合的火花线，而不是需要心算的十行平铺文本。窗口未知时只显示绝对 token 数、不给百分比；被拒绝的回合永远不会被当成已结算的历史。

## 验证与边界

每项改动都通过 `guard` 与聚合的 `ci-gate` 套件，包括 macOS、Linux、Windows 上的 Rust 引擎测试，TypeScript 单元、类型检查与 e2e 套件，以及会话黑盒回放。

- 委派游标由一条 drain 测试覆盖，其子会话记录 668 条事件；同一测试在旧引擎上 120 秒内超时失败。
- 待处理输入由引擎 store 与 stdio 测试覆盖，另有针对附件与游标分页的投影测试。
- 阶段映射由 bridge 与 translator 测试覆盖。黑盒回放套件另外要求每个投递的事件携带唯一 source、且重连能复现相同的事件 id；正是这条要求否决了更早一版用实时 progress 管道发布 `streaming` 阶段的实现 —— 只存在于 progress 的事件不在 journal 里。
- 等待状态行由 TUI 渲染测试覆盖。

生产守护进程下的引擎回收、集群放置与长时间运行的 watcher 主机仍不在自动化证据范围内。
