# miao v0.3.63

[English](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.63.md)

v0.3.63 把压缩（compaction）变成一件可看、可停的事：状态条会说出正在进行的是哪一段压缩，而不是一律显示成等待模型；ESC 能中止正在跑的压缩，被中止的那次也不再把熔断计数推上去；`/compact` 可以手动触发；被中止或根本无法启动的压缩会明确报出。同时，provider 的 key 收进了模型选择器，被二次派发后未写 stop 就死掉的子会话会被收掉，永不推进 todo 列表的续跑循环也被加上边界。

## 看得见、也停得下的压缩（#2905、#2907、#2912、#2889、#2898）

- **状态条说出是哪一段压缩**：摘要调用在整个过程中不返回任何 token，所以过去整段压缩都显示为 `Waiting for model`；现在会显示正在进行第几段。
- **ESC 能中止压缩**：本轮 run 的取消令牌会传入压缩请求，每段开始前检查，摘要流也共用同一个令牌。被中止的压缩记录 `compaction.cancelled`，且不计入熔断——熔断正是过去在几次摘要超时之后拒绝下一次压缩的原因。
- **停止的压缩、以及无法开始的压缩都会报出**，不再把状态条留在 `working` 上什么都不来。
- **告警只在压缩边界触发一次**，不再在 60% 与 80% 各来一次（#2889）；单独的上下文压力提示已删除（#2898）。

## 顺手就能用的命令（#2911）

- **提示符里可用 `/compact` 与 `/init`**：引擎一直带着持久的 `request_compact`（在下一个稳定边界做一次检查点并重置熔断），但 TUI 从来不会发送它，导致摘要熔断的会话完全无法手动压缩补救。`/init` 会为项目写出 `AGENTS.md`。

## 模型选择器里管理 provider 的 key（#2906）

- **在选择模型的地方新增或替换该 provider 的 key**：已经在提供路由的 provider 不必再绕去配置文件加账号，多个账号之间也能区分。

## 委托（#2904、#2891、#2893、#2888、#2883、#2908）

- **等待提示只统计本会话自己的子会话**，不再把它能找到的所有 `subagent_start` 都算进来，因此不会再为已经委托出去的工作把会话冻住（#2904）。
- **侧问会分出主线（AGT-06）**：`task { explore: true }` 在最近的闭合边界复制本会话历史，且在主线索取之前不回灌任何输入（#2891）。
- **委托深度上限可调，但仍然是上限**（#2893）。
- **运行中的子会话行会带上存活时长**，工作中与卡死不再长得一样（#2888）；失败的后台子会话会通知派发它的会话（#2883）。
- **被二次派发、未写 stop 就死掉的子会话会被收掉**：恢复逻辑过去把 start 与 stop 分开读取，只要某 id 出现在任一侧就丢弃，于是一个历史上的 stop 会把子会话永久关不上（#2908）。

## 不再失控的循环（#2895、#2901）

- **永不推进 todo 列表的续跑循环被限制**（#2895），不再在模型回答「等待中」时反复注入同一条续跑提示。
- **每种优化都能用显式开关做消融（VAL-04）**，机制靠关掉它来度量，而不是靠论证（#2901）。

## 发布与 CI

- **release PR 可以携带全部 workspace manifest**（#2910）：版本号也会改到 `apps/desktop/package.json`，发布路径闸门现在放行它，于是版本提升能在一个 PR 里落地。
- 验收索引补充了 VAL-03 基线（#2897、#2894）、AGT-06（#2896）、侧栏作用域（#2899、#2900）以及 AGT-03/TOOL-01/CTX-05 的落地记录（#2890）。窄面板测试改为逐格读取渲染结果，因此在 Windows 上同样成立（#2902、#2892）。
