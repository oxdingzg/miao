# miao v0.3.63

[English](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.63.md)

v0.3.63 主要修一个「会话跑不动」的问题。原本的等待暂停只该表示「我自己还有后台任务没跑完」，但它把本会话**委派过的所有子会话**都算了进去，包括几小时前就已经结束的那些 —— 于是长时间编排的会话每次被唤醒只答一轮就自我暂停，任务列表永远推进不了。现在暂停只作用于本会话自己的后台工作，被读取的那些行也会被修复，而不是一直被当真。

## 停住的会话重新能跑（#2904、#2908）

- **暂停只看本会话自己的后台任务**：子会话结束会走自己的通知，不是父会话必须等待的边界。
- **子会话在跑不再冻结父会话**：只结束这一轮（drain），既不写暂停说明，也不再自我注入续跑提示 —— 不会在待办列表没变的情况下反复向 provider 要一轮。
- **被重派发后死掉的子会话由恢复逻辑关闭**：计数要求「最新一次 start 之后还有 stop」，而恢复逻辑只要该 id 历史上出现过任意一次 stop 就当作已关闭；于是「二次委派后被杀」的子会话会一直算作运行中。现在恢复逻辑按序号折叠两种事件，每个开放子会话只关闭一次。

## 压缩过程看得见（#2905、#2907、#2889、#2898）

- **状态条直接写「压缩」**，不再显示成模型等待。
- **中断一轮会同时停掉正在进行的那次压缩**，不让它在已取消的轮次上继续跑完。
- **只在压缩边界提醒一次**（不再是 60% 与 80% 各一次），阈值以下不再有压力提示。

## provider 与命令更顺手（#2906、#2911）

- **在模型选择器里管理 provider 的 key**，包括为已有 provider 追加第二个 key。
- **日常用的 slash 命令**默认已绑定。

## 委派过程更像「在工作」（#2891、#2893、#2888、#2883、#2895）

- **侧问题会从主线分叉**（AGT-06），而不是把历史再讲一遍。
- **委派深度上限可调**，并且仍然是上限（`MIAO_SUBAGENT_MAX_DEPTH`）。
- **运行中的子会话行带时长**，**失败的子会话留下凭据**给发起委派的会话。
- **不推进待办的续跑循环有上界**，反复改写列表也无法无限自问。

## 用于度量的机制开关（VAL-04、#2901）

- 每个优化机制都可以通过显式开关关掉，从而把「机制有效」的结论放在它缺席的对照下测量。

## 验证

- 发布提交的 CI 全绿：`engine`（四个分片）、`tui`、`cli`、`blackbox`、`unit`、`typecheck`。
- Windows 测试靶架：快捷键绑定与窄面板两条用例改为按渲染网格逐格读取，可以在 Windows 上通过（#2892、#2902）。

## 升级

`latest` 通道的 `miao` 会自动更新；否则重新执行 README 里的安装命令。被旧等待列表暂停的会话，下一条消息即可恢复：影子子会话会在启动时由恢复逻辑关闭。
