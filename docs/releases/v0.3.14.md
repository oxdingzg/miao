# miao v0.3.14

v0.3.14 fixes the startup failure that followed v0.3.13. v0.3.13 made the Rust TUI the front end `miao` starts, and every launch ended on `engine_closed: miao-engine output stream closed` before a single prompt could be typed. Two independent defects caused it, and both are fixed. Nothing needs to be reconfigured: upgrade and start `miao` as before.

## TUI

- **`miao` starts the engine again (#1566).** The launcher handed `miao-tui` the product database as the engine's `--db`. `miao-engine serve` refuses that file — it is a different schema, and it answers `Invalid("not a miao-engine database; use a separate path")` and exits before it reads a request, which the TUI can only report as a closed output stream. The launcher now derives the engine database the way the server and the migration CLI do: a Location's store is a pure function of its directory under the configured engine storage root (`engine.storage`, `MIAO_ENGINE_STORAGE`, or the default beside the product data), so the TUI and the server open the same file. An installation that explicitly opts out of native storage now gets a clear refusal instead of a dead child process.
- **The Session catalog loads (#1566).** The engine's command envelope is adjacently tagged, so a command declared without arguments takes no `params` key at all. The TUI sent `{"method":"sessions","params":{}}` for the catalog and every read came back `invalid_request: expected an id and a typed method/params request`. `sessions` and `model_catalog` now go out as `{"method":"sessions"}`, exactly as the TypeScript host sends them, so the home list, the model dialog, and the account dialog populate.

## Engine

- **Derived config sections are validated with their key paths (#1555),** so a malformed `agent`, `command`, or `skill` entry names the key that failed instead of the whole document.
- **A location whose config documents do not parse now fails explicitly (#1547),** rather than starting with a silently reduced configuration.
