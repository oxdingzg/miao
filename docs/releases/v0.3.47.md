# miao v0.3.47

v0.3.47 closes one of the long-standing input-surface gaps and one loop-guard
defect: a client can finally see whether the turn consuming its promotion is
still alive, and a Session that answered with a tool call no longer keeps its
todo loop alive forever.

## Input receipts name the consuming run

- **The receipt distinguishes executing from failed (#2699).** `input_status`
  already told a client whether an input was sent, admitted, pending promotion,
  or promoted, and an exact retry of the same durable identity answered
  `duplicate: true` without creating a second message. What it could not say
  was what happened after promotion: the receipt now surfaces `run.state` —
  `executing` while the turn that consumed the promotion still runs,
  `failed`/`completed`/`interrupted` once it settles — so a client polling
  receipts can tell a live turn from a dead one and stop re-sending on
  guesswork. A continuation's newer run supersedes the older picture, and the
  steer/queue delivery classes keep their own `pending_ahead` counters.

## The loop guard survives tool activity

- **An idle turn after a tool call still counts as no progress (#2700).** The
  no-progress guard resets its stall counter whenever the model dispatched a
  tool — but the flag was per-run, so one `bash` call retired the guard for
  the rest of the run: a Session whose todo list had stopped moving kept
  being continued as long as it sprinkled tool calls between text-only
  replies. The flag is now consumed per decision, so the guard keeps counting
  across idle turns and stops the loop with an explicit pause message.
