# miao v0.2.16

本版本重点提高后台任务续跑和多窗口原生会话的可靠性，补齐产品配置接线，并在安装时提供匹配的引擎和协议感知的自动发现。

## 后台任务续跑

完成报告按有界批次进入会话，每个 provider-turn 批次扣一次自动唤醒额度，不再按报告条数扣费；admission watermark、FIFO 顺序和排队定时 tick 的边界保持有效。

额度耗尽时，未读报告会继续保存，TUI 会显示明确的暂停原因。发送新消息即可补充额度，继续消费已保存的结果。

## 原生会话与产品接线

- 根据产品可用模型和活动账户生成原生路由。manifest 只包含凭据引用，不包含 token；刷新仍由产品 credential broker 负责。
- 原生会话接入产品 LSP、formatter 选项和沙箱 monitor 执行；显式 formatter 选项在生成 manifest 后仍然有效。
- 每个窗口拥有自己的 runtime，原生 Session 状态通过存储共享。Session claim、lease epoch 和跨进程写入预留协调修改；WAL 读取不获取这把写锁。状态更新、模型选择和恢复决策使用相同写入边界。
- 中断请求到达实际 owner；过期 run 恢复和 heartbeat 不会挤占仍然存活的 owner。
- 定时巡检不再递归获取 owners 注册表锁。恢复时更换已终止的客户端，普通 RPC 错误不会重启健康 owner。
- shutdown 不再给 unit 命令发送参数；stdout/stderr 有界排空后保留真正有用的退出诊断。
- 非交互 CLI 能显示原生回复，不伪造 assistant 元数据；快速退出的 PTY 结果仍能交给晚到的订阅者。

## 终端界面

崩溃界面显示最先发生的错误；dialog action bar 在选中项初始化后构造，修复初始化顺序故障。可搜索的 `/login` 命令用于从终端发起 relay 登录。

## 安装与升级

发布安装器会补全匹配的引擎，即使 miao 已经是目标版本。引擎归档会通过 SHA-256 manifest 和所需协议检查。Windows 还会检查引擎版本匹配、暂存后替换、保留回滚程序，并在显式引擎替换来源无效时保留已安装引擎。缺少兼容引擎的旧版本仍保留 TypeScript 回退。

原生写入和进程执行能力需要显式宿主策略（`MIAO_ENGINE_POLICY`）；自动发现不会额外授予能力。在 POSIX shell 中，`MIAO_ENGINE_BIN= miao` 可明确为该次命令关闭原生自动发现。

原生 schema 12 数据库不能由旧引擎读取。开发原生存储应与发布版存储隔离；回退时应使用与所选引擎兼容的存储，不要让旧引擎打开新数据库。
