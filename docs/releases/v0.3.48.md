# miao v0.3.48

v0.3.48 stops the todo loop from re-prompting itself several times a minute
while a Session is really only waiting: continuation now respects a wall-clock
floor, backs off while the todo list stays put, and stays silent while
background work is running. It also fixes the upgrade probe on Windows, which
failed on every write and left installed builds unable to update.

## The continuation loop learns to wait

- **Continuations are paced (#2703).** The todo loop used to admit the next
  continuation the moment a text-only reply landed, at whatever speed the
  model answered - a Session waiting on a long build emitted the same
  "continue the next todo" prompt every few seconds. Injections now respect
  a wall-clock floor (`continuation_min_interval_ms`, 30 seconds by default;
  set it to 0 to restore the old cadence). While the list stays unchanged
  across tool-backed turns the floor backs off exponentially - 30s, 1m, 2m,
  up to a 16-minute cap - and the moment the list moves the pace snaps back.
- **A Session with live background work stops re-prompting itself
  entirely (#2703).** Completion notifications wake the drain on their own,
  so injecting the continuation prompt into that wait bought nothing but
  noise; the loop now idles instead and picks up with the notification.
- **The no-progress guard keeps its teeth (#2699, #2700 lineage).** Two
  text-only continuations without tool activity and without a todo change
  still pause the loop with an explicit message; tool-backed polling slows
  down but never trips that guard, so long single-task sessions are safe.

## Windows can update again

- **The upgrade probe writes to the Windows null device (#2705).** The
  version check discarded the redirect body with `curl -o /dev/null`, but
  curl.exe on Windows resolves that path against the current drive — from
  `D:\` it writes `D:\dev\null` — and every write failed with `curl: (23)`.
  All four retries failed identically, so `miao upgrade` and the background
  update check never detected a version on Windows. The null device is now
  spelled `NUL` there; reproduced with System32 curl from PowerShell, and
  the release-redirect test passes against the real endpoint.
