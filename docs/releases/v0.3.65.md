# miao v0.3.65

[简体中文](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.65.zh.md)

v0.3.65 restores the darwin-x64 archive that 0.3.64 lost, makes a background
job's row lead with what it produced, and repairs the /accounts flow so storing
a second key for one provider routes it instead of failing the whole
configuration reload.

## Storing a second key routes again (#2931)

- **`/accounts` works for multiple keys.** Every stored account derives a route
  named `provider/model@account`; the id validator never learned about `@`, so
  the first reload after a second key was stored rejected the whole derived
  catalog (`invalid provider stream: invalid model route catalog entry`) and the
  new key routed nothing. The validator now accepts the account slot, pinned by
  unit tests.

## The jobs row leads with what the job produced (#2930)

- **Output first, command second.** A long command used to push a running job's
  output out of the visible row, so 45 printed markers stayed invisible while
  the data was right there.
- **The per-row detail preview is gone.** It answered from the job's `result`
  only, so the selected row — the one the operator is looking at — was
  overwritten with `running · no result yet` exactly while the job was talking.
  The list answer itself carries the live tail now.

## Packaging (#2929)

- **The darwin-x64 archive ships again** alongside the other platforms.

## Verification

- CI green on the release commit: `engine` (four shards), `tui`, `cli`,
  `blackbox`, `unit`, `typecheck`.
- Windows host: `cargo test --lib model_catalog` 4 passed / 0 failed (the new
  validator pins).
- Known and recorded, not fixed here: `tests/wakeup.rs` can time out under CI
  load (#2932) and `tests/web.rs` crashes with `STATUS_STACK_OVERFLOW` on
  Windows (#2926).

## Upgrading

`miao` on the `latest` channel updates itself; otherwise re-run the installer.
If a key stored through `/accounts` was showing "no route", it routes after
this upgrade — the next configuration reload derives it.
