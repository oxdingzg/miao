## [0.2.5] - 2026-10-11

miao 0.2.5 improves Session resilience and continues dependency-ready work while other tasks wait on background jobs.

### Dependency-ready task execution

- Todos support stable `id` and `depends_on` prerequisites, plus `waiting` and `blocked` states. A waiting task blocks its dependents, not independent work. If 4 waits and 5/6 depend on it, independent 7–9 remain runnable (#618).
- Explicitly authorized autonomous goals can continue ready tasks across idle boundaries within iteration, provider-turn, and no-progress limits. Waiting-only graphs become idle without polling. Paused, blocked, or done goals stop this autonomous continuation (#618).
- Reject duplicate IDs/edges, unknown prerequisites, cycles, and premature execution/completion before replacing durable task state. Preserve prerequisite identity across reload (#618).
- Terminal reports, the sidebar, and the scheduler share dependency readiness. Independent unfinished work is distinguishable from a globally waiting Session (#618).

### Provider and background recovery

- Bound unfinished tool arguments to 1 MiB and 120 seconds by default, including stalled streams. Adjust `MIAO_TOOL_INPUT_MAX_BYTES` or `MIAO_TOOL_INPUT_TIMEOUT_MS` for intentional large inputs. These limits apply to argument generation, not tool execution (#615).
- Correct invalid JSON arguments for unexecuted local calls at most twice over durable history. Retain completed operations; do not blindly replay provider-executed calls or unknown side effects. Keep intermediate errors visible while making CLI exit status reflect the final continuation (#614).
- Recover from retryable abnormal WebSocket closes, including 1006, and retain frames under slow consumers. Protocol and policy failures remain terminal (#590, #593).
- Preserve the process-global execution route through Location drains so a background completion durably notifies and wakes an idle Session. Retain background outcomes and pending todo work (#610, #617).

### Provider and client compatibility

- Preserve interleaved reasoning and opaque continuation state for Copilot; give ACP reasoning blocks stable identities distinct from answer text (#598, #613).
- Support the OpenAI `ultrafast` service tier and namespaced Session/parent identity headers (#604, #605).
- Recognize C++ module extensions, resume Sessions with their original executable, retain confirmed outcomes after client exit, and distinguish interruption from failed work (#606, #597, #609, #619).
- Verify XAI image-bearing tool followups on the native Responses and explicit Chat preparation paths (#622).

### Rust engine development

- Add strict Session blackbox recording/replay and native tool receipts that replace execution without repeating executor side effects (#589, #592).
- Persist and validate native task dependencies and deliver derived ready tasks to the provider (#623).
- Track newer Session resilience behavior as explicit cross-backend acceptance gates (#621). Native state/context support does not establish complete native autonomous continuation or product integration.

**The default Session runtime remains TypeScript.** Rust default switching still requires representative quality/efficiency evidence, native behavior parity, actual client delivery, singular ownership, and installation/rollback acceptance.

### Verification and upgrade

The merged changes pass their applicable CI checks. Combined CLI regressions and a remotely built macOS preview have been tested, including an actual model/HTTP Session that performs independent work before its background dependency finishes, then completes serial dependents after the durable notification without another human prompt.

The release pipeline requires successful CI for its exact release commit and builds macOS arm64/x64, Linux arm64/x64, and Windows x64 archives. Restart existing miao processes after upgrading to load the new runtime and tool definitions. Database migrations preserve legacy todos without dependency fields.
