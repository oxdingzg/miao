# miao v0.3.9

v0.3.9 restores what a native Session shows about its file edits: an `edit`, `write` or `apply_patch` call again renders the file content and the changed lines, and the diff is rendered from the event rather than re-sent to the model. Alongside it, a Session whose storage or directory is gone stops warning on every listing refresh, a transport failure keeps the reason the socket reported, and the engine gains its own reader for the product's config files. No existing Session changes owner in this release.

## What a native Session shows

- **A file mutation carries the diff it already knows.** The engine answered a write or edit with `{sha256, bytes, applied}` and nothing else, so the product had no patch to draw: an `edit` card fell back to a bare `Update(path)` row, a `write` card lost its body, and `apply_patch` lost its per-file hunks. Every mutation now reports the committed files under a display block on the completion event — path, action, unified patch and addition/deletion counts — and the product projects that into the same `FileDiff` shape its own TypeScript tools use, so the existing card renderer, summary line and diff highlighter render it unchanged.
- **The diff never reaches the model.** The model already wrote the text it asked for, so a patch inside the tool result would only pay for it twice. The store moves the display block into the `tool.completed` event and strips it from the result, the serialized result and the projected history. Because the block rides the durable event, reopening or replaying a Session renders the same diffs.
- **A rebased edit shows what replaced the drift.** When an edit rebases onto a file that changed underneath it, the diff covers the text that actually landed on disk, not only the span the model asked for.

## Native Session catalog

- **A Session absent from its storage is absent, not broken.** A placement can outlive the storage it names — a deleted temp checkout, or a release that wrote its own storage root. Reading the catalog for such a row answered `Query returned no rows`, and the product logged `native catalog facts unavailable` on every listing refresh (48 in the 14 minutes after v0.3.8). The store now answers "unknown Session", the catalog skips that row, and a storage file that does not exist reads as empty instead of spawning a reader that exits non-zero. A store that cannot be read at all still reports an error per Session, and a failed usage read still reports `usage_error`.
- **A Location whose directory is gone is skipped quietly.** `miao` removes worktrees it created, and temp checkouts under `/tmp` disappear on their own; listing such a group died in `realPath` and warned once per group per refresh — the operator's log held 7311 `skipping native Sessions whose Location could not be read` lines for seven dead directories. The group's directory is now probed first and a gone group is skipped at debug level, while a Location that exists but still fails to resolve keeps its warning. The search service answers an empty index for a gone directory instead of reporting an `Invalid path` initialization failure on every boot.

## Providers

- **A transport failure keeps its cause.** `provider transport failed` was a unit error, so a refused connection, a failed TLS verification, a provider that never sent headers and an exhausted retry window all read the same. The error now carries the reason — `provider transport failed: connect failed: Connection refused (os error 61)`, `timed out: …`, `decode failed: …` — and the request URL is deliberately not included, because a route's query string can hold a credential. Classification is unchanged: availability, fallback, input rejection and pre-output replay all match the same error.

## Engine groundwork

- **The engine reads the product's config files.** A first, self-contained step toward engine-side config ownership: the same file order (`miao.json`, `miao.jsonc`, `opencode.json`, `opencode.jsonc`), JSONC comments and trailing commas with a string-aware scanner, directory discovery in priority order, and object-deep / array-replace merging that matches the product's semantics. A malformed file names its path instead of degrading to an empty config. Nothing is wired to engine startup yet, so runtime behaviour is unchanged.

## Validation and limits

Every change passed `guard`, the aggregated `ci-gate` suite, and the Rust engine tests on macOS and Linux, including the TypeScript unit, typecheck and e2e suites.

- The display diff is covered end to end: a real `edit_file` driven through the runtime asserts that the completion event carries the committed patch, that the model-facing result and the projected history do not, and the bridge asserts the product `FileDiff` projection.
- Native `read`, `glob` and `grep` still report less than their TypeScript counterparts; those summaries were never produced by the native engine and are unchanged in this release.
- Config reading is not yet connected to engine startup; the product still materializes the config the engine reads.
- The Windows engine and runtime suites run against the release commit rather than on every pull request, so a Windows-only break surfaces at the release gate.
