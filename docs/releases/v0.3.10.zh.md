# miao v0.3.10

v0.3.10 是通往单内核路上的维护版本：超长 diff 预览不再能把 TUI 打崩；转录和输入行现在会明说这一轮是否还在跑；一个目录重新只持有一份 location service map——这也是近期 CI 反复失败的权限卡死问题的根因。

## 产品

- **长 diff 预览不再让会话崩溃。** 折叠的补丁预览按固定行数截断，但最后一个 hunk 头仍然宣称有更多行；diff 渲染器解析这段预览时从 render memo 里抛出 `Added line count did not match for hunk at line N`，把整个 TUI 带走。现在截断后的 hunk 头会改写为实际保留的行数，上下文高亮器也改为容错解析——补丁格式有问题只损失高亮，不再损失会话。
- **转录会显示哪一步还在跑。** 最后一个 assistant 步骤在整轮期间保留实时页脚：生成时是 `✳ Agent · model · working · 12s`，请求已发出但未回应时是 `◐ Agent · model · waiting for model · 12s`；结束后落定为 `✓ … completed 12:34 · 1m 2s` 或 `✗ … stopped · interrupted`。计时的归属是页脚本身，页脚卸载即停，空闲会话不再挂着定时器。
- **输入行在有回执时仍保留实时状态。** 一轮里有排队或 steer 的提示词时，状态行会同时显示回执（`Received · joins next turn`、`Queued · 2 pending · starts when idle`）和当前阶段，而不是只剩回执；正在工作的会话不会再看起来像冻住。
- **不可用的 `--model` 在 TUI 打开前就报错。** 本渠道无法提供的显式模型 id 现在直接以 `Model not found: provider/model` 退出，而不是弹三秒提示后悄悄用回退模型打开；`miao models` 默认只列出当前 location 能跑的模型。

## 引擎

- **所有会话都经引擎收件箱准入（S2）。** `SessionV2.prompt` 通过 `SessionAdmission` 准入一条持久的 `session_input` 记录；引擎托管的会话直接进引擎存储，产品侧把随之而来的 `input.admitted` 事件投影回来；`MIAO_INPUT_TS_ADMIT=1` 可回退到 S2 之前的写入路径。
- **一个目录只有一份 location service map。** S2 让同一目录存在两条准入路径，为其中一条构图的 provider 图可能生成第二份 `LocationServiceMap`；权限回复于是落进没人等待的那份，工具调用永远不恢复，ACP 会话一直挂到超时。现在 map 按图的形状缓存，并由同一份共享替换列表构建，两条路径落在同一份 map 上。
- **权限规则在引擎内求值（S6 step 1）。** 分层决策被抽成纯函数 `PermissionV2.decide` 并移植进引擎，配套由 TypeScript 实现生成、在 CI 中保持一致的 golden corpus（`tests/differential/permission_decide.json`），以及 `permission_evaluate` 查询：返回效果、生效规则集，以及派生授权必须引用的 authority 摘要。
- **产品配置在引擎内派生（S5 step 2）。** `serve`/`acp` 接受 `--config-dir`，从产品自己的配置文档与环境派生产品策略（workspace 模式、sandbox 开关）；显式的 `--policy` 仍然优先。
- **GLM 的 thinking 内容不再作为 Responses 内容发送。** Chat Completions 的推理块（包括 GLM 保留的 thinking）不是 Responses 的 reasoning item；它仍留在转录里，但不再被当作可见文本发送，也不再伪造加密状态。

## 构建

- **Windows 发布构建不再被占用中的探针镜像拖死。** 烟测探针退出后仍可能占用自己的镜像，导致删除临时目录失败——0.3.9 的 `windows-2025` job 正是死在这里，而烟测本身已经通过。

**完整变更**：与 [v0.3.9](https://github.com/oxdingzg/miao/compare/v0.3.9...v0.3.10) 对比。
