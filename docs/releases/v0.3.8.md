# miao v0.3.8

v0.3.8 is the release where a new Session is born on the engine and most of what the TypeScript runner already knew arrives with it: the provider families that used to need a loopback gateway speak their own wire, a rejected tool call says which field was wrong, a long Session keeps its newest messages, and an endpoint that is merely unreachable is reported as unavailable instead of as a malformed request. No existing Session changes owner in this release.

## Engine and native Session

- **A new Session lives on the engine by default.** Placement used to depend on an engine storage root being configured; the host now supplies `<data>/engines` by default, so a new Session is engine-owned unless an operator explicitly rolls back with `--engine ts`, which still sets an empty `MIAO_ENGINE_STORAGE` and never falls through to the default. A Session already owned by TypeScript keeps its own path.
- **The remaining TypeScript Sessions can move in one run.** `miao session migrate-all` plans first — a Session with no bound model or no readable product row is skipped and reported rather than aborting the batch — then drives each one through the existing resumable coordinator (frozen → prepared → switched → completed), and summarizes failures with a non-zero exit. Rerunning is safe: a completed import is a no-op and an interrupted one resumes from its persisted state.
- **A long Session keeps its tail.** Snapshot projection and provider history selection stopped at 1001 messages while the documented runaway guard permits 20,000, so a Session past that point lost its newest history, forks copied only the prefix, and the model could miss the latest prompt and tool results. Both now read one row past the actual guard, and an oversized history fails explicitly instead of quietly.
- **A snapshot truncated by an older engine is refused.** Engines released up to 0.3.7 project with `LIMIT 1001` while the cursor still claims to cover the whole Session. That snapshot is now rejected with a diagnostic instead of showing a tail that stops at the 1001st row.
- **A finished turn is announced only once idle is settled.** A headless native run could report success and exit while the engine was still working, and the engine later recorded the run as interrupted: the wait returned in the window between input promotion and the run row. Explicit waiters now confirm a settled idle before finishing.
- **Initial promotion and the run row commit together.** A snapshot taken between those two commits saw no pending input and no active run, so a short-lived CLI could close over still-running work.
- **The last allowed turn wraps up.** Spending the final provider turn used to be a hard stop mid-operation; that turn is now text-only with the tool surface withheld, so the transcript closes with what was done, what is left and what to do next.
- **A monitor settles with one readable notice.** A terminal monitor admitted the whole internal envelope as its prompt and then admitted a generic "read the stored result" notice pointing at `{"exit_code":0}`. It now settles once, with the lines the operator saw.
- **Catalog reads no longer start engines.** Listing historical native Sessions could open one long-lived engine per storage just to read a title. A bounded, read-only batch command serves catalog reads without migrations, runtime construction, leases, providers, LSP or MCP; explicitly selected older engines keep their existing path.
- **A Session with todos or a goal no longer bricks at its budget.** The engine injected durable progress as a note and refused the turn when history plus that note exceeded the request budget, and every retry re-sent the same oversized request. The note is optional context, so an input already near the budget is now sent without it and the turn runs.
- **Repetitive output is stopped mid-stream.** A model looping on a short prose or reasoning refrain used to run to the turn budget; the product's detector is now in the engine, with the same exclusions for code fences, tables, lists and non-prose text.

## Providers and transports

- **Five endpoint families gained a native wire.** Bedrock Mantle (Responses, Chat for the two safeguard models), Azure OpenAI Chat and Azure OpenAI Responses (`api-key` with an explicit `api-version`), Vertex Anthropic (the `streamRawPredict` shape: model in the URL, `anthropic_version` in the body) and Vertex Gemini (OAuth bearer) now dispatch from the same route catalog as everything else. Accounts whose only credential is Entra or ADC still use the loopback gateway, because the engine has no source for those tokens.
- **A routed transport failure is reported as unavailable.** The router wraps each route's error, and that wrapper fell through the runtime's availability check, so an unreachable endpoint surfaced as `invalid request: provider transport failed` and sent operators looking for a malformed prompt. It now reads `provider unavailable: …` and can fall back.
- **Provider availability and request rejection are different errors.** Transport failures, unreplayable responses and retryable HTTP 429/5xx render as `provider unavailable`; a genuine 4xx rejection stays `invalid request`.
- **Retry policy matches the product's runner.** The engine retries inside a 60-second window instead of a fixed count: 500 ms backing off at 1.7, capped at 5 seconds, jittered by ±20%, never shorter than a pause the provider named, with `Retry-After` honoured in millisecond, delta-seconds and date forms up to 15 minutes, and one self-heal.
- **A Chat stream that ends without a finish reason completes.** Some gateways close with `[DONE]` and never send one; the stream declared itself complete, so the missing reason now ends it naturally, preserving any tool call it carried, while an unsupported reason still names itself.
- **Idle deadlines stay armed through a stream.** The reader used to disable its event deadline after the first semantic event, so keep-alives could hold a turn busy forever; semantic events now re-arm a rolling deadline that pings never extend.
- **Web search keeps the operator's provider.** The product knob `MIAO_WEBSEARCH_PROVIDER` is mapped onto the engine's variable, with the engine's own setting authoritative when both are present.

## Tools and failures

- **A rejected tool call names the field and the value.** Every engine-side rejection rendered as `invalid tool input`, so a model could not tell a wrong field name from an out-of-range number and resent the identical call. The rejection now carries the reason.
- **The product decodes what models actually send.** Numbers written as strings, a timeout above the ceiling, and the aliases models use for edit and write fields are unambiguous, so they are read instead of rejected and re-sent.
- **Built-in tools keep their refusal reason.** `apply_patch` and `todowrite` answered every failure with one sentence, hiding the lines the matcher could not find and the validation or permission rule that blocked the change.
- **The shell result carries the engine's refusal.** A refused call and a signal death both projected as `[command not executed]`, and a failed call rendered its raw JSON as the message; the transcript now shows the refusal itself and `[killed by signal N]`.
- **Attachments reach the model the way the product shapes them.** A PDF the selected wire cannot carry inline is written under `.miao/attachments` and pointed at by path; attached directories and `@file#10-20` ranges are inlined as text (directories bounded at 200 entries); inlined text files become `<file name path>` blocks clipped at 100,000 characters. `miao run --file` no longer swallows the trailing prompt.

## Context

- **Pruning is a durable, readable fact.** Request-only tool-output pruning used to leave only transient progress, so after a reconnect nobody could see what was removed or what it saved. Each prune now commits a fenced fact with the affected payloads and the before/after/saved UTF-8 bytes, and the product replays it as a settlement record in the transcript.
- **Pruning never grows the request.** Near-budget output could get larger once markers and recall instructions were added; a replacement that would not save bytes now leaves the original in place, and markers count toward the remaining request size.
- **The app charts estimated input composition.** Each loaded checkpoint contributes a stacked estimate of system, user, assistant, tool and other input, excluding a response from its own input and resetting attribution at compaction, side by side with the persisted snapshots it is explicitly not a replacement for.

## Shell, app and CLI

- **The prompt is framed with rules.** Full-width horizontal rules replace the left accent bar and the fade strip, with the agent colour kept on both rules.
- **Auto-approve and the escape action are visible under the composer.** The session route had nowhere to show whether auto-approve was on, or that background work still ran after the turn; a standing hint row now carries both.
- **Native argv commands render as commands.** A `run_command` call projected its argument array without the string the transcript and command consumers read, so the command was hidden in the details.
- **`/clear` keeps the model.** A new Session used to carry only the footer's local selection, which a native Session does not have — its model is an operator-bound route — so the operator's default route silently took over. The current Session's route (and variant) is now carried into the new one.
- **A closed terminal is not a crash.** Writing to a stderr that a pipe had closed raised an uncaught exception and recorded a crash for an otherwise clean run; shutdown and CLI output now write best-effort.

## Build, CI and release

- **Release artifacts embed the engine built for them.** The release pipeline built engine sidecars but did not embed them, so an older updater could keep an unmarked engine and miss that release's Rust fixes. Each architecture's engine is now built, signed and embedded into its CLI before publishing.
- **The conformance script starts from the operator's database.** Each cell began with an empty product database, so a provider keyed by the operator's login never resolved and every cell failed before reaching the engine. Cells are now seeded from the release channel's database, falling back to the dev channel's.

## Validation and limits

Every change passed `guard` and the aggregated `ci-gate` suite, including the Rust engine tests on macOS and Linux, the TypeScript unit, typecheck and e2e suites, the session blackbox replay, and the conformance harness.

- The Windows engine and runtime suites run against the release commit rather than on every pull request, so a Windows-only break surfaces at the release gate.
- Entra and ADC-only credentials remain on the loopback gateway for Azure and Google; native routes cover the credential sources the engine can mint or read.
- Placement is now engine-owned for new Sessions, but the engine database is not yet the single authority: the product database still holds the projection, and moving existing Sessions is an explicit command.
