# miao v0.3.43

v0.3.43 makes OpenCode Go usable from the native engine.

## A gateway turn names its conversation

- **Routes derived from the product config send `x-opencode-session` (#2586).**
  The native engine builds its model routes from the `providers` section of the
  product config. Those derived routes carried the provider, endpoint,
  credential and limits, but no auth headers, while OpenCode's gateway routes a
  turn by conversation and rejects a request that does not name it. Every
  `opencode-go` turn therefore failed with `HTTP 400 MissingSessionID` even
  though a valid key was stored, and a model with no derived route silently fell
  back to the first route the config declared — usually an OpenCode Free entry,
  which answered `429 FreeUsageLimitError`. `opencode-go` routes now carry the
  Session-bound header, using the same `$session` placeholder the product's own
  routes send, so sibling Sessions still route and cache separately. The
  environment fallback for that provider also uses the gateway's documented
  `OPENCODE_API_KEY` instead of `OPENCODE_GO_API_KEY`.

## Every key gets its own route

- **A provider with two keys now serves both (#2564).** Native routes bound one
  credential per integration — the first unexpired one — so a provider holding a
  second key answered through the first alone: `ctrl+o` could not list the other
  account, and nothing in the picker said which key a model would spend. The
  route manifest now carries one route per live credential. The first account
  keeps the plain `provider/model` id a Session may already have pinned; the
  rest are `provider/model@<label>`, and every route names the account it spends.
  The picker labels each model with that account, so choosing a model also says
  which key it charges.
- **Storing a provider key no longer needs a miao restart (#2585).** The engine
  builds its routes at startup, so a key stored while it ran served nothing until
  miao restarted — and a second miao could keep answering from the routes it had
  built earlier. Storing a key now restarts just the engine: its spawn is the
  product shim, which re-prepares routes and credentials, and the TUI then
  reloads the model and provider catalogs, the Session list and the open Session.
  A key stored while a turn is running waits for that turn to finish instead of
  cancelling it.

## The phone works on its own

- **A phone-only mode beside the relay client (#2584).** The iOS app opens on two
  tabs. 本机 runs an assistant entirely on the phone — a provider configured
  on-device, an in-process agent loop with sandboxed file tools, streamed
  replies rendered as Markdown, multiple conversations, photo attachments,
  dictation, and optional MCP tools over HTTP. 电脑 keeps the existing relay
  client. Adding a provider is one picker and one key: the app knows 火山引擎,
  智谱, DeepSeek, OpenAI, Kimi, 百炼, 硅基流动 and OpenRouter.
- **Queueing is a per-message choice, not a mode (#2589, #2591).** The relay
  composer offered a sticky 排队 toggle, so every later prompt was queued
  silently and one answer appeared to belong to older questions. It now appears
  only while a turn runs, resets after each send, and confirms with
  「已排队：这一轮结束后发送」.
- **The TUI queues while a turn runs (#2590).** Every prompt used to be admitted
  as a steer, joining the running turn at the next boundary; a follow-up then
  read as part of the work in progress. Prompts now queue while a turn is live
  and steer only when the session is idle, matching Claude Code. Esc still takes
  back the newest queued input before interrupting.
