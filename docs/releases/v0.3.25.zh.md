# miao v0.3.25

v0.3.25 让"长会话"重新可续，并让原生引擎成为 TUI 的默认路径，而不再是一个需要显式开启的模式。此前一个会话一旦抵达模型的上下文窗口就无法继续；现在它会按**自己所使用模型**的窗口来压缩，而当请求仍被拒绝时，引擎会把请求裁到能装下再重试，而不是原样重发。

## 引擎与上下文

- **会话能从上下文溢出中恢复（#2058）。** 端点自己的拒绝被正确识别，而不是当作"坏输入"；窗口直接从这次拒绝里学到，被拒的那一步在同一次 drain 内重试。
- **自动压缩按会话自己的模型规划（#2068）。** 进程级的 `--context-limits` 只描述一个模型；跑其他模型的会话现在优先取路由声明的窗口，其次取拒绝中声明的窗口，而操作员显式设置的 `context_limits` 仍然最高优先。
- **被拒的请求会被裁剪（#2080）。** "端点刚刚拒绝了这份历史"本身就是请求放不下的证据，即使手里没有上一轮请求的 provider 计数；裁剪目标是**窗口减去 headroom**，而不是原始窗口——这正是"重试能装下"与"再被拒一次"的差别。
- **工具结果紧跟它的调用（#2080）。** 一条同时携带工具结果与图片的消息，原先会先把图片降级成 `user` 消息推出，于是在 `tool_calls` 与端点要求的结果之间插入了一个 `user` 轮次。现在工具结果先于该消息携带的其他内容出行。
- **权限项目的忙等从 2 秒放宽到 10 秒（#2055）。**

## 工具链

- **单一原生二进制、引擎进程内运行。** TUI 默认在自己的进程里跑引擎，CLI 作为单一原生二进制发布。
- **路由与权限来自产品配置。** 引擎路由清单从产品配置派生（`7a46bdf4`、`23213c67`），agent 的权限会带进引擎（`f47a58b1`），而被默认化的轮次会说明它用了哪个模型（`a49b81b9`）。
- **遵守配置的默认模型（`90303c18`）。**

## TUI

- **每个会话一个草稿（#2084）**，不再全进程共用一个草稿。
- **失败会指出下一步（#2198）**；窄布局也保持可读：遵守 `NO_COLOR`、leader 按 `leader_timeout` 过期、滚动速度与加速度跟随 `tui.json`。
- **新增视图：** 会话目标与待办分开展示（#2093）、最近各轮耗时（#2074）、后台任务及其预览与停止（#2089、#2091）、定时唤醒与 cron（#2099）、`/tag`（#2081），以及 `/recall` 恢复被归档的工具输出（#2070）。
- **若干修补：** 窗口从后台返回后重绘（#2085）、标签标题不再原地跳动（#2072）、被阻塞的 MCP 调用显示完整工具名（#2224）。

## CI

- **引擎分片不再因为 runner 磁盘写满而失败（#2062）。** 该套件有 181 个测试 target，带完整调试信息的一次构建在仅有约 20GB 空闲的 runner 上达到 70GB 的 `target/debug/deps`，于是最先耗尽磁盘的分片以 rustc I/O 错误失败——看起来像"合并把 main 弄坏了"。现在测试构建使用 `line-tables-only` 调试信息、回收托管镜像里用不到的 toolchain，并且磁盘守卫覆盖两条腿（它此前的条件用一个永远不会匹配的 matrix 值，从未生效过）。

## 核心

- **用量按角色归属（#2029）**，补齐了"一个会话在每个角色上花了多少"的拆分。
