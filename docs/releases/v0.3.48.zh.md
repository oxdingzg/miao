# miao v0.3.48

v0.3.48 让 todo 循环不再在「其实只是在等」的时候每几分钟自我续跑一次：续跑
现在有了时间底线，列表不动就指数退避，后台任务运行期间干脆保持安静。它还修好
了 Windows 上的升级探测——此前每次写入都失败，装好的 miao 无法自我更新。

## 续跑循环学会了等待

- **续跑有了节奏（#2703）。** 此前只要模型回了一句纯文本、且还有可运行的
  todo，循环就立刻注入下一条续跑指令，速度完全跟随模型——等一个长构建的
  会话每隔几秒就重复一遍「继续下一个 todo」。现在注入尊重时间底线
  （`continuation_min_interval_ms`，默认 30 秒；设 0 可恢复旧节奏）。列表在
  工具回合之间保持不变时，底线按指数退避——30 秒、1 分钟、2 分钟，封顶
  16 分钟；列表一有变化，节奏立即回到底线。
- **有存活后台任务的会话完全停止自我续跑（#2703）。** 完成通知本就会唤醒
  drain，往等待里注入续跑提示除了噪音什么也买不到；循环现在直接转入空闲，
  等通知到来再继续。
- **无进展护栏的牙齿没有松（承 #2699、#2700）。** 两轮纯文本续跑、没有
  工具活动、列表也没变，循环仍会带着明确说明暂停；工具轮询只会变慢、
  不会触发该护栏，长单任务会话是安全的。

## Windows 恢复了自我更新

- **升级探测写入 Windows 空设备（#2705）。** 版本检查用 `curl -o /dev/null`
  丢弃重定向响应体，但 Windows 的 curl.exe 会把该路径解析到当前盘符——在
  `D:\` 下就写成 `D:\dev\null`——每次写入都报 `curl: (23)`，四次重试同样
  失败，`miao upgrade` 和后台更新检查在 Windows 上永远拿不到版本号。现在在
  Windows 上把空设备拼成 `NUL`；已用 PowerShell 里的 System32 curl 复现，
  发布重定向测试对着真实端点通过。
