## [0.2.7] - 2026-10-13

miao 0.2.7 完成 CLI 中重复 V1 运行时的退役，扩展原生 Session 的读取和事件重放能力，并收紧工具执行和上下文压缩边界。默认 Session 运行时仍然是 TypeScript；本次发布没有把全部 Session 切换到 Rust 引擎。

### CLI 统一为一套运行时服务图

- 所有命令改由 core-only 的 `CliRuntime` 执行。项目和检出目录通过 core 项目注册解析，不再构建 V1 InstanceStore/InstanceRef 引导图（#777、#783）。
- 删除已退役的 V1 provider、插件认证、config、agent、LSP、MCP、snapshot、skill、worktree、formatter、command、permission、question、image 服务及其 instance/workspace 管线。活跃的 TUI 配置、插件安装和 marketplace 加载能力继续保留（#758、#767、#783）。
- 公共 SDK 视图模型直接从 schema 模块导入；此次退役没有改变生成的客户端内容（#771、#783）。
- 回调运行时与事件转发使用 core 服务和显式的事件 Location 元数据，取消 V1 隐式实例上下文（#783）。

### CLI 兼容性变更

- `agent create` 使用 core `Catalog` 与 `AISDK` 解析模型，继续支持 LLM 生成 agent；`agent list` 输出 core agent 的标识与权限（#763）。
- provider 登录改用 core integration 方法。退役旧的 `providers login <url>` well-known 流以及未注册 provider 的 “Other” 路径；已注册的 API key/OAuth 方法使用 `providers login [provider] --method <label>`（#744）。
- Snapshot 调试采用内容寻址树：`debug snapshot capture`、`files <from> <to>`、`diff <from> <to>`。LSP workspace-symbol 查询采用 `debug lsp symbols <file> <query>`，通过文件选择对应语言服务器（#733、#772）。
- 旧配置解码、凭据采纳和 archive 兼容仍然保留。本次发布不重置数据库，也不删除已有 Session 历史（#783）。

### 原生 Session 读取与重放

- 原生 Session 元数据、消息与历史从引擎日志读取；历史分页保留完整的持久序列组（#760、#779）。
- 原生 execution status 与 todos 从引擎读取；TypeScript 分页所有者在应用游标和数量限制前排除原生 catalog 投影，避免所有权混淆（#784、#789）。
- 原生与 TypeScript Session 共同进入锚定列表分页，原生 catalog placement 提供分页身份和存储位置（#751、#761、#762、#766、#775）。
- 原生事件通过 SSE 提供，游标路由可重放持久事件（#768、#778）；真实 HTTP/SSE 验收测试覆盖了日志读取链路（#786）。
- 已组合 native transport 且操作者显式配置 `MIAO_ENGINE_STORAGE` 时，新 Session 可在首个 prompt 前完成原生初始化；没有 storage opt-in 时，创建仍由 TypeScript 负责（#774）。
- 原生运行仍受引擎配置控制，其余修改/审批路由属于独立的后续工作；本版本不宣称原生功能已经完全对齐，也不将原生执行设为默认。

### 执行与上下文处理

- Eager 工具执行受界限约束，settlement 通过并发许可收敛（#764）。
- 原生压缩触发器使用计数后的 usage anchor；超大工具输出从发往 provider 的请求中裁剪；显式 compact 会重置压缩熔断器（#740、#742、#755）。
- 增强压缩验收覆盖与 Windows 引擎测试 fixture 的确定性（#757、#759、#765）。

### 凭据基础设施

- 源码新增独立 credential daemon 与引擎 daemon-source 集成，包含 device-login 所有权和每个数据库仅一个 daemon 的约束（#776、#780）。
- 这是后续集成的基础设施，并不意味着全部 CLI 登录或 TypeScript 凭据刷新已委托给 daemon；独立 handoff 工作落地前，默认 CLI 凭据路径保持现状。

### 验证与升级

- 最终 V1 运行时删除通过 miao/desktop 类型检查、剩余 miao 全量测试（1106 通过、49 跳过、0 失败）、配置/archive/事件定向测试、生成客户端零差异检查，以及交互式源码 TUI 冒烟（#783）。
- 发布要求精确 main 提交的 CI 成功，并通过五个发布平台的构建。
- 使用通常的 `miao` 自动更新通道或仓库安装脚本升级。默认 Session 运行时仍是 TypeScript。
