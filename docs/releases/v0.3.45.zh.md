# miao v0.3.45

v0.3.45 修掉了让 Session 变成"只能读"的三个缺陷——Chat Completions 端点读不了
历史、Windows 上写入被拒、裸 `permission` 动作被忽略——并收进了 v0.3.44 以来
引擎、TUI 与 CLI 的改动。

## 三个"只能读、不能写"的修复

- **交错的工具回答之后，历史可以继续了（#2648）。** 引擎把每个工具结果单独
  存成一条 message，而结果里可能带图片或文本。逐条降级时，一条用户消息被插
  在 assistant 的 `tool_calls` 和后续工具回答之间，Chat Completions 端点会
  直接拒绝——并且每次重试都重放同一份被拒历史，Session 在一轮中途卡死。降级
  现在会把文本和图片扣住，在最后一个回答之后合并成一条用户消息；受影响的
  Session 无需任何迁移即可继续。
- **Windows 写入不再被误判越界（#2649）。** 读检查早已把 `\\?\` verbatim
  前缀归一，但三处写检查仍拿 verbatim 规范路径与纯拼写的工作区根比较，
  `Path::starts_with` 永远不匹配，所有 `write_file`、`edit_file`、
  `apply_patch` 都被 "path is outside the configured workspace" 拒绝。现在
  所有包含性比较都用读路径早已采用的纯拼写。
- **裸 `permission` 动作生效了（#2650）。** 产品会把 `miao.jsonc` 里的
  `permission: "allow"` 归一化成通配规则，引擎迁移却悄悄丢弃字符串，所有
  工具停在默认决策——本想放行写入与进程的配置跑成了只读。引擎现在会推导出
  与产品相同的通配规则，同一份配置在两侧语义一致。

## v0.3.44 以来的其他改动

- **引擎**：按任务核算费用、墙钟与人工介入（VAL-02，#2645）；供应商重试会
  标明等待类别与暂停来源（#2647）。
- **TUI**：配额重试提示处可直接切换账号与模型（#2651）。
- **CLI**：升级探测像下载一样重试（#2646）。
- **文档**：记录 RUN-01 输入回执验收运行（#2652）。

## 升级方式

`miao upgrade`，或用 `install` 脚本重装。Windows 二进制仍未签名，发布说明里
会记录该状态。
