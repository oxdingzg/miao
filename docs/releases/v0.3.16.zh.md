# miao v0.3.16

v0.3.16 让 Rust TUI 在以前会被拒绝的机器上启动，并让失败的一次 provider turn 说明真实原因，而不是声称做过根本没做的重试。现在还能解释每个配置值从哪来，原生 Session 也能切换到一个已存在的工作区。升级后照常启动 `miao` 即可，这里没有任何需要改配置的项。

## TUI

- **凭据存在产品数据库里的机器，Rust TUI 现在能启动（#1588）。** TUI 自己拉起 `miao-engine`，而它能转发的环境只是一张固定的 flag 表，里面没有产品路由、也没有凭据来源，于是这类机器在启动时就以 `API key or explicit credential source is required` 退出。现在启动器把 `MIAO_ENGINE_BIN` 指向一个 shim，由它重新进入同一个可执行文件，准备好 TypeScript 宿主本来会准备的那套 per-Location 计划——路由与凭据、MCP、配置来源、环境上下文、hooks、LSP、formatter——并在引擎的整个生命周期里保住这些清单和本地 AI-SDK 网关，同时在 TUI 与真正的引擎子进程之间转发帧。
- **空闲的 TUI 每分钟重绘一次，不再是每秒十次（#1581）。** 随时间变化的只有时钟类标签，所以它们改为每分钟刷新并跳过错过的间隔；输入、引擎与窗口尺寸事件仍然立刻重绘。
- **预览安装会保证 TUI、CLI、引擎来自同一次构建（#1577）。** `install-local.sh --tui-binary` 把它们配对，改启动器之前先校验版本，遇到冲突的保留二进制直接拒绝；显式设置的 `MIAO_TUI_BIN` / `MIAO_ENGINE_BIN` 依旧优先。

## 引擎

- **失败的 turn 会在窗口内重试，并说明失败原因（#1591）。** 以前重试窗口在 turn 开始时就 arm 了，于是一个慢的首次尝试就把窗口花光；turn 级 replay 随即返回 `the turn's retry window was spent before another request`，**一个请求都没发出去**，而失败行还会补上 `kept failing after retries`——哪怕一次重试都没发生。现在窗口改为首次失败时才 arm，最后一次失败会被保留并写进消息的 `(last attempt: …)`，transport 原因记到 `provider.request.result`，replay 记为 `provider.retry` 并带 `scope: "turn"`。自己失败掉的 turn 现在读作 `the model endpoint failed: …`。端点真的连续失败满整个窗口仍会结束这个 turn——但至少它会告诉你失败在什么上。
- **Chat Completions 回复按 TypeScript 协议解析（#1576）。** Rust 版在四处比参照实现更严格，可能让一个答案本来已经可读的 turn 失败，例如要求网关可能省略或重编号的 choice `index`。
- **原生 Session 可以切换到已存在的工作区（#1573），并且切换会真正收尾（#1568、#1569）。** 切换走外部目录的权限边界，并在当前这轮工作结束之后调度，历史、消息 ID、工具、用量与选中的上下文都会带过去。冻结只在激活与落位都校验之后释放，走默认路由的 Session 也不会再导出空的模型绑定。
- **JSONC 按 UTF-8 解码（#1587）。** 扫描器以前把每个字节当成一个字符追加，静默损坏中文键值、带重音的路径和 emoji——连纯 JSON 文档也受影响。

## 配置

- **每个生效的配置值都能被解释（#1589）。** `miao debug config --sources` 会报出胜出的文档、被它覆盖的值，以及每个文档的作用域——global、project、本地 `.miao`、环境变量覆盖——用的是产品其余部分读取的同一份有序合并结果，并对每个叶子值做脱敏。
- **被忽略的键会带着修法报出来（#1592）。** 加载依旧宽容，但每份文档现在多了一道严格探针，拒绝时给出文件、键路径和被忽略的值，并区分未知键、缺失键与形状不对的值。因为 typo 通常就是这个 location 在别处已经定义的键，建议取自已加载文档在同一层级定义的键。
- **两个读取者对优先级给出同一个答案（#1601）。** 同一份有序来源计划现在有一个共享的 golden 用例，要求 TypeScript 读取者与引擎对每个叶子值给出相同的结果。它抓到两个缺陷：引擎的合并会丢掉后续文档都没提到的键，而 `miao debug config --sources` 会把已被后续对象替换掉的标量仍列为生效值。
