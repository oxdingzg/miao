# miao v0.3.64

[简体中文](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.64.zh.md)

v0.3.64 is about telling the truth about what is running: a background job now
reports what it is saying while it runs, the jobs dialog shows a job's output
instead of its result envelope, and compaction explains what it is doing. It
also turns the engine sandbox off by default, which is a behaviour change worth
reading before upgrading.

## A job says what it is doing while it runs (#2925, #2923)

- **A running job's output is kept in memory** and filled into the jobs answer,
  so a row can answer "what is it saying" before the job's result exists.
  `read_pipe` read each stream to EOF before returning, so the progress channel
  only ever carried one blob at the end; it now reads in chunks and reports each
  one, keeping the old 32769-byte cap and the `output_limit` stop.
- **The jobs dialog previews output, not the result envelope.** It used to
  serialize the whole `result` object into the row, which read
  `completed · {"enforcement_required":false,…}` where the operator wanted the
  output. It now shows the newest output lines, falls back to `error` when a
  failed job produced nothing, and clips to the row's budget.

## The engine sandbox is off by default (#2927)

- **Behaviour change.** A run is no longer sandboxed unless asked: the engine
  spawns commands without the workspace-write sandbox by default, and
  `/sandbox` in the TUI toggles it for the Session. Read this before upgrading
  if you relied on the sandbox being on.

## Frozen permission sources block again on Windows (#2915, #2916, #2917)

- **A frozen workspace is spelled the way a Location is spelled.** The handoff
  row stored the Windows `\\?\C:\...` form while `engine_location.root` stored
  the plain one, so the freeze trigger's string equality never held and a frozen
  source blocked nothing. Measured on a Windows host: `cargo test --lib
  permission` went from 5 passed / 1 failed to 90 passed / 0 failed.
- **The release gate no longer skips that test**, and `specs/ci-windows.md`
  records that the row was a product defect rather than a hosted-runner
  limitation.
- **The permission classifier sees protected paths whatever the separator.**
  `protectedPath` split on `path.sep`, so a POSIX-style resource on Windows
  (`/project/.git/config`) hid `.git` and the classifier answered `safe`.

## Compaction is planned by size and says what it is doing (#2920, #2921, #2912)

- **A compaction pass is planned by size**, not by message count.
- **A rejected pass keeps its reason**, and folding is opt-in.
- **The status strip reports a compaction pass that stopped, and one that cannot
  start**, instead of leaving the phase unreadable.

## Verification

- CI green on the release commit: `engine` (four shards), `tui`, `cli`,
  `blackbox`, `unit`, `typecheck`.
- Windows host: `cargo test --lib permission` 90 passed / 0 failed;
  `miao-tui` 656 passed / 0 failed.
- Known and recorded, not fixed here: `tests/web.rs` crashes with
  `STATUS_STACK_OVERFLOW` on Windows in one approval-related case (#2926), and
  the Windows unit (TS) leg still fails on modules no shipped artifact consumes
  (#2873).

## Upgrading

`miao` on the `latest` channel updates itself; otherwise re-run the installer.
