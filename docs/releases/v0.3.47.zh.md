# miao v0.3.47

v0.3.47 关闭了一个长期存在的输入面缺口和一个循环护栏缺陷：客户端终于能看到
消费其晋升的回合并是否仍然存活，而用工具调用回答的会话不再让自己的 todo
循环永远存续。

## 回执开始写明消费它的回合

- **回执区分 executing 与 failed（#2699）。** `input_status` 此前已经能告诉
  客户端一个输入处于 sent、admitted、待晋升还是 promoted，同一 durable
  身份的精确重试也会以 `duplicate: true` 应答而不产生第二条消息。但晋升之后
  发生了什么它说不上来：回执现在带出 `run.state`——消费晋升的回合仍在运行时
  是 `executing`，落定后是 `failed`/`completed`/`interrupted`——轮询回执的
  客户端因此能分清活回合与死回合，不必再靠猜测决定是否重发。后续续跑产生的
  更新回合会覆盖旧画面，steer/queue 两种投递类别继续维护各自的 `pending_ahead`
  计数。

## 循环护栏在工具活动面前不再失守

- **工具调用之后的空闲回合仍计入无进展（#2700）。** 无进展护栏在模型派发了
  工具时会重置自己的停滞计数——但该标志是按 run 记的，一次 `bash` 调用就
  把护栏豁免到 run 结束：只要在纯文本回复之间穿插工具调用，todo 列表早已
  停止移动的会话就会被一直续跑下去。现在标志在每次决策后被消费，护栏跨
  空闲回合持续计数，并带着明确的暂停说明停止循环。
