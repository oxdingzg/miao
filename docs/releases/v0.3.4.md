# miao v0.3.4

[简体中文](https://github.com/oxdingzg/miao/blob/v0.3.4/docs/releases/v0.3.4.zh.md)

This release makes long sessions reliable end to end. Native engines reclaim themselves when their client disappears, give a stalled control call a named deadline instead of a generic transport error, and stop replaying a journal they have already caught up with. The TUI keeps a reader's place in history instead of pulling them to the tail, stops growing the transcript with prompt delivery state, lets a prompt still waiting to be delivered be taken back and edited, and closes a turn with one summary line naming its span, its completion time and any background work still running. A soft per-prompt token budget now ends a runaway drain with a summary rather than an open bill. Process commands also honor the operator's sandbox choice for the first time.

## Improvements and fixes

- Process commands honor the operator sandbox switch. The native engine applies the configured sandbox policy to the commands it runs instead of a fixed behavior, so an operator can turn confinement on or off per deployment.
- A stdio engine whose client died without a clean exit now reclaims itself from client input alone. Internal events and progress notices no longer extend the idle deadline, live background work still postpones it, and a terminated or interrupted engine unwinds through shutdown so its kill-on-drop children (LSP servers, MCP servers, workers) are reaped rather than orphaned. After shutdown the engine exits directly instead of risking a block on the stdin fallback reader.
- Closing an interactive native client no longer leaves requests hanging. Outstanding RPCs are rejected, a graceful shutdown is requested, and a child that does not exit is reaped, so a descendant holding the pipe cannot keep the engine alive after its host exits. Control RPCs get a 60-second deadline that names the stalled operation and points at the durable-receipt guidance; model execution stays asynchronous and is not subject to that deadline. The CLI's second, legacy signal handler is gone, so SIGTERM and SIGHUP run the window-owned shutdown path and reach native client cleanup before the process exits.
- A caught-up native event subscriber returns an empty page immediately instead of re-decoding and translating the complete journal on every poll. New events and reconnects still rebuild the required prefix and keep their identities; a 2,500-event regression forbids any idle journal read.
- Repeating an identical tool call is refused with a corrective error result instead of failing the run. The native loop guard now signs the model's raw input alone, matches the TypeScript threshold, reports once per exhausted signature, and lets the model change approach; batched reads settle before the guard and legitimate polling bypasses it.
- Assistant identity is attributed to the serving agent. The engine journals the agent manifest's name with the provider identity, and the host renders the product model through the priced catalog, so session headers show the real agent and model instead of a null agent or an Unknown placeholder.
- Session titles resolve the model that actually served the session. A stale or empty product row can no longer send title requests to an exhausted provider while the conversation runs fine on another model, and exhausted title candidates are logged.
- The task tool registers its named subagents for every admission. A plain task call naming a subagent no longer fails as unregistered, an unchanged catalog does not append duplicate registration events per prompt, and engine task input is projected into the product vocabulary so subtask rows carry the same title shape as native product tasks.
- A soft per-prompt token budget bounds a looping drain. `agent.budget` counts billed input, output, reasoning and cache across the provider turns of one admitted prompt; at 80% the model is told to wrap up, at 100% it gets one tool-free final turn, and the drain ends with a durable pause notice that records why it stopped. Promoting new user input re-arms the budget, so every prompt gets its own allowance.
- Google account quota errors now say they come from the Antigravity model service rather than the Gemini App's usage limits, and model discovery keeps the backend reason and reset delay instead of discarding them. Rate limits and capacity errors keep their evidence without exposing provider descriptions or adding retries.
- Native model and variant selections are remembered after a successful selection, including variant cycling, so restarting the TUI restores the model you picked rather than the previously saved one. Rejected selections leave saved preferences untouched.
- The TUI waits for prompt admission without a client timeout, so slow admission under load no longer surfaces as a transport error on the client.
- Reading back through history no longer loses new output. Leaving the tail remembers the last message seen and counts what arrives after it behind a `↓ N new messages` pill; clicking it, pressing the last-message key, or scrolling back near the bottom re-pins the tail and clears the count. The pill is an overlay, so it never reflows the transcript.
- Prompt delivery state moved to the footer. SENDING, RETRYING and QUEUED no longer render inside the user row, so a prompt waiting for admission stops growing the transcript and rewriting a message that was already sent; the history holds only durable messages.
- Repetitive tool rows collapse. Consecutive completed reads fold into one `Read N files` row whose paths expand on click, while pending and failed reads stay individual and prose or another tool breaks the run. An edit diff longer than the inline budget now previews its first 20 lines and counts the rest, in both `edit` and `apply_patch`, instead of hiding the hunk behind a click.
- A prompt still waiting for delivery can be taken back and edited. esc removes the newest waiting prompt instead of interrupting the running turn, and only an empty queue interrupts; the up arrow recalls that prompt into the composer, restoring its text after the server confirms the cancel. A prompt that already crossed the promotion boundary is history and is never restored, and a prompt cancelled by another client stops rendering as pending. The esc hint reads `remove prompt` while the queue is non-empty.
- A settled turn ends with one summary line: `● Worked for 1m 12s · done 11:42 AM`. It spans the whole turn from the prompt that opened it rather than one step, reads `Stopped after …` when the turn was interrupted, leaves a failed tail to its existing error block, and appends `· N subagents still running` while delegated child sessions are still executing.
- The terminal title carries the session subject alone. The hard-coded `miao | ` prefix is gone, empty or control-only titles still fall back to `miao`, and the 40-grapheme cap no longer spends seven characters on chrome.

## Validation and limits

The Rust engine suite passed on a macOS arm build host with zero failures across unit, integration and terminal coverage, with `cargo clippy --all-targets -- -D warnings` and `cargo fmt --check` clean; the cron capacity test now schedules distinct inputs so it exercises the shared budget it claims to test. TypeScript typecheck passed, and the engine bridge, assistant-identity, translator, session-runner, journal and native client lifecycle suites passed, the last including unresponsive-subprocess tests with a real prebuilt engine. The idle-reclaim behavior is covered by a real stdio engine test that starts a binary, waits through the idle window without a client shutdown, and asserts a clean exit; a real TUI run followed by SIGTERM reaps its native child. TUI interaction tests cover the new-message pill, the footer receipt line, read-run folding, diff previews, the terminal title, the waiting-prompt target shared by esc and the up arrow, and the settled turn summary including its last-turn-only, interrupted, failed-tail and background-subagent cases.

The per-prompt token budget is enforced by the TypeScript runner. The native engine's agent manifest is strict about unknown fields, so `budget` is not forwarded to it yet and native drains keep the session-level USD budget as their only cap; engine-side enforcement is a follow-up. Live engine recycling under a production daemon, clustered placement and long-running watcher hosts remain outside the automated evidence.
