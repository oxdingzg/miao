# miao v0.3.65

[English](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.65.md)

v0.3.65 找回了 0.3.64 丢掉的 darwin-x64 产物，让后台任务的行**以它产出的内容开头**，并修复了 `/accounts` 给同一 provider 存第二个 key 时整份配置重载失败的缺陷。

## 同一 provider 存第二个 key 后重新可以路由（#2931）

- **`/accounts` 支持多 key。** 每个已存账户都会派生一条 `provider/model@account` 路由；id 校验器一直不认识 `@`，于是给一个 provider 存第二个 key 后，第一次重载就会拒绝整份派生清单（`invalid provider stream: invalid model route catalog entry`），新 key 路由不到任何东西。现在校验器接受账户槽位，并以单元测试固定。

## jobs 行以任务产出开头（#2930）

- **输出在前、命令在后。** 长命令会把运行中任务的输出挤出可见行宽——45 个 marker 明明都打印了，界面上却看不见；现在数据与顺序都对齐。
- **移除按行预览。** 它只读 `result`，所以被选中的行——恰是操作者盯着的那行——会在任务正在说话时被覆盖成 `running · no result yet`。列表答案本身已携带实时尾巴。

## 打包（#2929）

- **darwin-x64 压缩包重新随其它平台一起发布**。

## 验证

- 发布提交的 CI 全绿：`engine`（四分片）、`tui`、`cli`、`blackbox`、`unit`、`typecheck`。
- Windows 主机：`cargo test --lib model_catalog` 4 passed / 0 failed（新增校验器固定）。
- 已知且已记录、**本版未修**：`tests/wakeup.rs` 在 CI 负载下可能超时（#2932）；`tests/web.rs` 在 Windows 上有一条 `STATUS_STACK_OVERFLOW`（#2926）。

## 升级

`latest` 通道的 `miao` 会自动更新；否则重新执行安装命令。之前通过 `/accounts` 存的 key 若显示「no route」，升级后即可路由——下一次配置重载就会派生出来。
