# miao v0.3.60

[English](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.60.md)

v0.3.60 完成了 Rust 化的最后一步删除：TypeScript 产品栈——TS provider 循环、TS
server、TS CLI 入口和整个 `packages/miao` 实现——已从工作区消失。产品就是一个
带唯一执行权威的 Rust 二进制，而这一主张的门槛证据已全部在档。

## TypeScript 产品栈退役（#2840、#2841，RUS-02）

- **`packages/miao`、`packages/server`、`packages/sdk` 与空壳 `packages/cli`
  已删除。** 桌面与 web 客户端保留各自的运行时路径：渲染进程直接连接引擎的
  回环 rpc 平面，已提交的 API 类型保留为共享词汇表。
- **TS provider 循环（`session/runner/` 与本地 drain）连同其最后两条生产边
  一并删除。** location-services 装配把 `SessionExecution` 绑定到 no-op 执行
  器——schedule 的 fire 路径仍有一个永远不会认领 Session 的实现，调用方替换
  依旧优先。
- **静态导入清单从 312 收缩到 184 条边界**，runner 为 0/0：工作区里不再有任何
  TypeScript 文件引用 provider 循环。
- **引擎自身的测试套件覆盖了原 TS harness 的职责**——ACP 客户端矩阵、HTTP 双
  wire 适配器、审批生命周期、placement 迁移/拒绝套件全部跑在引擎 crate 上。

## Headless JSON 重新报出每步成本（#2822）

`miao run --format json` 用 `step_finish` 事件结算每个 provider 步骤，事件里带
该步骤的成本与 token 计数——这是 TypeScript headless runner 确立的事件形状。
Rust 产品此前丢失了该事件，headless 消费者会对真实计费的运行静默读到零步骤。
未定价的步骤保持 `cost: null`，消费方如实报告"未知"而不是假零。

## 一个 Session 只允许一个运行中执行，由数据库强制（#2827）

`engine_active_run`——`engine_run(session_id)` 上针对 running 行的唯一部分索引
——此前没有任何测试覆盖它。两个新测试钉死了同 Session 的拒绝/接受周期，以及它
不应误伤的跨 Session 并发，连同租约生命周期与 placement 迁移/拒绝套件。

## 侧栏用量区阅读体验整理（#2818）

用量区只有一个头（Last 24h 条带），不再是两个叠放横幅；被列宽截断的行悬停即
显全文；跨多 provider 的一天会按 provider 分组、模型行缩进短横线展示。

## 门槛证据全部在档（#2823、#2826–#2839）

REL-04 门槛以空阻断失败清单关闭，每个门槛都有记录：唯一执行权威（组合根引用
+ 存储层强制测试）、控制面清单与具名拒绝、刷新的真实客户端语义矩阵（35 个套
件全绿）、隔离副本迁移/故障注入 drill、上一版产物的成对校验清单，以及固定任
务基准（glm-5.3-flash 上 10/10 格）。观察窗口经所有者决定提前关闭；
darwin-x64 原生验证继续延期，直到出现真实的 Intel 用户反馈。
