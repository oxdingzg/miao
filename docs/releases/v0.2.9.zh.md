## [0.2.9] - 2026-10-15

miao 0.2.9 是引擎版本：原生引擎补齐了基线套件所度量的编辑、读取、上下文与委派行为，产品侧改为用引擎自己的用量证据结算步骤，macOS 产物完成签名与公证。

### 新增

- **engine**：编辑改为可恢复而非直接失败。陈旧编辑会按"模型最后读到的文件"换基，快照有锚点，并注入漂移以实测该路径；`edit_file` 在精确匹配形式之外也接受简洁的 `anchor` 与 `new_text`（#804、#805、#823）。
- **engine**：大文件可按窗口读取（`offset`、`limit`），超大读取会自我解释而非隐晦失败，冻结套件新增大文件、多行与类型修复载体（#811、#818、#815）。
- **engine**：读取时预热语言服务器并在编辑后报告诊断；配置 `--verify-command` 后，run 必须通过它才能收尾——失败转为分类续跑，持续失败则分类收尾（#808、#822）。
- **engine**：上下文管理对其删除的内容负责。被省略的工具输出可由标记中的句柄找回；选择改为预算感知、先省略最旧；压缩摘要保留 durable state 与有界输入；且该门禁终于能从 CLI 开启（#826、#846、#839、#851）。
- **engine**：同一回合的声明式读取以 4 为界并发派发、按序结算，成员由声明而非名字决定，且每次调用都会报告自己的运行窗口（#844、#834、#841）。
- **engine**：委派可以按引用读取父会话的归档输出并记录结果；用途角色绑定在绑定模型失败时向主模型升级一次（#843、#847、#845）。
- **engine**：用量证据携带每回合 TTFT 与缓存血缘；ACP authenticate/resume/close 如实遵循协议；前缀缓存策略显式化（#842、#852、#827）。
- **release**：macOS 产物完成签名与公证；引擎二进制经发布通道分发（#840、#854）。
- **miao**：产品步骤以引擎日志的用量证据结算；引擎配置可映射 fallback 模型与角色绑定（#850、#848）。
- **remote-control**：默认 Hub 的浏览器配对入口随版本发布，并支持自定义 Hub（#833、#825）。

### 修复

- **engine**：空的 provider 完成不再静默结束 run 而是被分类；循环分类计数进入证据；摘要调用加上上限，静默的 provider 不再挂住回合（#813、#814、#855）。
- **eval**：对比 runner 现在会转发它声明的全部消融旗标并驱动引擎的上下文限制——被测的那一臂才是真正运行的那一臂（#830、#851）。
- **llm**：流式工具调用在流停止时定稿，而不是等到 finish 帧（#836）。

### 已知问题

- 自动压缩在基线载体上确实会触发，但每次摘要请求对该 sweep provider 都会停滞：一次实测中出现 11 次尝试、11 次失败、5 次被 breaker 跳过。上面的上限让这类回合能存活（每次尝试约 20s）；请求形状本身仍待修复（#855）。

### 验证与升级

- 引擎与评测工作在仓库携带的冻结套件上度量（编辑类载体、大文件与多行载体、长会话载体、读批量载体），并由引擎、评测与 blackbox 套件钉住；上述每个 PR 在三平台均通过。
- 通过常规 `miao` 自动更新通道升级，或使用仓库安装脚本。
