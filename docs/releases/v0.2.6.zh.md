## [0.2.6] - 2026-10-13

miao 0.2.6 让上下文压缩过程可见、可控，并落地了 Rust engine 的首批生产切片：持久化 admission、推理与工具片段的流式输出，以及带显式配置的自动压缩。

### 压缩过程可见

- Session drain 在摘要进行中报告 `compacting` 阶段，长时间压缩不再看起来像卡住的回合（#709、#715）。
- App 在压缩进行中就渲染流式摘要，而不必等到边界（#732）。
- 按分段发布压缩进度（#701），检查点之后的第一个 provider 回合获得显式的恢复预算（#724）。
- 小型模型改为在其 provider 内按价格选择，而不是按名称（#699）。

### 原生引擎：由配置激活的自动压缩

- 上下文管理在引擎侧落地为六道显式门：以归一化 usage 为锚的触发（显式 headroom 与窗口比例取更晚者，#717）、provider 自身计数端点并在被拒时回退估算且绝不失败回合（#718）、热前缀摘要规划与分段兜底（#722）、工具输出裁剪并保护最近输出（#726）、连续被拒后的熔断（#727），以及在事务性的 `pre_compact`/`post_compact` 之间发送进度事件（#730）。
- 执行器经 run-owned checkpoint 契约提交：要求运行活跃、provider 回合已闭合、无未结算工具（#711、#730）。
- 运行循环在已闭合边界执行检查；serve 命令接受 `--context-limits <json>`（camelCase：`window`、`ratio`、`headroom`、`perPass`），TS 派生层通过 `EngineOptions.contextLimits` / `MIAO_CONTEXT_LIMITS` 传递（#734、#735、#739）。未配置时自动压缩保持关闭。
- 运行时回归证明：配置限制后，真实运行会在回合内完成压缩并以摘要替换选择（#735）。

### 原生引擎：流式与持久性

- 归一化 delta 词汇覆盖 Anthropic、Responses、Chat、Gemini 的推理片段、工具输入片段与流式工具调用起点；一帧可携带多个片段时逐片段发布通知（#719、#721）。
- 会话桥把这些片段翻译为 `session.next.reasoning.delta`、`session.next.tool.input.started`、`session.next.tool.input.delta`，部件 id 锚定到持久化的 step 起点；App 与 TUI 在没有 `step.started` 时为原生助手建立占位（#714、#725）。
- 运行结束时丢弃未提交的流式草稿，已提交的部分保留（#702）。
- 原生 owner 使用服务作用域的注册表：跨请求作用域存活，关闭时释放数据库租约（#710）。
- 原生 prompt admission 由 `MIAO_ENGINE_BIN` 组合启用；未启用时原生所属会话仍被明确拒绝（#716）。

### 内部

- MCP、debug、models、snapshot、LSP 等面迁移到 core 服务（#728、#731、#733、#736），provider 凭据经 core 读取并移除（#737），app 层删除废弃的 V1 存储与后台服务（#712），并解耦最后一批非 harness 的 `AppRuntime` 消费者（#723）。
- 高亮解析器注册到活动客户端，修复 shell 高亮的解析器初始化顺序问题（#705）。
- CI 只扫描一次 push 发送的提交以查密钥（#706），并接受 enrollment fixture 的哑密钥（#707）。

### 验证与升级

- 每个改动均通过 PR 合入，且 exact-head 必需检查全绿，包括单元、类型检查与原生黑盒套件（identity、connection、owners、reads、receipts）。
- Rust engine 相关改动在 Linux、macOS（arm64）与 Windows 上以完整 `cargo test` 与 `cargo clippy -D warnings` 验证，并包含对本地 peer 的真实 provider 流测试。
- 升级沿用原有通道：`miao` 会从 `oxdingzg/miao` 的 release 自动更新；本地检出可用 `./script/install-local.sh` 预览。

### 状态

- 默认运行时仍为 TypeScript。Rust engine 的自动压缩通过 `MIAO_CONTEXT_LIMITS` 选择性开启；下一步是原生 Session 的读取路由（sync、messages、事件流），随后完成七任务实时客户端验收与实测 roadmap 复查，之后才考虑默认切换。
