# miao v0.3.11

v0.3.11 是维护版本，其中一项性能修复本身就值得升级：长会话的 snapshot 不再为每条消息扫描一遍事件日志。本版同时合入 ratatui TUI 的前两个 Phase 3 切片，并堵上引擎侧几处会让进行中的回合中断或卡住的问题。

## 性能

- **会话 snapshot 只读一次身份日志（#1524）。** 一个 1,124 条消息、7,227 个事件的会话，投影要 1.7–1.9 秒——因为每条消息都单独扫一遍事件去找 assistant identity；现在一次预载全部身份。同一投影降到 170–175 毫秒，TUI 每次重新水合都不再付这份平方级开销。

## 引擎

- **慢速 stdio 读取是背压，不是故障（#1523）。** 向暂停读取的客户端写大帧会阻塞写入端，过去被当成传输已死，进而结束引擎持有的所有会话。现在写入端等待管道排空；只有管道关闭或显式 shutdown 才结束输出流。
- **格式错误的工具调用不再结束回合（#1519），被拒的调用会说明还缺什么（#1521）。** 非法工具参数会给模型一次纠正机会而不是拆掉会话；拒绝信息会点名缺失的参数。
- **委派的子会话可达、有界、且不会递归（#1514、#1515、#1517）。** 子会话可以被打开查看，不能再委派，并继承此前被宿主漏掉的边界限制。
- **大附件经 stdio 完整送达（#1512）。** 超出单帧舒适大小的附件不再被截断。

## TUI

- **Phase 3 的 T1 与 T2 合入（#1503、#1520）。** ratatui 外壳与引擎 stdio 传输位于 `crates/miao-tui`；转录等切片随后跟进。
- **发送 prompt 不再重读转录（#1525）。** 准入后并行刷新状态与待处理收件箱，不碰转录，一次发送以两个小读取收尾而不是整篇重新水合；模型或 agent 的选择只在实际变化时才发送。
- **会话在第一次回答后就有标题（#1518），状态行会点名当前回合在等哪个工具（#1516）。** composer 提示也并到同一行（#1513）。

## 平台

- 本版没有安装器或打包变更。

**完整变更**：与 [v0.3.10](https://github.com/oxdingzg/miao/compare/v0.3.10...v0.3.11) 对比。
