## [0.2.7] - 2026-10-13

miao 0.2.7 completes the removal of the duplicate V1 runtime from the CLI, expands native Session reads and event replay, and tightens execution and compaction boundaries. The default Session runtime remains TypeScript; these changes do not switch all Sessions to the Rust engine.

### One runtime graph for the CLI

- Commands now run on the core-only `CliRuntime`. Project and checkout resolution uses core project registration instead of the V1 InstanceStore/InstanceRef bootstrap (#777, #783).
- The retired V1 provider, plugin-auth, config, agent, LSP, MCP, snapshot, skill, worktree, formatter, command, permission, question and image services, plus their instance/workspace plumbing, are removed. Active TUI configuration, plugin installation and marketplace loading remain (#758, #767, #783).
- The public SDK view models are imported from schema modules directly. Generated clients remain unchanged by the retirement (#771, #783).
- Callback runtimes and event forwarding use core runtime services and explicit event Location metadata instead of ambient V1 instance state (#783).

### CLI compatibility changes

- `agent create` resolves its model through core `Catalog` and `AISDK` while keeping LLM-backed generation; `agent list` reports the core agent identity and permissions (#763).
- Provider login uses core integration methods. The legacy `providers login <url>` well-known flow and the unregistered “Other” provider path are retired. Use `providers login [provider] --method <label>` for the registered key or OAuth methods (#744).
- Snapshot debugging uses content-addressed trees: `debug snapshot capture`, `files <from> <to>` and `diff <from> <to>`. LSP workspace-symbol lookup uses `debug lsp symbols <file> <query>` to select the owning server (#733, #772).
- Legacy configuration decoders, credential adoption and archive compatibility remain. This release does not reset the database or remove stored Session history (#783).

### Native Session reads and replay

- Native Session metadata, execution-derived messages and history are read from the engine journal. History paging preserves durable sequence groups (#760, #779).
- Native execution status and todos are read from the engine, and native catalog projections are excluded from the TypeScript paging owner before cursors and limits are applied (#784, #789).
- Native and TypeScript sessions participate in anchored listing pages; native catalog placement supplies the paging identity and storage location (#751, #761, #762, #766, #775).
- Native events are served through SSE, and a cursor-based route exposes durable event replay (#768, #778). A real HTTP/SSE acceptance test covers the journal read path (#786).
- New Sessions can be initialized on the engine before their first prompt when a native transport is composed and the operator explicitly supplies `MIAO_ENGINE_STORAGE`; without this storage opt-in, creation stays TypeScript-owned (#774).
- Native operation remains gated by engine configuration, and the remaining mutation/approval routes are still separate work. This release does not advertise full native parity or make native execution the default.

### Execution and context handling

- Eager tool work is bounded and settles through a concurrency permit (#764).
- The native compaction trigger uses counted usage anchors, oversized tool output is elided from outgoing requests, and an explicit compact resets the compaction breaker (#740, #742, #755).
- Compaction acceptance coverage and Windows engine-fixture determinism are strengthened (#757, #759, #765).

### Credential groundwork

- The source tree gains a standalone credential daemon and an engine daemon-source integration, including device-login ownership and one-daemon-per-database enforcement (#776, #780).
- These are integration groundwork, not a claim that every CLI login or TypeScript credential refresh already delegates to the daemon. The default CLI credential path is unchanged until the separate handoff work lands.

### Validation and upgrade

- The final V1-runtime deletion passed miao and desktop typechecking, the remaining miao suite (1,106 passed, 49 skipped, zero failures), preserved configuration/archive/event tests, generated-client checks with no diff, and an interactive source TUI smoke test (#783).
- Release publication requires successful CI for its exact main commit and successful builds for the five release platforms.
- Upgrade through the usual `miao` auto-update channel, or use the repository installer. This release keeps the TypeScript Session runtime as the default.
