# miao v0.3.71

[English](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.71.md)

v0.3.71 让压缩不再为自己的摘要付费，并允许操作员给自动压缩一个常驻保留目标；另有两个小修：剪贴板图片不再撞名，桌面窗口可以真正跑起一段对话而不只是旁观。

## 检查点携带的摘要不再计入下一次阈值 (#3017)

检查点会把被摘要的历史替换成一条 `<history-summary>` 消息，而自动触发把这条消息也算进了下一次阈值。于是每一轮压缩都在为自己的产出付费：会话刚压缩完，下一段一开头就已经逼近触发点；摘要越长，重新压缩得越早，而历史其实并没有长那么多。

压缩用的 `context_limits` JSON 因此新增两个可选键（默认值都等于原有行为）：

- `prefixScope` 取 `total`（默认，按 provider 计到的整个请求算）或 `bodyAfterPrefix`：折扣掉携带的摘要，让阈值只衡量「检查点之后的增长」。
- `retention` 给自动压缩一个常驻保留目标，语义等同于手动 `/compact <focus>`；请求自带的 focus 仍然优先，而且该目标现在也能进入 prefix 摘要这条保真度更高的路径。

`history_summary_text()` 成为携带文本的唯一构造点，折扣算法与历史选择不可能对「携带了什么」产生分歧。

## 复制的图片不再重名 (#3015)

同一纳秒内落盘的两张剪贴板图片会得到相同文件名。后缀现在混入进程内单调递增的复制计数器，连续粘贴不会再互相覆盖；纳秒基数仍然区分不同的轮次。

## 桌面窗口可以跑对话了 (#3014)

此前 Tauri 窗口只能观看会话，不能发起。`engine-reader` 增加了对话所需的两个写操作——`initialize`（空闲会话，`protocol: 2`）与 `admit`（持久 prompt，投递方式默认 steer）——除此之外仍保持只读。`SessionSurface` 增加了 **New** 按钮与回车发送的输入框，转写由实时订阅驱动增长，不再轮询。

已对着 `miao serve` 端到端验证：`initialize` → `admit` → `input.promoted` → `run.started` → 真实 provider 调用 → `message.committed` → `run.finished`；`tsgo -b` 与 `vite build` 通过，bundle 重新签名并在 macOS arm64 上启动。属于 #3012 的一部分。

## 升级

`miao upgrade`（或安装脚本）即可升级到 v0.3.71。本次发布不改变任何配置语义：现有 `context_limits` 保持原有行为，两个新键均为可选。
