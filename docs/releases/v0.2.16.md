# miao v0.2.16

This release improves background continuation and multi-window native sessions, connects more product settings to the engine, and installs matching engine sidecars with protocol-aware discovery.

## Background continuation

Completed background reports enter the conversation in bounded batches, charging one automatic wake unit per provider-turn batch rather than per report. Admission watermarks, FIFO order and queued-tick boundaries are preserved.

When the automatic continuation allowance is exhausted, unread reports remain saved and the TUI displays an explicit pause reason. Send a new message to recharge the allowance and resume those outcomes.

## Native sessions and product integration

- Native model routes derive from the product's available models and active accounts. Generated manifests carry credential references, not tokens; refresh remains with the product credential broker.
- Product LSP, formatter options and sandboxed monitor execution are connected to native sessions. Explicit formatter options survive manifest generation.
- Each window owns its runtime while native Session state is shared through storage. Session claims, lease epochs and a cross-process write reservation coordinate mutations; WAL readers do not acquire the write reservation. State updates, model selection and recovery decisions use the same write boundary.
- Interrupts reach the owning process. Stale-run recovery and heartbeats do not displace a live owner.
- Timer supervision no longer recursively acquires the owner registry lock. Recovery replaces terminal clients while ordinary RPC errors preserve healthy owners.
- Shutdown sends unit commands without parameters, and bounded stdout/stderr drains retain the useful exit diagnostic.
- Native replies render in the non-interactive CLI without invented assistant metadata. Fast PTY exits remain available to late subscribers.
- Boundary regressions cover replay of an already-completed tool call, legitimate identical calls in later user turns, and recovery after tool invocation fails. Durable dispatch-attempt tokens remain a roadmap follow-up.

## Terminal UI

The crash screen names the first error. Dialog action bars are built after their selected option, fixing initialization-order failures. The searchable `/login` command starts relay sign-in from the terminal.

## iOS companion

The sidebar toggle is available before a host is connected. Open conversations use the same navigation control, and account entries have distinct accessibility identifiers.

## Installation and upgrade

The release installers reconcile the engine sidecar even when miao itself is already current. Engine archives are checked against their SHA-256 manifests and required protocol. Windows validates the engine's matching version, stages replacement, retains a rollback executable, and preserves the installed engine when an explicit engine replacement is invalid. Older releases without a compatible engine retain the TypeScript fallback.

Native write/process capabilities require an explicit host policy (`MIAO_ENGINE_POLICY`); automatic discovery grants no additional capabilities. In POSIX shells, `MIAO_ENGINE_BIN= miao` explicitly disables native discovery for that command.

Native schema 12 databases are not readable by older engines. Keep development native storage separate from release storage. When rolling back, use storage compatible with the selected engine rather than opening a newer database with an older engine.
