# miao v0.3.29

v0.3.29 makes the progress channel lossless, so a streamed answer can no longer
arrive as a fragment with its head missing. It also restores the composer box
and the per-state tool marks the TypeScript-mirroring round had replaced with
something that read worse.

## Streamed answers can no longer lose their head

v0.3.28 stopped one specific way of starving the progress receiver. It left the
channel itself able to drop: `broadcast` keeps a fixed ring per reader and
discards the oldest entry when that ring fills, reporting `Lagged` only after
the values are gone. Raising the ring from 256 to 32768 moved the cliff without
removing it, because the number of deltas in a turn is set by the provider's
chunking, not by anything the engine bounds.

- **Progress is a lossless fan-out (#2473).** Every subscriber now gets its own
  unbounded queue, so a send never drops a frame and never blocks the provider
  turn. A dropped delta has no durable cursor to replay from — the committed
  journal holds the turn, not text that is still arriving — which is why the
  old channel could only paint a tail. An abandoned reader is pruned on the
  next send, and every in-process reader does nothing but drain.

## The composer shows what the run is doing, in colour

- **The composer is a named box again (#2472).** Its title carries the run's
  state — the phase, the elapsed time, the queue depth, and any notice — with
  the braille spinner beside it and the warning tone once a wait passes half a
  minute. That puts "is it working, queued, or waiting on me?" inside the box
  the operator is typing into instead of in a band above it. The band above the
  box is now spacing only.
- **A freshly admitted run shows a clock (#2472).** The status used to fall
  back to a plain, colourless `Working` whenever the run was active but no
  `provider.*` frame had arrived yet. That window spans the whole request
  setup, and with no clock and no tone it reads exactly like a wedged turn. The
  App now anchors a clock on the run the first time it sees it active.
- **Tool rows carry a glyph per state (#2472).** A finished call is `✓`, a
  failed one `✗`, a running one `·`. The single `●` they replaced distinguished
  those only by colour, so a monochrome theme drew three different outcomes as
  the same mark.

## The Windows sandbox suite no longer races itself

- **The Windows sandbox tests run serialized (#2475).** Twelve tests in
  `windows-sandbox.rs` ran concurrently, and each one probes AppContainer and
  then starts its own `miao-run` plus a child process that has to produce a
  file within ten seconds. They contend for the same container profile, so the
  two that started last missed their deadline — `overlapping_invocations…` with
  "first lease never became ready" and `child_tree_killed…` with "child
  heartbeat never appeared" — while the other ten passed in the same run. Those
  waits ask whether a sandboxed child can start at all, not how fast it does,
  so serializing is the honest fix.

## Upgrading

    miao upgrade

`miao upgrade` reports the installed version and how to move to the latest
release. Installations that report `feed none configured` were installed by
hand and upgrade by re-running the install script:

    curl -fsSL https://raw.githubusercontent.com/oxdingzg/miao/main/install | bash
