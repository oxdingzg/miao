# miao v0.3.46

v0.3.46 fixes the reason a freshly stored provider key still asked for a full
restart, repairs two defects on the workspace surface, and stops a terminal
read that fell behind from walking the backlog instead of the current screen.

## A stored key serves its models again

- **The routes manifest is written whatever its size (#2662).** The launcher
  derives the model routes, writes them to a temp manifest, and points
  `MIAO_ENGINE_MODEL_ROUTES_CONFIG` at it — but only when the encoded list
  stayed under 64 KiB. Past that ceiling the file was skipped, so the launch
  kept the routes it had derived and a key stored afterwards had nothing to
  append to: the provider and its models only appeared after restarting miao,
  which re-derived the list from scratch. The ceiling belongs to values passed
  through the environment, not to a file the engine reads. `miao serve`'s
  derivation carried the same gate and silently fell back to configuration-only
  routes; both paths now share one writer.

## Configured permissions

- **Permission rules in the config are honoured again (#2665).** The policy was
  derived from the raw merge of the config documents, but the rule reader only
  understands the `permissions` array that the V1→V2 migration produces. Every
  `permission` or `tools` entry an operator wrote was therefore ignored, and
  writes and process kept the default ask no matter what the config allowed.
  Migration now runs before the rules are read, so the engine evaluates what the
  configuration actually says.

## The workspace surface

- **`<leader>w` lists your workspaces again (#2663).** The command sent an
  empty `params` object to a unit-tagged request, and the engine rejected it as
  `unsupported request workspaces`.
- **Worktree removal keeps the Sessions that work there alive (#2663).** Only
  the checkout's ledger was read, so a tree that Sessions moved into before it
  became a worktree could be removed while its own ledger still anchored them,
  stranding their working directory. Both ledgers are read, and both are
  repointed on a forced removal.

## Terminal reads

- **A reader that fell behind resumes at the newest window (#2661).** A read
  whose cursor the 1 MiB ring had overrun replayed from the oldest retained
  byte, so a slow reader walked the backlog one 32 KiB window per call while the
  program kept painting and never reached the current screen. Full-screen
  repaints also lay cells out with escapes and no newline, so the row budget
  folded nothing and the pane laid out one enormous line; both are fixed.
