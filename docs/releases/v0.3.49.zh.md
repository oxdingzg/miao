# miao v0.3.49

v0.3.49 让模型诚实地看见自己的上下文：曾经让会话中途停下的「回合预算」
说法被移除了；当对话接近自动压缩阈值时，模型现在能看到真实的占用数字和
接下来会发生什么，而不是等历史被压缩替换时才发现。

## 「预算」说法退场（#2711）

- **回合额度提示改为陈述测量结果，不再描述可花的额度。** 引擎的每回合
  余量提示此前读起来像一笔模型可以花销并辩护的预算（「预算即将/已用尽」），
  模型便以宣布回合结束来回应。现在的收尾与耗尽提示只陈述每轮重测的事实、
  要求以纯文本收尾，不再邀请模型自行看守额度。
- **更少的误停。** 仍有持久工作的会话保住其 provider 回合余量；只有真实
  测量会暂停它，操作者随时可以用下一条提示继续。

## 模型看得见上下文在变满（#2712）

- **上下文压力阶梯随会话自身的请求下发。** 占窗口 60% 时，模型得知占用
  并被要求保持读取收敛；80% 时给出具体动作（完成当前操作、把持久状态写进
  文件）；88% 时告知下一回合边界将运行压缩、请干净收尾当前步骤。数字以
  窗口为先、每轮重测、并作废此前提醒里的数字；压缩检查点把阶梯清零重新
  武装。委派的子代理看不到它——锚点属于父会话的窗口。
- **请求定界与压缩规划使用同一个有效窗口。** 现在两者的解析顺序一致：
  操作者覆盖、会话模型的路由声明容量、端点拒绝时自报的窗口。此前仅通过
  路由得知窗口的会话会武装压缩，而请求本身却始终不设界。

## 忙时输入并入当前轮（#2715）

- **工具运行期间提交的提示改为 steer，不再排队等空闲。** 此前轮次运行时输入
  的提示会以 `queue` 准入，语义是「等会话即将空闲再处理」。goal 循环可以把一次
  drain 连续跑成几十个续跑轮次，提示就排在操作者早已翻篇的工作后面，只能靠手动
  中断轮次脱身。现在改为 steer：进行中的工具调用一结束，引擎就在同一轮内把它交给
  模型——这正是文档早已写明的边界，也是 Claude Code 的做法。命令类提交仍然等到
  本轮结束。

## 代码着色回到产品自己的配色（#2716）

- **围栏代码块与 diff 正文改用产品一直在用的语法色板。** 此前 token 颜色取自界面
  色：关键字用 `secondary`、字符串用 `success`、数字用 `warning`，在默认主题下就是
  蓝紫关键字、发闷的绿字符串和琥珀色数字。现在改读产品的 `--syntax-*`：注释与关键字
  用弱化文字色、字符串青、数字青系；浅色背景自动切换深色孪生值，`NO_COLOR` 下完全
  不上色。
