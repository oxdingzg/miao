# miao v0.3.29

v0.3.29 让进度通道变成无损的，流式回答不会再以缺少开头的残片形式出现。同时恢复了
输入框的方框样式和每种工具状态的符号——这两处被「对齐 TS」那一轮换成了更难读的样子。

## 流式回答不会再丢失开头

v0.3.28 堵住了一种让进度接收端饿死的具体路径，但通道本身仍然会丢数据：`broadcast`
给每个接收者维护一个定长环，环满时丢弃最旧的一条，而 `Lagged` 只有在值已经消失之后
才会报出来。把环从 256 调到 32768 只是把悬崖推远，并没有消除它——一个回合里有多少个
增量取决于 provider 的分片方式，不是引擎能设上限的东西。

- **进度改成无损扇出 (#2473)。** 每个订阅者现在都有自己的无界队列，发送既不会丢帧，
  也不会阻塞 provider 回合。丢掉的增量没有可重放的持久游标——已提交的日志记录的是
  这个回合，不是仍在到达的文本——所以旧通道只能画出尾巴。无人读取的队列会在下一次
  发送时被清理，而进程内的读取者除了排空队列不做任何别的事。

## 输入框会带颜色地说明这个回合在做什么

- **输入框恢复成带标题的方框 (#2472)。** 标题里带着回合状态——阶段、已用时间、队列
  深度和任何提示——旁边是盲文点阵的 spinner，等待超过半分钟时转为警示色。这样
  「它在工作、在排队、还是在等我？」就出现在操作者正在输入的框里，而不是框上方
  单独一条带子里。方框上方那条带子现在只作留白。
- **刚被接受的回合也会显示计时 (#2472)。** 以前只要回合处于活动状态、但还没有收到
  任何 `provider.*` 帧，状态就会退回成一个既无计时也无颜色的纯 `Working`。这个窗口
  覆盖整个请求准备阶段，没有计时也没有色调，读起来和卡死的回合完全一样。现在 App
  在第一次看到某个回合处于活动状态时就为它锚定一个计时。
- **工具行按状态区分符号 (#2472)。** 已完成的调用是 `✓`，失败的是 `✗`，正在运行的
  是 `·`。被它们替换掉的单一 `●` 只能靠颜色区分，所以在单色主题下三种不同结果被
  画成了同一个符号。

## Windows 沙箱测试不再自己跟自己抢资源

- **Windows 沙箱测试改为串行 (#2475)。** `windows-sandbox.rs` 里的 12 个测试原本并发
  运行，每个都要探测一次 AppContainer，然后各自启动 `miao-run` 加一个子进程，并且
  要在十秒内等它写出文件。它们争夺同一个容器配置，于是最后启动的两个没赶上期限——
  `overlapping_invocations…` 报 "first lease never became ready"，
  `child_tree_killed…` 报 "child heartbeat never appeared"——而同一次运行里另外十个
  测试全部通过。这些等待问的是「沙箱子进程能不能启动」，不是「启动得多快」，
  所以串行才是诚实的修法。

## 升级

    miao upgrade

`miao upgrade` 会报告已安装版本以及如何升级到最新发布。如果输出
`feed none configured`，说明这份安装是手动装的，重新运行安装脚本即可：

    curl -fsSL https://raw.githubusercontent.com/oxdingzg/miao/main/install | bash
