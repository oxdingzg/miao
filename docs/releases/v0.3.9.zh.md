# miao v0.3.9

v0.3.9 把 native 会话对文件改动的显示补了回来：`edit`、`write`、`apply_patch` 调用重新显示文件内容与改动行，而且这份 diff 来自事件本身，不会再发给模型一份。同版本里，存储或目录已经消失的会话不再在每次刷新列表时报错刷屏，传输失败会带上 socket 给出的原因，引擎也第一次有了自己的产品配置读取器。本版本不改变任何既有会话的属主。

## native 会话显示什么

- **文件改动把它已经知道的 diff 带上了。** 引擎对写入与编辑只回答 `{sha256, bytes, applied}`，产品因此没有 patch 可画：`edit` 卡片退化成一行 `Update(path)`，`write` 卡片丢掉正文，`apply_patch` 丢掉逐文件的 hunk。现在每次改动都在完成事件上带一个 display 块 —— 路径、动作、unified patch 与增删行数 —— 产品把它投影成与自家 TypeScript 工具相同的 `FileDiff` 形状，因此既有的卡片渲染、摘要行与 diff 高亮都不用改。
- **diff 不会进入模型上下文。** 模型本来就已经写出了它要的文本，把 patch 放进工具结果等于为同一段文本付两次钱。存储层把这个块搬进 `tool.completed` 事件，并从结果、序列化结果与投影历史里剥掉。由于它挂在持久事件上，重开会话或回放同样能画出这些 diff。
- **rebase 过的编辑显示实际落盘的内容。** 当编辑需要 rebase 到被外部改动的文件上时，diff 覆盖真正写入磁盘的文本，而不只是模型请求替换的那一段。

## native 会话目录

- **库里没有的会话就是没有，而不是坏了。** 一条 placement 可能活得比它指向的存储更久 —— 临时 checkout 被删、或某次发布写了另一个存储根。读这类行的目录会回 `Query returned no rows`，产品于是每次刷新列表都记一条 `native catalog facts unavailable`（v0.3.8 启动后 14 分钟内 48 条）。现在存储层回答"这个会话我不知道"，目录直接跳过该行；存储文件不存在时读成空列表，而不是拉起一个以非零退出的读取器。完全读不了的存储仍然逐会话报错，读取用量失败仍然报 `usage_error`。
- **目录已经不存在的 Location 安静跳过。** miao 会删掉自己创建的 worktree，`/tmp` 下的临时 checkout 也会自己消失；列这类分组时会在 `realPath` 崩掉，并且每次刷新每组警告一次 —— 操作者日志里七个死目录攒下 7311 条 `skipping native Sessions whose Location could not be read`。现在先探测分组目录，已消失的分组只在 debug 级别跳过；目录存在但仍解析失败的 Location 依旧警告。搜索服务对已消失的目录回空索引，而不是每次启动该 Location 都报一次 `Invalid path` 初始化失败。

## Provider

- **传输失败保留原因。** `provider transport failed` 原本是个无内容错误，于是连接被拒、TLS 校验失败、端点接了连接却不发响应头、重试窗口耗尽，四种情况读起来一模一样。现在错误带上原因 —— `provider transport failed: connect failed: Connection refused (os error 61)`、`timed out: …`、`decode failed: …` —— 并且刻意不带请求 URL，因为路由的 query 里可能藏着凭据。分类不变：可用性判定、回退、输入拒绝与输出前回放仍匹配同一个错误。

## 引擎地基

- **引擎读得懂产品的配置文件。** 朝"引擎拥有配置"迈出的自成一体的一步：同样的文件顺序（`miao.json`、`miao.jsonc`、`opencode.json`、`opencode.jsonc`），能识别字符串状态的 JSONC 注释与尾随逗号剥离，按目录优先级发现文件，对象深合并、数组整体替换，与产品语义一致；损坏文件报出路径而不是退化成空配置。目前还没有接进引擎启动，所以运行时行为不变。

## 验证与边界

每项改动都通过 `guard`、聚合的 `ci-gate` 套件，以及 macOS 与 Linux 上的 Rust 引擎测试，其中包含 TypeScript 单元、类型检查与 e2e 套件。

- display diff 有端到端覆盖：一个真实的 `edit_file` 跑完运行时后断言完成事件带着落盘的 patch、而模型可见的结果与投影历史没有它；bridge 侧断言产品 `FileDiff` 投影的形状。
- native 的 `read`、`glob`、`grep` 显示的信息仍少于 TypeScript 版本；这些摘要本来就由 native 引擎产出不了，本版本没有改变这一点。
- 配置读取还没有接到引擎启动；读配置的仍是产品物化出来的文件。
- Windows 引擎与运行时套件对着发布提交运行，而不是每个 PR 都跑，所以只在 Windows 出现的问题会在发布闸门暴露。
