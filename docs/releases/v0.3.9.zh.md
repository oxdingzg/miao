# miao v0.3.9

v0.3.9 是通往单内核路上的维护版本：引擎学会读取产品自己的配置文件；让会话一直"无名"的两类失败——被吞掉的标题模型报错、对已死模型的无限重试——现在可见、有界、可自愈。

## 引擎

- **引擎读取产品配置文件（S5 step 1）。** `miao.json` 的发现逻辑（含 JSONC 注释与尾逗号、后目录按优先级覆盖）现在在引擎内执行（`config_scope`），合并规则与产品"按节整键替换"的语义一致。这是 S5 的前半步；TS 侧目前仍传目录与环境，临时 `product-*.json` 物化将在下一步移除。
- **文件修改的 diff 能到达转录。** 引擎侧算好的编辑 diff 不再在工具结果与产品投影之间消失。
- **存储中不存在的会话按"不存在"上报。** 缺失的引擎会话此前报成笼统冲突；消费方现在能区分"不在"与"坏了"。
- **传输失败保留原因。** 路由层包裹的端点失败曾被可用性层误读为请求格式错误；包裹对象现在保持可读。

## 产品

- **标题生成说真话，并且不再捶打已死的模型。** native 会话命名曾每轮 idle 都重试同一个失败模型并吞掉 provider 报错，会话只能一直顶着 `New session - …` 占位符，日志里只剩一条 `exhausted its model candidates`。现在：每个候选的真实失败都会落日志（模型与错误，超时与被拒分开）；套餐排除或模型不存在会记入缓存并跳过（普通限流仍可重试）；空闲泵改为指数退避而非固定每分钟一次。套餐拒绝目录 small model 的场景（如 zhipuai 的 `glm-5.3-highspeed`）在第一次被拒后回退到会话自己的模型——标题从此能生成出来。已存在的占位会话在阻塞条件解除后（例如 Google 配额窗口结束），会在下一次空闲转换时自动补上标题。

## 平台

- **目录已删除的 Location 会被跳过而不是告警。** 扫描不再为被删掉的 worktree 刷屏。

## 文档

- Phase 3 设计（ratatui TUI 统一，切片 T1–T11）与 S2 读取路径定稿随本版本入库。
