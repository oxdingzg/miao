# miao v0.3.39

v0.3.39 让操作者最常做的两件事——添加 provider 与退出会话——真正停在界面承诺的位置。

## 添加 provider 在命令行可用

- **`miao auth` 自己找到产品凭据库（#2553）。** `auth login` 与 `auth` 之前缺少
  `MIAO_ENGINE_CREDENTIAL_DB` 就拒绝运行，于是在默认安装下，TUI 让操作者执行的那条命令
  会因为一个内部变量名而失败。现在解析规则与引擎一致：显式变量优先，否则使用
  `<data home>/miao.db`，首次登录时创建目录；从未写入过的库按空列表报告，而不是报错。
- **`auth logout` 可以指明账号（#2553）。** 之前只删 `default`，用 `--account NAME`
  存的账号无法通过任何命令删除。现在支持 `--account NAME`，并报告该 integration 还剩几条。
- **provider 可以在选择器里直接添加（#2556）。** 之前选到引擎尚未服务的 provider，
  只会得到一段指引：去 shell 执行 `miao auth login <provider> <key>`，再重启 miao。
  现在会弹出密钥输入框，回车即写入产品凭据库（与单二进制启动读取的是同一个文件，
  首次使用时自动创建），并说明重启后该 provider 的模型才会出现。随发布内目录以
  `@ai-sdk/openai-compatible` 提供的 provider（含 opencode-go）到此即可用；不在目录里
  的（例如 commandcode）或用原生协议提供的（openai、google）仍需在配置里写 `providers`。
- **`miao models` 列出引擎实际服务的路由（#2555）。** 它原先只读配置里的 provider，
  于是一台实际路由 9 个 provider 的机器只报 3 个：`model-routes.json` 里由目录派生的
  路由从未出现。现在复用引擎自身的路由材料化，打印与运行中引擎一致的那一组。
- **被替换的那段指引错了两处（#2554）。** 它还让你“去 miao.json 给该 provider 加一个模型”。
  引擎在启动时构建路由表，而 TUI 没有任何 reload 通道，所以在运行中的进程里重开选择器
  永远看不到新加的 provider；此外引擎以 `@ai-sdk/openai-compatible` 提供的那批 provider
  在持有 key 凭据后会自动路由，最常添加的这几个并不需要写 miao.json。

## 退出会话会说出它是哪个会话

- **退出时打印会话与恢复命令（#2551）。** Rust TUI 原本完全没有退场输出——唯一的一份在
  legacy TypeScript TUI 里，只有在 `--tui=legacy` 时才执行——因此结束一段对话后，
  操作者手上没有可输入的标识。现在会在恢复主屏幕之后打印标题、id 与 `miao -s <id>`；
  也正因如此，之前的尝试才会一个字都看不到。

## 选择器画出它列出的内容

- **模型选择器里的 ctrl+o 与已配对设备列表（#2552）。** 两者都能回答 `title()`、也接收键盘，
  却没有进入绘制路径所依赖的 list 访问器，结果只画出边框与标题、正文空白。现在两者都可达，
  并加了遍历所有 list 变体的测试，避免这类空白框再次出现。
