# miao v0.2.23

本版本让原生引擎可以从配置直接开启，修复了破坏 CLI 续跑与显式路由下服务端原生会话的两个故障，并关闭了能力矩阵中记录的插件与客户端覆盖缺口。

## 重点

- **配置即可开启原生引擎**：在全局配置中设置 `engine.storage`，新会话就会落在 Rust 引擎上；`MIAO_ENGINE_STORAGE` 仍然优先。安装器会附带引擎二进制；`miao doctor` 现在会显示发现到的二进制、协议/schema/版本、存储根目录，并在已开启存储但找不到兼容二进制时给出警告（#1201）。
- **CLI 续跑修复**：已被删除的引用路径（比如被外部删除的 worktree 或未克隆的仓库）会让引擎在服务前以 `InvalidInput` 退出，导致 `miao run --continue` 失败。现在缺失的引用授权会被跳过，而不是杀死子进程（#1202）。
- **显式路由在服务端修复**：显式 provider/endpoint 路由只暴露一个没有 route id 的主路由，服务端原生会话无法绑定它——每次 prompt 都报 `Model is not in the native host route catalog`。现在主路由按模型身份绑定，带 id 的路由仍然优先（#1206）。
- **重启不重放**：新增真实引擎验收测试：在同一存储上先后启动两代服务进程，证明转录持久且已完成的回合不会被重放——每个 prompt 恰好产生一次 provider 请求（#1211）。
- **降级防护入档**：用 0.2.15 引擎打开 0.2.22 的 store 会被 `unsupported database schema version` 拒绝、不写入任何字节，当前引擎随后正常继续；rollback 验证文档已记录 SHA-256 级证据（#1209）。
- **客户端覆盖入档**：慢客户端积压上界（暂停的裸 TCP SSE 客户端独立溢出、健康客户端持续接收）、重连、cursor 严格续传且不重复，均已由产品测试覆盖；剩余缺口是第三方 ACP 编辑器 UI 与 app transcript retype（#1208）。

## 引擎与平台

- 插件 `tool.definition` 钩子反向派发到宿主（#1198）；没有 AI SDK 包的插件 provider 映射为 openai-chat 路由，原生会话因此可以自动压缩与路由（#1199、#1195）。
- delegation 从原生会话上报进度（#1194）；product-tool 派发会标注发起的工具调用，并在结算时取消挂起调用（#1192）。
- 每个 provider turn 把 TTFT 写入按模型的 usage 行（#1200），TUI 侧栏显示平均首字节时间（#1203）。
- 安装器在 release 缺少引擎产物时回退到最新的引擎归档（#1196）。
- provider 流 watchdog 按 phase 分离（#1210）；引擎成本基准 harness 与试点报告落在 `script/`（#1207）。

## 验证范围

所有改动合入前均通过完整 CI。两个引擎修复都带真实引擎回归测试（显式路由下服务端原生会话完成一轮；缺失引用授权被跳过）；重启验收用确定性 provider 跑了两代服务进程；降级演练记录到字节级哈希。

## 更新方式

重新运行安装脚本，或让正在运行的 `miao` 在下次检查时通过后台更新获取 v0.2.23。已有会话、凭据和配置都会保留。
