# miao v0.3.60

[简体中文](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.60.zh.md)

v0.3.60 completes the Rust migration's final deletion: the TypeScript product
stack — the TS provider loop, the TS server, the TS CLI entry and the whole
`packages/miao` implementation — is gone from the workspace. The product is
one Rust binary with one execution authority, and the gate evidence for that
claim is now on record.

## The TypeScript product stack is gone (#2840, #2841, RUS-02)

- **`packages/miao`, `packages/server`, `packages/sdk` and the empty
  `packages/cli` are deleted.** The desktop and web clients keep their runtime
  path: the renderer attaches to the engine's loopback rpc plane, and the
  committed API types stay as the shared vocabulary.
- **The TS provider loop (`session/runner/`, the local drain) is deleted** with
  its last two production edges. The location-services assembly binds
  `SessionExecution` to a no-op execution — the schedule's fire path keeps a
  bound implementation that never claims a Session.
- **The static import inventory shrinks from 312 to 184 boundaries**, with the
  runner at 0/0: no TypeScript file in the workspace references a provider
  loop any more.
- **The engine's own test suite covers what the TS harness used to** — the
  ACP client matrix, the HTTP wire adapters, the approval lifetime and the
  placement migration/rejection suites all run on the engine crates.

## Headless JSON speaks cost again (#2822)

`miao run --format json` settles every provider step with a `step_finish`
event carrying the step's cost and token counts — the shape the TypeScript
headless runner standardized. The Rust product had lost that event, so
headless consumers silently read zero steps from runs that billed real money.
An unpriced step keeps its cost `null`, so consumers report unknown rather
than a fake zero.

## One running execution per Session, enforced by the database (#2827)

`engine_active_run` — a unique partial index on `engine_run(session_id)` for
running rows — had no test exercising it. Two new tests pin the
same-Session rejection/acceptance cycle and the cross-Session concurrency it
must not fence away, alongside the lease lifecycle and the placement
migration/rejection suites.

## The sidebar usage section reads cleanly (#2818)

One header (the Last-24h strip) leads the usage block instead of two stacked
banners; rows the column clips reveal their full text on hover; and a day
spread across providers groups models under their provider with an indented
dash.

## Gate evidence on record (#2823, #2826–#2839)

The REL-04 gate closed with an empty blocking-failure list, and every gate now
has its record: single execution authority (composition root + storage
enforcement tests), control-plane inventory with named rejections, a refreshed
real-client semantics matrix (35 suites green), an isolated-copy
migration/fault-injection drill, the paired-artifact checklist for this
release's predecessor, and the fixed-task benchmark (10/10 cells on
glm-5.3-flash). The observation window closed by owner decision; the
darwin-x64 native verification stays deferred until a real Intel-user report.
