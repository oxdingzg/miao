## [0.2.0] - 2026-10-10

miao 0.2.0 opens the 0.2 line and consolidates the 0.1.x series. Across 0.1.x the session core was rebuilt on the durable V2 record, remote control landed end to end, the hot edit, patch, and git paths moved onto a native addon with OS sandboxing, and the cost and latency controls were tuned. 0.2.0 carries that forward and adds the Rust M0 engine. This page summarises the series; per-release details stay in the changelog.

### Session core and storage

- V2 is the only session runtime. The V1 runtime and the legacy session, permission, question, and sync routes are gone, and every client reads the durable record (#324, #299, #427, #416, #418).
- Storage is shared across windows with exclusive migrations and per-window runtime and session ownership, and a window opens attach-first so a schema upgrade never blocks it (#256, #259, #336, #421).
- Payloads are content-addressed: oversized attachments and tool output move into a blob store with `miao db externalize-blobs`, `gc-blobs`, and `retention`, and `miao db status` reports the V1 to V2 migration metric (#55, #61, #77, #305, #329).

### Remote control

- A Hub account foundation with durable authentication, relay roles, and one-use Runtime upgrade tickets (#98, #99, #110).
- Signed device authority and an account-isolated signed roster with bounded grants, plus one-tap same-account device connection and trusted browser enrollment (#469, #476, #480, #482, #487).
- Browser pairing that survives social login, with private cookies and an encrypted session workspace (#124, #128, #130, #464).
- Push and a native iOS app: account-bound registration and encrypted notification contexts delivered over bounded APNs (#146, #147, #155, #158, #159, #97, #119, #150).

### Native acceleration and sandbox

- The `@miao/native` addon is embedded in the binary and backs edit matching and patch derivation, with `MIAO_NATIVE=0` as the TypeScript fallback (#76, #103).
- `git status` runs in-process through gix behind `MIAO_NATIVE`, falling back to the subprocess path (#492).
- The sandbox runs `bash` under macOS Seatbelt or Linux Landlock, opt-in through config or `MIAO_SANDBOX`, with a Windows AppContainer backend (#435).

### Cost and latency

- Tool schemas are normalised at the protocol boundary, so an object root or a top-level combinator no longer fails a whole turn (#491).
- Repetitive output is detected and stopped, including markdown-emphasis refrains, without replaying tools (#495, #53, #127).
- Streams that end without a terminal frame, or that fail transiently, are retried instead of failing the turn (#440, #269, #29), and measured latency baselines are recorded (#239).

### Terminal UI

- The transcript stays pinned to the tail while streaming and recovers from a stranded viewport (#322, #424, #445, #474, #488, #497).
- Esc interrupts the running turn while queued prompts survive and advance, and user messages carry a prompt glyph (#431, #407, #489).
- Subagent activity is shown inline, the Todo panel refreshes on live updates, `/clear` starts a new session in place, and the sidebar lists recent cross-Session messages (#337, #429, #272, #501).

### Engine

- The Rust M0 engine lands: `miao-engine` runs as its own process, with a stdio JSONL host client and headless driver that subscribe to it, admit a prompt, resolve approvals, and wait for `run.finished` against a dedicated engine database (#498, #499).
- The engine gains a `bash` tool with pty-backed process execution (#503).

### Since v0.1.31

- #503 adds the engine `bash` tool with pty-backed process execution, and #499 lands the Rust M0 engine; #498 provides the host client and headless driver.
- #501 shows recent cross-Session messages in the sidebar.
- #500 keeps a cross-window session wake advisory, so a message admitted for a session owned by another window is preserved instead of failing.
- #497 stops the transcript window oscillating into a blank view; #494 stabilises the question-prompt tests.

### Upgrading

Restart miao windows after installing the update. Replacing the executable on disk does not replace code already running in old processes. The 0.1.x line removed the V1 runtime and the legacy network SDK, so clients and plugins that still target them must move to V2 and `@miao/client` / `@miao/sdk`. The model catalog is read only from miao's own source.

### Distribution notes

Windows binaries are currently unsigned.
