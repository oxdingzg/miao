# miao v0.3.69

[English](https://github.com/oxdingzg/miao/blob/main/docs/releases/v0.3.69.md)

v0.3.69 为同一个 provider 加上第二个账号、在磁盘上已有新版本时明确提示，并修掉了长会话与参数转发里让请求被拒的问题。

## 同一 provider 的第二个账号（#2975）

- 重新输入 key 现在就地更新凭证行，而不是替换整行，因此挂在该 id 上的路由与账号不再脱钩。
- 模型选择器新增「添加账号」；配置对话框收集标签名，引擎把两行保持为两个独立账号。
- 路由清单改为从配置与存储重新推导，而不是逐条打补丁。
- 每个 provider 的工具开关：short anchors、批量编辑与代码索引可分别开关。

## 状态栏提示「已安装但未运行」（#2978）

升级只替换启动器的软链接；已经在跑的窗口仍用自己那份构建，而页脚版本是编译期常量。当磁盘上的构建比正在运行的新时，状态栏会保留 `0.3.69 installed · restart to apply`。它在启动时读一次，因为它要你做的就是重启。

## 长会话不再申请超过窗口的输出预算（#2985）

deepseek 类路由在上下文窗口之外还声明了输出容量，端点按「输入 + 请求输出」对窗口计费。原来预算只按窗口算：一个 655K 输入的会话请求 393,216 输出，被端点以超出 1 token 拒绝，而两次溢出恢复都无法缩到它自己算出的界以下。现在压缩与受界预算都先减去路由声明的输出容量。

## 转发的 `serve`/`acp` 参数按 token 解析（#2991）

`--auto-approve` 后面跟任何转发的 `MIAO_ENGINE_*` 开关都会报 `missing option value`：成对解析让无值开关把下一个开关吃成了值。现在逐 token 扫描——`--auto-approve` 单独成立或显式写 `true`/`false`——可接受的语法没有变化。

## 过大的 Retina 截图可以正常附上（#2988）

4–8 MB 的剪贴板 PNG 经 base64 后超过引擎 8 MiB 的附件上限，于是 admit 驳回整条输入，看起来像按了回车没反应。macOS 上超过 4 MiB 的剪贴板图片现在经 `sips` 重编码为 JPEG（质量 80、最长边 2400 px）；重编码失败或没有变小时仍保留原图。

## 任务或 monitor 崩溃后会正确收尾（#2992）

后台任务若 panic 会被记成 `unknown`，monitor 若 panic 会永远停在 `running` 而背后没有进程。现在两者都走常规终态：任务记为 `failed` 并带上 panic 错误，monitor 像被停止那样完成一次持久收尾。

## 更小的修复与维护

- 媒体测试的恢复重开会在租约释放窗口内重试，而不是 panic 在 `Busy` 上（#2995）。
- app 的 i18n parity 不再比对已退役的 Electron 语料（#2989）；多余的 `mut` 不再弄挂 Linux 的 clippy 腿（#2990）。
- Electron 桌面壳已退役（#2986），TypeScript 引擎实现移到 `packages/engine-ts`（#2987）。发布产物不变：产品仍是那个 Rust 二进制。
- `bun run lint:dead` 把「没有任何文件导入的文件」挡在树外（#2980），首次审计发现的 4 个文件已删除（#2974）。
- 包的层次（#2973）与开发流程（#2993）按现状重写了文档。

## 升级

`latest` 通道上的 `miao` 会自行更新；否则重跑安装脚本。已经在运行的窗口在重启前仍用旧构建——状态栏会在这种情况下告诉你。
