# 为什么选择 miao

[English](why-miao.en.md)

**如果你希望任务执行时还能补充要求、看清上下文和费用变化，并在终端里管理并行工作，miao
值得试用。** miao 把重点放在模型周围的执行、上下文和交互上。
模型选择、MCP、LSP 与子代理不是 miao 独有；差异在于这些能力如何组合、哪些状态可见，以及
失败时留下怎样的记录。

本页是产品用途与方向概览。**状态核对：2026-10-07**，以当前 `main` 和 `v0.1.20` 源码为依据；
新合入代码不代表已经发布。更完整的横向分析见[八个开源编程代理对比](agent-comparison.zh.md)。

## 四种值得试用的场景

### 任务没结束，你已经有新要求

代理正在改代码时，补一句“保留旧配置”或“先修测试再改实现”。输入先进入持久化记录，默认在
下一个安全轮次边界处理；显式 queue 等会话即将空闲时再处理。你可以继续参与任务，而不是
每次都中断并从头说明。

这不是随时抢占正在执行的命令，也不保证模型必然正确理解新增要求。见[输入与会话](guide.zh.md)。

### 长会话变慢，你想知道钱和时间花在哪里

miao 显示逐轮用量、费用估算和缓存状态；大工具输出用有界预览与全文文件处理，旧结果裁剪、
摘要和压缩策略可配置。你可以用这些信息排查昂贵或缓慢的轮次，再决定是否换模型或调整任务。

费用是模型标价下的估算，不是供应商账单。裁剪和摘要也可能移除细节，不能承诺固定的省钱比例。
见[供应商与费用](providers.zh.md)。

### 主任务要推进，调查工作又不能丢

把找调用点、审查迁移或研究错误交给子会话。显式后台任务会返回可检查的 ID，完成时通知父会话；
主会话继续工作，随后读取报告或补充任务。项目内会话之间也能带权限约束地交换消息。

不同会话是独立执行上下文，写同一文件仍可能冲突；后台任务属于窗口生命周期，不是常驻服务。
见[后台子代理](background-subagents.md)与[运行时生命周期](runtime.md)。

### 你在多个终端窗格里运行代理

miao 可以单独运行；在 mtty 中，它上报工作、等待输入、完成或错误状态，供终端显示徽章、通知和
提示队列。终端负责组织窗格与提醒，miao 负责模型任务。你不必为了使用 miao 更换终端。

见 [mtty 的代理工作台](https://mtty.dev/zh/mtty/) 和 [Remote Control](remote-control.zh.md)。
远程控制是可选的自建 Hub 与设备授权流程，不等于无人值守的云端任务服务。

## 功能差异：提供什么，以及边界在哪里

下表强调使用方式，不把共有能力包装为独占功能。与其他项目的实现区别见[横向对比](agent-comparison.zh.md)。

| 需求 | miao 的方式与当前状态 | 应当知道的边界 |
|---|---|---|
| 运行中补要求 | 持久化输入；steer / queue 分别在安全轮次和空闲边界采纳；已发布 | 不抢占当前工具；输入记录不等于执行已完成 |
| 后台协作 | `task` 的显式后台子会话、报告与取消入口已发布；只读子代理默认后台是 `v0.1.20` 后的源码更新 | 不是跨机器集群；写入共享文件仍需协调 |
| 上下文与费用 | 逐轮估算、缓存状态、输出治理与摘要已发布；旧结果裁剪/自动压缩默认开启，可配置 | 缓存受供应商影响；估算与预算不是账单硬上限 |
| 长任务续跑 | 可选的待办驱动循环、迭代/停滞保护与费用预算；已发布 | 显式开启；不提供崩溃后自动续跑 |
| 减少编辑返工 | 模糊匹配与诊断已有；快照换基恢复、read 后 LSP 预热是 `v0.1.20` 后的源码更新 | 换基只接受唯一且有界的锚点，拒绝猜测式替换 |
| 工具并行 | 只读工具按类别并发，未声明工具默认独占；主流路径已发布 | 不等于按文件访问冲突调度；concurrent 路径还没有统一有界池 |
| 批量工具脚本 | Code Mode / 渐进工具披露属于实验功能 | 受限语言和工具范围，不是任意脚本执行环境 |
| 命令隔离 | bash 的 OS 沙箱已实现，macOS/Linux 支持；默认关闭 | Windows 无后端；后端不可用默认告警后无沙箱运行，可改为拒绝 |
| 终端与远程 | mtty 状态集成、Remote Control 的 Hub/设备授权路径已实现 | 本地运行不需要 Hub；远程接入需配置并显式启用；窗口退出结束连接 |

默认开关、平台限制和具体命令以[指南](guide.zh.md)、[配置 schema](https://mtty.dev/miao/config.json)
及所安装版本为准。[原生组件基准](native-benchmarks.zh.md)记录的是内部组件测量，不是产品速度排名。

## 什么时候也应试试其他选择

- 更在意专属后端的增量传输、预热或固定模型工作流，可以一起试 Codex CLI 或 Gemini CLI。
- 需要文件冲突感知的批量调度、复杂的子代理编队，可以研究 Kimi Code 的路径。
- 重视哈希锚定编辑、细分模型角色与更丰富的工具链，可以试 oh-my-pi。
- 想按 profile 组合自己的 harness，可以研究 DeepSeek Harness；需要接受其开发预览状态。
- 想沿用其他多供应商工作流与生态，可以一起比较 opencode 和 Qwen Code。

这些是需求对应的试用方向，不是优劣排序。**miao 当前没有主任务自动备用模型链、凭据轮换或
自动沉淀的跨会话记忆，也没有崩溃后自动执行恢复。** 如果其中一项是硬要求，应先检查候选工具
的实际行为，再决定。

## 演进方向

下面是方向性 roadmap，作为后续迭代的讨论与更新入口。**没有承诺发布日期，也不是当前功能
清单；候选方案需经过设计、测试和真实任务验证，才会进入默认行为。**

| 方向 | 现在的基础 | 接下来值得推进或验证的方向 |
|---|---|---|
| **更可靠的完成与恢复** | 持久化输入、事件记录、条件写入、工具/供应商重试与中断状态 | 打磨取消和流式状态一致性；明确结果未知的恢复流程；自动续跑须先解决副作用与幂等边界 |
| **更稳定的上下文与缓存** | 上下文基线、输出落盘、裁剪与摘要、供应商用量可见性 | 改善 fork/辅助调用的缓存亲和；探索裁剪内容可回读、渐进工具发现与更准确的 token 判断 |
| **更可控的并行与模型选择** | 工具类别并发、后台任务、子代理及辅助小模型 | 有界并发和资源冲突调度；容量故障后的显式备用模型策略；结构化报告与更清晰的协作权限 |
| **更一致的客户端与集成** | 共享协议与客户端、TUI/App/ACP、mtty 集成和窗口级远程接入 | 收敛兼容服务与界面状态，改善长历史交互、Remote Control 的配对/授权可见性，以及插件接口 |
| **可验证的性能与默认行为** | 机制回归测试、组件基准与逐轮数据 | 补充启动、首轮、恢复与长任务的用户路径预算；在同一任务集量化时间/费用/成功率，再决定优化与默认开关 |

每次更新应将已经落地的内容移入“当前状态”，并标明发布版本或源码范围；不继续留在“未来”。
具体工程任务以仓库 issue、PR 和源码为准，不能仅凭旧路线图判断完成状态。
