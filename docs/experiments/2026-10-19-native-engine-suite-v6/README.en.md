# Native engine vs TypeScript: suite v6 (2026-10-19)

[简体中文](README.zh.md)

Both engines ran the frozen suite v6 on the same `main` commit — 45 live model runs each — to compare success, turns, billed input, cached input, output, and the resulting cost.

- Repository revision: `83f7c4f935295946d46d1e802cb81ea382f0893c` (identical for both arms)
- Suite: v6, 15 classes, `suiteHash = bd905b4f81f0a9412b614631a36337723067574848c5f05b50ead1cf48675091`
- Model: `deepseek-v4-flash` (TypeScript through the `deepseek/` provider, native engine through the `openai-chat` protocol against `https://api.deepseek.com/chat/completions`)
- Engine binary: `miao-engine 0.2.16`, `binarySha256 = b2c1d67f465561ad7bed58ab28ebe03658b8042e16b0bb3f75a41d65329d14fd`
- Repetitions: 3 per class, 90 runs total, sequential (the arms never share provider capacity)
- Billing: rates in `prices.json`; amounts computed with the product's own `SessionRunnerCost.ofTurn`

## Result

See [`results.md`](results.md) (generated by `../tools/compare.py`) and [`results.csv`](results.csv).

| Engine     | Passed      | Turns         | Billed input | Cached input | Hit rate | Output | Cost         | p50   | p95    |
| ---------- | ----------- | ------------- | ------------ | ------------ | -------- | ------ | ------------ | ----- | ------ |
| TypeScript | 39/45 86.7% | 233 (5.18/r)  | 605,554      | 2,892,288    | 82.7%    | 22,890 | $0.11324     | 7.6 s | 34.9 s |
| Native     | 42/45 93.3% | 500 (11.11/r) | 154,295      | 3,345,021    | 95.6%    | 92,838 | **$0.08888** | 9.0 s | 28.3 s |

**Conclusion**: the native engine costs **21.5% less** overall (ratio 0.785) and passes more runs, with a slightly slower p50 (+1.4 s) and a better p95. Its input side is cheaper (billed input 154k against 606k, hit rate 95.6% against 82.7%) and its output side is more expensive (93k against 23k, at 11.1 turns per run against 5.2).

Per-class ratios (native/TS) are in `results.md`: 14 of 15 classes are cheaper on the native engine (0.055–0.847). The exception is `long-session` (3.43×; the native engine takes 82 turns per run against TypeScript's 17). **Excluding that class: TS $0.10003 against native $0.04356, so native is 56.5% cheaper.**

**Break-even**: on this observation, the verdict flips once output is priced at least **6.32×** input; this model is at 4.0×.

## Repeat runs and spread

A second run of the same suite and model at `n=3` (the earlier round) gave ratio **0.881**, break-even **4.98×**, and **0.408** excluding `long-session`. Across the two rounds the native engine's advantage moved between 11.9% and 21.5%, driven mostly by the turns/output spread in `long-session` (3.4×–4.3×). Therefore:

- one round establishes a direction, not a magnitude;
- for a cost claim, run the same configuration at least twice and report both rounds (see the rules in `../README.en.md`).

## Behavioral differences

- `permission-denial`: TypeScript 0/3 (terminates as completed with only a `tool.error`, missing the `permission.denied` the task requires); native 3/3 (both receipts present).
- `stream-interruption`: 0/3 for both arms, for a protocol reason rather than an engine one: the interruption proxy is built for Responses/SSE, so on the `openai-chat` route TypeScript is SIGINTed (exit 130, no `provider.interrupted`) while the native engine receives provider HTTP 418. The class is not comparable on this route.

## Evidence boundary

One model, n=3 per class, short programmatically gradable tasks, sequential runs on one machine, and tiny absolute amounts (~$0.20 for both arms). These numbers are not a product-level or cross-model claim.

## Reproduction

```sh
# Prepare the key first (never committed): <env.json> = {"OPENAI_API_KEY": "<deepseek key>"}
cd packages/miao

# TypeScript arm (5 classes per chunk; <data> is the product data directory)
bun run src/engine/baseline-sweep-cli.ts --engine typescript --out <out> \
  --tasks read-only,multi-read,small-edit,multi-file,test-repair --repetitions 3 --pause-ms 500 \
  --model deepseek/deepseek-v4-flash --entry packages/miao/src/index.ts --credential-db <data>/miao.db \
  --revision <revision>

# Native engine arm (same model over the openai-chat protocol)
bun run src/engine/baseline-sweep-cli.ts --engine rust --out <out> \
  --tasks read-only,multi-read,small-edit,multi-file,test-repair --repetitions 3 --pause-ms 500 \
  --model deepseek-v4-flash --binary <miao-engine> --provider openai-chat \
  --endpoint https://api.deepseek.com/chat/completions --env-file <env.json> --revision <revision>

# Collect and compare
python3 ../tools/collect.py --out <run dir> --engine typescript --chunk <out>...
python3 ../tools/compare.py --typescript <run>/raw/typescript --rust <run>/raw/rust \
  --prices <run>/prices.json --exclude long-session --csv <run>/results.csv --markdown <run>/results.md
```

The full three-chunk commands are in `manifest.json` under `commands`, together with the task list, repetitions, and suite hash.

## Files

| Path                           | Content                                                                                |
| ------------------------------ | -------------------------------------------------------------------------------------- |
| `manifest.json`                | per-arm revision, model, suiteHash, binarySha256, tasks, repetitions, commands, timing |
| `prices.json`                  | billing rates and their source                                                         |
| `results.md` / `results.csv`   | totals, per-class results                                                              |
| `raw/<engine>/evidence/*.json` | full evidence per run (attempts, phases, receipts, assessment)                         |
| `raw/<engine>/samples.json`    | merged samples (outcome, profile, receiptHash)                                         |
| `raw/<engine>/sweeps.json`     | per-chunk sweep summaries (binary path dropped, digest kept)                           |
