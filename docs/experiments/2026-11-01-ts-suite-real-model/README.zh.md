# 真实模型 TypeScript 套件：按完成任务计的成本与时间

## 范围与来源

- 产品：`miao-dev`，从工作树源码运行。运行期间检出点在 `8b3854080b`、
  `3a08e281cb`、`b6323b36af` 之间切换过；三者差异只有一行配置诊断和一篇规格文档，
  不涉及会话执行代码。共同基线是 `58118fc1dc` 的 `origin/main`。
  更严格的做法是在单一固定检出上重跑。
- 跑分脚本：`script/engine-benchmark.ts`（全程未变）。每个单元使用全新工作区，
  通过 `miao run --format json` 执行，成本与 token 数取自流式事件，不查询数据库。
- 模型：目录中的 `deepseek/deepseek-flash`，本轮只用了这一个模型。
- 任务：脚本内置的七个固定夹具——`bugfix`、`feature`、`refactor`、`multifile`、
  `recovery`（运行中中断后恢复）、`long-session`（多轮）、`impossible`
  （自相矛盾的请求，正确结果是拒绝）。
- 重复：每个任务每引擎 2 次，共 14 次尝试。
- 计费：`billed-in = input + cacheRead`，因为 provider 的缓存命中会让原始 `input`
  不可比；成本采用 provider 自报数值。

## 结果

每次尝试都通过了各自的验证闸门。没有失败样本，也没有超预算样本，因此本报告不存在
「只列成功样本」的筛除。

| 任务 | TypeScript billed-in p50 | $ p50 | 秒 p50 | 通过 |
| --- | --- | --- | --- | --- |
| bugfix | 239,235 | $0.0026 | 32 | 2/2 |
| feature | 282,868 | $0.0018 | 31 | 2/2 |
| refactor | 244,261 | $0.0013 | 31 | 2/2 |
| multifile | 218,822 | $0.0018 | 87 | 2/2 |
| recovery | 182,143 | $0.0013 | 44 | 2/2 |
| long-session | 341,531 | $0.0019 | 49 | 2/2 |
| impossible | 181,966 | $0.0017 | 26 | 2/2 |

本轮汇总：14/14 验证通过，provider 自报成本合计约 **$0.025**。每任务耗时是脚本
记录的「提交到验证完成」墙钟时间；本轮按构造不含人工介入。

原始输出：[`raw/deepseek-deepseek-flash.md`](raw/deepseek-deepseek-flash.md)。

## 本记录能支持与不能支持的结论

可以支持：

- 一次真实模型运行的固定任务集、模型、验证器与重复次数（VAL-01 的前两项），
  以及 VAL-02 所需的「按完成任务」成本与墙钟时间、COST-01 所需的缓存维度拆分。

不能支持，也不得据此推断：

- **任何 Rust 与 TypeScript 的对比**。本轮只有 TypeScript 臂。原生臂需要新构建的
  引擎二进制；机器上唯一的引擎产物早于该基线，用它跑会得出误导性对比。
- **统计置信度**。每任务两次重复只能作方向性参考；因为只有两个样本，各行 p50 等于 p95。
- **输入回声延迟（PERF-01）与启动时间（PERF-03）**。它们有各自的测量方法与脚本；
  本轮只测模型轮次。
- **越过触发点的长任务压缩（CTX-02）**。`long-session` 夹具为九轮，不跨越压缩触发点。
- **人工介入统计**，这也是 VAL-02 的验收项之一。
