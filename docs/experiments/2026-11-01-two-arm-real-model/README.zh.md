# 双引擎真实模型对照：TypeScript 与原生引擎

## 范围与来源

- 基线：`main` 上的 `58118fc1dc`，两臂都从该提交运行。
- 原生臂：在同一次提交上、于项目 macOS 构建机执行的
  `cargo build --release --bin miao-engine`，通过 `MIAO_ENGINE_BIN` 指定。
  它自报 `protocol 2`、`routes_schema 2`、版本 `0.3.23`，正是宿主要求的组合，
  因此旧产物无法冒充基线引擎。
- TypeScript 臂：同一棵树的 `miao-dev`，不走原生放置。
- 跑分脚本：`script/engine-benchmark.ts`，未修改。每个单元使用全新工作区，
  通过 `miao run --format json` 执行，成本与 token 取自流式事件。
- 模型：目录中的 `deepseek/deepseek-flash`，两臂同一模型。
- 重复：每任务每引擎 2 次，共 28 次尝试。
- 计费：`billed-in = input + cacheRead`；成本采用 provider 自报数值。

## 结果

28 次尝试全部通过验证闸门。没有失败样本，也没有超预算样本，因此不存在被筛掉的记录。

| 任务 | TS billed-in | Rust billed-in | 差异 | TS $ | Rust $ | TS 秒 | Rust 秒 |

| bugfix | 200,509 | 184,675 | −8% | $0.0026 | $0.0026 | 40 | 19 |
| feature | 315,811 | 315,309 | 0% | $0.0018 | $0.0024 | 24 | 27 |
| refactor | 250,484 | 289,913 | +16% | $0.0015 | $0.0016 | 25 | 22 |

| **p50 之和** | **2,058,333** | **1,774,892** | **−13.8%** | **$0.0165** | **$0.0142** | **234** | **189** |

- 计费 token 汇总：`1,774,892 / 2,058,333 = 0.862`，原生臂少读 **13.8%**。
- 自报成本汇总：`$0.0142 / $0.0165 = 0.861`，低 **13.9%**。
- 提交到验证完成的墙钟时间汇总：`189 / 234 = 0.808`，快 **19.2%**。
- 质量没有被牺牲：两臂各 `7/7` 通过，包括 `impossible`——该任务唯一通过条件是
  拒绝伪造结果。

整轮开销约 **`$0.06`**（28 次尝试的 provider 自报成本）。

## 本记录能支持与不能支持的结论

可以支持：同一基线、同一模型、同一任务集下两引擎在成本、计费 token 与墙钟时间上的对照，
且每次尝试的闸门结果都已列出。

不能支持：

- **统计置信度**。每单元两次重复只是方向性，每行 p50 等于 p95 正是这个原因。各任务差异
  （refactor `+16%` 与 recovery `−28%`）大于任何在此样本量下值得主张的汇总结论。
- **泛化的速度结论**。这是单机、单模型上的七个短任务；长会话、大仓库与工具密集场景未被代表。
- **输入回声延迟与启动时间（PERF-01、PERF-03）**需要各自的 harness；**越过触发点的压缩
  （CTX-02）**也不覆盖——九轮的 `long-session` 夹具不跨越触发点。
- **人工介入统计（VAL-02）**：按构造为 0 次，且脚本不记录该项。
