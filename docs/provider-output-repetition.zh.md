# 供应商重复输出：调查与保护

[English](provider-output-repetition.en.md)

## 调查结论 — 2026-10-04

本机会话使用 `opencode-go/deepseek-v4.1-flash`、`default` variant，多次反复输出 `Emit.`、`edit.`
等步骤标记，随后才发出结构化工具调用。

只读检查会话投影、持久化事件和回合日志后发现：

- 异常会话有八个明显重复回合，其中一个包含 437 行重复标记。重复内容同时存在于助手消息投影
  和持久化的 `session.next.text.ended` 事件中，并非仅在终端呈现时重影。
- 这些回合以 `tool-calls` 结束，工具执行完成。这不同于没有真正执行工具的 XML/DSML 外泄，也
  不同于 `finish=stop` 后 runner 不断重新派发请求。
- 检查时段中，异常会话有 63 个回合，供应商报告的 `input + cache.read` 为 276,517–372,283 tokens。
- 同时段，同一供应商、模型和 variant 的其他会话仍能正常工作。其中两个输入更大：34 个回合、
  542,622–570,030 tokens；78 个回合、402,187–514,485 tokens。第四个会话有 41 个回合、
  8,492–62,998 tokens。

因此，长度本身不能解释故障。会话特定的历史、生成行为、请求参数和网关路由仍是可能因素。
模型自称“退化”不构成诊断证据。

默认归档目录中未找到历史 provider-wire 记录。持久化数据可以定位渲染前的异常输出，但不足以
彻底区分上游生成与协议解码行为。本次是应用侧保护，不是已证实修复了供应商模型或路由根因。

相关上游反馈：[#44962](https://github.com/anomalyco/opencode/issues/44962)、
[#43146](https://github.com/anomalyco/opencode/issues/43146)、
[#52763](https://github.com/anomalyco/opencode/issues/52763)。调查时均为开放状态。

## 保护机制

`packages/core/src/session/runner/output-guard.ts` 在事件进入持久化发布器和本地工具派发之前，
检查每次 provider attempt。普通文本与 reasoning 分块独立跟踪；状态按每次流订阅创建，不在
不同 Session 或窗口之间共享。

首版检测刻意保守：

- 检查最近 64 行短的、非空自然语言文本，忽略空行分隔。
- 要求不同文本最多六种，出现最多的两种合计占至少 58 行。
- 跳过 fenced code；遇到长行、JSON、表格、列表或非自然语言内容则清空窗口。
- 最多保留 16 个内容块，每块最多 64 行，每行最多 160 个 UTF-16 单元。
- 不检查工具参数；它与重复工具调用上限是不同机制。

触发后，流以不可自动重试的 `InvalidProviderOutput` 错误结束，并显示以
`Stopped repetitive text output` 或 `Stopped repetitive reasoning output` 开头的错误。
runner 保留此前已发布的输出，结算已启动的工具，不自动重放整个 provider turn。
检测到循环之后的工具调用不会派发。`session.output.repetition` 警告日志只记录通道与窗口大小，
不记录会话文本。

之后用户明确续跑时，发送给供应商的历史会隔离异常助手文本/reasoning，包括可识别的历史循环。
持久化消息保持原样，已记录的工具调用和结果仍进入上下文，避免隐藏已经完成的副作用。

## 验证与边界

本地独立回放样本包含四个同时段会话的 263 个文本/reasoning 片段：

- 异常会话：55 个片段中识别出 7 个严重循环。第八个较短的异常未达到保守阈值。
- 三个对照会话：208 个片段，没有触发。

这验证的是已观察到的样本，不是全部合法输出。刻意高频重复未置于代码块中的短句，也可能触发。
没有换行的重复、长段落重复、阈值以下的短循环不在首版检测范围内。

回归覆盖普通文本/reasoning、chunk 边界、Unicode/CRLF、代码/列表/表格豁免、上游流释放、
内容块和订阅隔离、无自动重试、已完成工具结算，以及只隔离模型上下文而保留持久化历史。

本次变更不会追溯开启原始 wire 记录，也不等于替换了已安装的发布二进制。
可用时，显式启用 `MIAO_LLM_WIRE_ARCHIVE` 可以获取之后的 wire 证据，但无法重建先前响应。
本文不包含凭据、本机原始会话或机器地址。
