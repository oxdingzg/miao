## PERF-04 — idle CPU, process-tree RSS and resource leaks

| criterion | command | observed |
| --- | --- | --- |
| record CPU, RSS and file descriptors for an idle run | `cargo test --test idle_resources -- --nocapture` | 1 passed, printing `PERF-04 idle: cpu_ms=0 over 3000ms, rss_kb=17744, fds=18`. The harness spawns the real binary against the scripted engine, lets the first frames settle, then samples the process over a three-second quiet window: `ps -o time=,rss=` for CPU and memory, `/proc/<pid>/fd` on Linux and `lsof -p <pid> -Fn` on macOS for descriptors. The bounds (`< 3000 ms`, `< 512 MB`, `0 < fds < 1024`) only catch a busy loop or a leak; the numbers that matter are the ones printed. |
| do not repaint while idle | `cargo test --lib -- repaint` | 2 passed: `pane::tests::a_relative_timestamp_only_repaints_when_its_label_would_change` and `app::tests::a_home_screen_without_timestamps_never_repaints_on_its_own` (#2096 removed the fixed fifty-nine-second idle tick) |
| file-descriptor usage | same command | reported as `fds=18` on an idle process, with a bound that a descriptor leaked per frame would breach inside the window. Where neither `/proc` nor `lsof` answers, the count prints `unavailable` and the assertion is skipped rather than failing a platform that cannot measure. |
| 100 Session switches, and streaming-versus-idle convergence | — | **not accepted**: no harness drives that many switches yet |
| the whole process tree (engine, TUI, broker, LSP, workers) | — | **not accepted**: the TUI embeds the engine, so an idle run is one process; a spawned-engine run still needs the tree walk |
