# INP-08:Vim 模式、建议输入与输入质量辅助

状态:评估完成;无代码改动。本文对 INP-08 的三个候选分别给出评估结论,并确认"默认不
开启、不新增模型请求、可关闭、不影响 CJK/IME 与既有键位"四条约束在结论下的成立方式。
源码基线为 main `85efc79be8`,2026-10-30。

## 1. 现状盘点(as-is,锚定实现)

- **无 Vim 模式**:输入面是 `@opentui/core` 的 `TextareaRenderable`,键位经统一
  keymap layer(`packages/tui/src/keymap.tsx`)分发。没有任何 mode 状态机(normal/
  insert/visual)实现;`parsers-config.ts` 里的 nvim 提及只是 tree-sitter 查询的来源
  仓库,与编辑模式无关。
- **补全是显式触发的,无 ghost text**:`component/prompt/autocomplete.tsx` 只在
  触发符(`@` 文件、slash 命令)后列出候选;`prompt/history.tsx`、`stash.tsx`、
  `frecency.tsx` 提供本地历史/暂存/频次排序。没有任何"模型生成的前瞻建议"(ghost
  text),也没有为自动补全发起模型请求。
- **无隐藏字符提示**:输入对 zero-width、双向控制、不可见 Unicode 字符不做标记或
  警告;`prompt/display.tsx` 的 `displayCharAt` 处理显示宽度,但不提示不可见字符。
- **外部编辑器已覆盖重度编辑**:INP-05 线的编辑器集成(外部 `$EDITOR` 打开当前
  草稿)是多行复杂编辑的既定出口;shell 模式(`!` 前缀)覆盖命令场景。

## 2. 逐项评估

### 2.1 Vim 模式 —— 暂不做,重度编辑走外部编辑器

- **收益面**:重度 Vim 用户在单行/多行草稿上的编辑效率;但 miao 的输入主体是自然
  语言 prompt,不是代码,长程结构化编辑(对齐、重复、正则替换)的真实场景落在
  代码编辑器里——那是被编辑对象,不是输入框。
- **成本面**:mode 状态机要横在统一 keymap 之前,是键位冲突的最高危来源(验收第 3
  条"不影响用户原有键位"直接受威胁);normal mode 与 CJK/IME 的 composing 交互
  (中文候选窗与 Esc 语义冲突)是已知难点;opentui Textarea 不暴露逐字符光标操作
  的完整原语,等于在渲染层之上重写半个编辑器。
- **既有出口**:INP-05 外部编辑器已把"用你最顺手的编辑器(含 Vim)编辑草稿"补齐。
  在输入框内重造 Vim 的边际收益接近零。
- **结论:不实现。** 重开条件:VAL-03 的操作基线显示草稿编辑摩擦是显著成本项,且
  外部编辑器路径实测不便(如 SSH 场景无可用 `$EDITOR`)。

### 2.2 模型驱动的建议输入(ghost text)—— 不做;本地建议已覆盖

- 验收第 2 条直接给出约束:**不新增模型请求做自动补全**。模型驱动的 ghost text
  每次停顿都发起请求,费用与延迟不可接受,且建议文本与用户意图的错配在 prompt 场景
  下修正成本高于收益。
- 本地零请求的建议已存在:历史循环、stash、frecency 排序的 `@`/slash 补全。它们
  默认开启、显式触发、随 keymap 可改,天然满足"默认不开启新增请求"与"可关闭"。
- **结论:不实现模型驱动的建议;维持本地显式补全。** 无重开条件——除非未来出现
  零请求的本地建议源(如本地小模型),届时另评。

### 2.3 隐藏字符提示 —— 登记为低优先候选,暂不实现

- **场景**:从网页/文档复制文本粘贴进输入框时,zero-width 字符(U+200B 系列)、
  双向控制符(U+202A-202E)、不可见格式字符可能随文进入,轻则显示异常,重则改变
  模型对指令的解读(bidi 重排可 visually 重排文本)。提示有真实的安全与调试价值。
- **成本面**:实现很小(输入流扫描不可见 Unicode 分类,命中时在输入行尾部显示
  计数徽标,点击/键位跳到首个命中),且默认开启不违反"不新增模型请求";但它
  会给每个粘贴增加一次全文扫描与一条潜在打扰。
- **判定依据**:目前没有已核验的用户案例(误粘贴不可见字符导致行为异常),按
  "有依据才提示"的项目纪律,先登记候选不实现。与 MEDIA-04 同样的重开条件写法:
  出现第一个真实案例即立项,实现时默认开启、可关闭、扫描在本地完成、不触碰
  IME composing 缓冲。

## 3. 结论

| 候选 | 结论 | 重开条件 |
|---|---|---|
| Vim 模式 | 不实现;INP-05 外部编辑器覆盖 | VAL-03 基线显示输入编辑摩擦显著且外部编辑器不可用 |
| 模型驱动 ghost text 建议 | 不实现 | 出现零请求的本地建议源 |
| 隐藏字符提示 | 低优先候选,暂不实现 | 第一个真实误粘贴案例 |

四条约束的确认:三项均默认不开启或不存在;不新增任何模型请求;本地补全的可关闭与
CJK/IME 兼容性是既有行为,本评估不引入任何改变其性质的新键位或捕获层。INP-08 以
本评估收口,不保留待办。
