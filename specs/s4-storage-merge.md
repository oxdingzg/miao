# S4：存储合一设计

状态：已落地，2026-10-26 合入 main（#1478）。前置：S3 已落地。

## 1. 目的

`specs/rust-phase-2.md` §4 的 S4：引擎库成为会话状态的唯一权威，产品库降为投影/索引；
迁移脚本可反复执行；降级回旧版本有明确的拒绝路径。

## 2. 现状

- 产品库：`<Global.Path.data>/miao.db`（`packages/core/src/database/file.ts:20`），drizzle
  迁移在 `packages/core/src/database/migration.ts:13`。
- 引擎库：`<storageRoot>/<sha256(location)>.db`（`packages/server/src/handlers/session.ts:141`），
  自带 `PRAGMA application_id` 版本号（`crates/miao-engine/src/store.rs:147`）。
- 引擎只在迁移/搬运时打开产品库，平时不读它（`specs/rust-phase-2.md` §1 的测绘结论）。

## 3. 设计

1. **权威归属**：会话状态（消息、事件、inbox、grant、usage）以引擎库为唯一权威；产品库保留
   索引与投影（Session 列表、搜索、TUI 需要的轻量视图）。
2. **单一写入方向**：产品从引擎的事件流投影；产品库不再有"只有产品知道"的会话真相。
   投影必须幂等、可重放，且能在引擎库丢失时从事件重建（不承诺反向重建）。
3. **迁移脚本可反复执行**：`migrate` 以 `(session_id, engine_seq)` 为幂等键，重复执行不产生
   重复行；执行前后各记一条 `data_migration` 行（表已存在）。
4. **降级拒绝**：旧版本打开新库时，`application_id` 版本号高于自身支持的版本即拒绝启动，
   并给出"请回滚到 ≥X 版本"的明确错误。这里的原则是宁可拒绝，也不要静默读一半。
5. **回滚窗口**：S4 合入后至少保留一个发布周期只读兼容（旧产品库仍被读取），再删除产品侧的
   写路径。

## 4. 验收

- 旧库迁移后重放一致：同一 Session 的可见消息序列、提升序列、usage 与代价在迁移前后逐项相等；
- 迁移脚本执行两次结果相同（幂等）；
- 新库 + 旧二进制的启动被明确拒绝，错误信息可操作；
- 关闭引擎（只读产品库）时 TUI 仍能列出 Session（投影完整）。

## 5. 不做

- 不做双向同步：只有一个写入者。
- 不把引擎库拆成多文件；"每个存储路径一个引擎进程"的约定不变。
- 不迁移远程/共享 Session 的归属（属于后续设计）。

## 6. 风险

| 风险 | 处理 |
|---|---|
| 迁移中途失败留下半写状态 | 单事务 + `data_migration` 记账 + 可重复执行 |
| 投影缺字段导致 TUI 掉信息 | 迁移前先枚举 TUI 读取面，逐项落投影测试 |
| 用户降级后数据不可读 | 版本号硬拒绝 + 发布说明写清最低版本 |
