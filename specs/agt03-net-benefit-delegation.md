# AGT-03：净收益委派与结构化报告

状态：设计待审阅；无代码改动。本文界定父会话何时该把一个切片委派给子代理（净收益判断）、
子代理须交回什么结构化结果供父决策，以及失败时已付进度如何折算重做成本。是 AGT-04 分工
边界的下游：AGT-04 说 Delegation owns「谁做一个有界切片」，本文说「何时值得切、切了要交回
什么」。源码基线为 main `7cac644215`，2026-10-28。

## 1. 问题

委派有成本：派生子会话、独立上下文、报告往返、以及子失败后父要重读转写判断重做多少。若
不界定"何时净收益为正"，父会把顺序依赖的活派出去（拿不到父上下文、反复往返），或把该隔离
的活拉进主上下文（淹没预算）。同时子的最终报告今天是自由文本，父无从据此决策。AGT-03 要
给出净收益判据 + 结构化报告契约 + 失败重做成本折算。

## 2. 现状盘点（as-is，锚定实现）

- **派发**：`task` 工具（`tool/task.ts:42`）引导已很薄——"独立调研或会淹没主上下文的活"
  才委派，`background: true` 让父并行继续。无净收益判据、无"何时不该派"。
- **中间报告**：`report` 工具（`tool/delegation-report.ts`）已实现：子在跑时发进度便签，
  单条 ≤ `MAX_REPORT_BYTES = 8KB`（`:10`）、每任务 ≤ `MAX_REPORTS = 8`（`:16`），按任务计
  （`delegation-store.ts:254` `progressCount`），父在下一个安全边界读，不打断父。
- **预算**：`wake_allowance`（`delegation-store.ts:388`）限定一条人类提示买到多少次机器唤醒，
  防自持循环；报告不额外扣。
- **失败重做**：子停滞或未交回完整报告时，`childProgress`（`delegation.ts:27`）汇总子已完成
  的工具调用数与最后一次调用名，注入失败消息供父决定重做多少（`delegation.ts:152,173`）。
- **最终报告**：子"照常回复即结算"——最终文本是自由文本（`delegation.ts` 取 assistant text）。

即：**报告的"量"已有界（字节/条数/唤醒），报告的"结构"与委派的"净收益判据"是空白。**

## 3. 净收益判据（何时委派）

父在派发前按四轴判断，正收益才委派：

1. **并行度**：切片之间无顺序依赖、可与父其余工作重叠 → 派（`background: true`）。有严格
   前置依赖、需父上下文接力 → 不派，内联。
2. **上下文体积**：切片会产出大量中间产物（检索、批量读、长日志）而父只需结论 → 派（隔离
   预算）。只需少量上下文、或结论高度依赖父已有状态 → 内联。
3. **专业度**：需要与父不同 agent/模型/工具面（如只读探索、专用领域）→ 派对应 `subagent_type`。
   与父同质 → 内联，省一次往返。
4. **失败重做成本**：若子失败，父重读转写+重做的期望成本 > 内联直接做的成本 → 内联。判据
   与 §5 的重做折算同源。

**反模式**：把一个必须顺序接力的活拆成多个子（上下文割裂、往返放大）；把一句话能答的活派出去
（往返成本 > 活本身）；派出去却不给足自足的 prompt（子缺父上下文只能反问）。

## 4. 结构化报告契约（子须交回什么）

最终报告是子结算的 assistant 文本，今天无结构。提案：约定一个轻量结构，让父无需读转写即可
决策，且仍是模型可读文本（不引入新事件类型）：

- **结论**（必填）：任务目标是否达成，一句话。
- **证据**（done 时必填）：关键产物/路径/数据，供父核验（对齐 AGT-04 对 Goal done 的 evidence 要求）。
- **改动面**（有副作用时必填）：动了哪些文件/资源，供父判断是否需复核或回滚。
- **未决/移交**（可选）：子未能完成、需父接手的部分，与 AGT-04 的 blocked 语义一致。
- **净收益回执**（可选）：子自评"这次委派是否划算"（如：隔离省下的上下文 vs 往返），供父
  校准未来判断。落在报告末尾的固定块，不混进结论。

结构是**约定的文本骨架**而非 schema 强制：父按块解析，缺块则退化为自由文本（老行为），永不
因结构缺失判失败。

## 5. 失败重做成本折算

`childProgress` 已汇总子完成的工具调用（`delegation.ts:27`）。本文把它升为**重做成本信号**：

- 子停滞/失败时，父收到「已完成 N 次工具调用（最后：X）」。父据 N 与 X 判断：切片几乎完成
  → 优先续跑该子（`task_id` 复用）而非重派；刚起步 → 可整片重派；有副作用 → 按 AGT-04/RUN-04
  铁律不重放，只补未做的部分。
- 净收益闭环：把"重派发现子已完成大半"计入 §4 的净收益回执，让父下次更倾向内联或更早续跑。

## 6. 现状缺口汇总

- **G1｜无净收益判据**：`task` 描述（`task.ts:42`）只说"何时派"，不说"何时不派"，父缺四轴判断。
- **G2｜最终报告无结构**：结算文本自由格式，父无法机器化提取结论/证据/改动面。
- **G3｜重做成本未闭环**：`childProgress` 只注入失败文本，未与"续跑 vs 重派 vs 内联"的决策
  显式挂钩，也未回流校准净收益判断。

## 7. 目标契约（提案，不在本文实施）

- **C1｜净收益四轴**：并行度、上下文体积、专业度、重做成本，写进 `task` 工具引导，正收益才派。
- **C2｜报告骨架**：结论/证据/改动面/未决/净收益回执五块的约定文本，父按块解析、缺块退化。
- **C3｜重做决策挂钩**：`childProgress` 的 N/X 映射到「续跑(task_id)/重派/内联」三分支，
  并回流 §4 净收益回执。
