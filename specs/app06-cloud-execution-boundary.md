# APP-06:云任务与集群执行边界

状态:评估完成;无代码改动。本文回答 APP-06 的三个验收问题:远程操控与云端执行的
区分、执行所有权/fencing/凭据边界的再设计时机、以及 Event replay claim 不是分布式
Session 执行锁的现状确认。结论:**维持明确延期——云端执行无当前需求载体;远程操控
本机是已设计的产品形态,两者不得混同**。源码基线为 main `85efc79be8`,2026-10-30。

## 1. 现状盘点(as-is,锚定实现)

- **远程操控本机是已设计的产品形态**:`specs/remote-control.md`(拟议,2026-10-04,
  2026-10-06 修订)定义统一会话接入:本地 TUI、App、网页操作**同一个本机会话**,
  "执行、文件与模型凭证留在会话所属机器";执行机器向 Hub 出站建连,不要求公网入站;
  关闭本地窗口,执行与 Remote Agent 一起结束。TUI 侧 `dialog-remote.tsx`、
  `dialog-devices.tsx` 是这条线的界面入口。**会话执行属主始终是那台本机**。
- **云端执行不存在**:仓库没有任何"会话执行所有权迁出本机、在某云端 worker 上
  drain"的实现或配置。V2 Session Core 的执行属主是 Location-scoped 的
  SessionRunner(miao `AGENTS.md` V2 Session Core 节),placement 只在本机
  process-local 范围内成立;集群执行明确写着"until clustering is implemented"。
- **replay claim 与执行属主分离是已定架构红线**:`AGENTS.md` V2 节明文
  "Keep EventV2 replay owner claims separate from clustered Session execution
  ownership"。replay claim 回答"谁在重放事件日志",回答不了"谁该执行下一条
  prompt";把前者当后者用,会在没有 fencing 的情况下出现双执行。

## 2. 逐项回答

### 2.1 远程操控本机 ≠ 云端执行(验收 1)

两者常被混为一谈,边界如下:

| | 远程操控本机(remote-control 线) | 云端执行(APP-06 的对象) |
|---|---|---|
| 执行属主 | 会话所属本机,不变 | 迁移到云端 worker,属主转移 |
| 凭据 | 留在本机,远端只见投影 | 凭据必须进云端边界,新攻击面 |
| 断连语义 | 远端离线,本机继续跑 | 执行在云端继续,属主漂移 |
| fencing | 不需要(单属主) | 必需(防双属主双执行) |

现状产品只做左列;右列没有任何实现,也没有需求载体。

### 2.2 所有权/fencing/凭据的再设计时机(验收 2)

**有真实需求才设计**,判定标准(全部满足才立项):存在"会话属主机器不在线时任务
必须继续"的产品承诺(即无人值守云端会话成为需求,而非选项);RUN-05 的续跑歧义
恢复与 APP-04 的远端 workspace 已落地(它们是云端执行的邻接前提)。在那之前写
设计只会给一个没有调用方的边界。

### 2.3 replay claim 不是执行锁(验收 3)

现状确认:V2 的 EventV2 replay owner claim 只服务于重放期间的日志属主判定;
集群化执行属主与 fencing 是独立问题。本条作为架构红线维持——任何未来云端执行
设计**不得**复用 replay claim 作为执行锁,必须引入带租约与续期的执行 fencing
(独立设计,见 2.2 的时机条件)。

## 3. 结论

维持 APP-06 的"明确延期"为**经评估的延期**:云端执行无需求载体、无邻接前提,
remote-control 线(执行留在本机)是当前全部产品形态。验收三项全部回答并以本文
为证;延期本身不变,重开条件 = 2.2 的两个前提落地且无人值守云端会话成为产品
承诺。本条以评估收口。
