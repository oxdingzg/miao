# AGT-05：跨会话消息回执、回复与环路成本

状态：设计待审阅；无代码改动。本文不重述跨会话消息的发现/投递/唤醒（见
`specs/v2/session-messaging.md`），而是界定发送之后的两件空白：**回复如何被结构化关联**，
以及**消息环路的成本如何被核算与设界**。源码基线为 main `e76435ad96`，2026-10-28。

## 1. 问题

`send_message` 让一个会话给同项目另一会话投递一条署名输入，但今天的契约刻意**止步于投递**：
回执只报"投给谁、是否请求唤醒"（`session-messaging.md:52`），明确"发送方不得等待回复"、
"请求唤醒只是建议，不代表执行开始或会有回复"（`:48`）。于是两件事没有机制：

1. **回复关联**：接收方处理后，发送方拿不到一条结构化、可关联到原请求的回复。若接收方要回，
   只能再 `send_message` 回来——两条消息之间没有因果关联，发送方无从把"这句是回我那条"。
2. **环路成本**：A 问 B、B 又问 A 的乒乓，只有散文告诫"避免回执的回执"（`:73`），没有预算或
   记账去设界。环路一旦形成只能靠人喊停。

AGT-05 要给这两件事以机制，让跨会话协调可关联、有界。

## 2. 现状盘点（as-is，锚定实现）

- **投递与回执**（已完备，不属本文）：`send_message`（`tool/send-message.ts:8`）向目标
  `session_input` 收件箱投一条署名输入；回执含 `sessionID` + `wake: requested|not_requested`
  （`session-messaging.md:52`）。steer/queue 投递与唤醒策略、执行接缝、协调边界均已定义。
- **明确留白**：发送方"不得等待回复"（`:48`）；"避免回执的回执与重复的已解决请求"是**告诫**
  （`:73`），无机制。
- **发现侧上下文**：`read_session_context` 可读他者会话的历史结论，但那是**读转写**，不是
  结构化回复。

即：**投递有回执，回复无关联；协调有告诫，环路无设界。**

## 3. 回复关联（reply）

- **回复是第二类署名输入**，携带对原请求的**因果引用**：接收方的 `send_message` 可选
  `in_reply_to`（指向原消息的输入 id）。有该引用即为"回复"，无则为"新消息"。
- **发送方可选择等待**一条关联回复（有界等待，见 §4），也可不等（默认，保持现有非阻塞语义）。
  回复到达时作为一条带 `in_reply_to` 的输入进入发送方收件箱，发送方下个安全边界读到。
- **不新增事件类型**：回复复用现有 `send_message` 投递通道，只是多一个因果字段与一条关联索引；
  语义仍是"投进收件箱、在安全边界处理"，不打断接收方正在跑的工作。

## 4. 环路成本（loop cost）

- **因果深度**：每条消息带一个 hop/depth（起始 0，回复 +1）。接收方看到 depth 超过阈值即
  拒绝再回，避免无界往返。
- **每请求回复预算**：一个请求最多被回复 N 次（如 1），额外回复需显式升级而非自动。
- **环检测**：收件箱入队时若发现"已在处理同一因果链"，合并/降级为通知而非再排队一轮执行，
  打断 A↔B 乒乓。
- **记账可见**：环路成本计入协调记账（沿用 AGT-03 的净收益回执口径），让父/用户看得见"这次
  协调花了多少往返"。
- **人是兜底**：设界只拦自动环路；显式的、带 `reason` 的升级仍可越过（与唤醒的 `reason` 要求
  同源），最终由人裁决。

## 5. 现状缺口汇总

- **G1｜回复无因果关联**：接收方要回只能另发一条 `send_message`，与原请求无关联字段。
- **G2｜发送方无回复通道**：契约明令"不得等待回复"（`session-messaging.md:48`），无结构化回复
  返回路径。
- **G3｜环路无设界机制**：只有"避免回执的回执"告诫（`:73`），无 depth/预算/环检测。

## 6. 目标契约（提案，不在本文实施）

- **C1｜`in_reply_to` 因果字段**：`send_message` 可选引用原输入 id；有则为回复，收件箱入队时
  建一条关联索引，不新增事件类型。
- **C2｜可选有界等待**：发送方可声明等待一条关联回复（有界超时），默认仍非阻塞。
- **C3｜环路三设界**：hop/depth 阈值、每请求回复预算、因果链环检测；超界合并为通知，需显式
  带 `reason` 升级才越界。
- **C4｜环路记账**：往返成本计入协调记账，沿用 AGT-03 净收益回执口径。

## 7. 与相邻工作的边界

- **`specs/v2/session-messaging.md`**：属主发现/投递/唤醒/执行接缝；本文属主发送后的回复关联
  与环路设界，二者互补不重叠。
- **AGT-03 净收益回执**：本文 C4 复用其口径，不另起记账。
- **AGT-02 取消**：环检测合并的通知不取消接收方已有工作，沿用"不打断现有授权工作"（`:73`）。
- **`MAX_INBOUND_QUEUE`**：收件箱上界已存（`:73`）；本文的环检测在其入队侧生效，不改上界。
